# 화면 구조 추출과 반복 검증

## 의미 분석 후, 디자인 시스템 근거로 가상 그리드

[의미·역할 정의](semantic-design.md)를 먼저 수행한다. 같은 역할이 반복되는 집단을 찾은 뒤 화면/콘텐츠/영역/컴포넌트/슬롯 순서로 분해한다. 단순히 감지된 사각형을 가까운 부모 안에 넣는 것으로 계층 분석을 대신하지 않는다.

기존 디자인 시스템의 실제 그리드·토큰·논리 단위가 제공되면 이를 기준으로 가상 그리드를 놓고 원본과의 잔차를 확인한다. 자료가 없으면 공유 외곽·텍스트 시작선·아이콘 중심·baseline·행 간격에서 **관찰 기반 그리드 가설**을 만든다. 4/8pt, 12열 등을 먼저 강제하거나 관찰 좌표를 반올림해 일치시켜서는 안 된다.

- 화면 시스템 영역, 앱 탐색, 주 콘텐츠, 보조 영역, 오버레이를 먼저 나눈다. 의미 영역과 그리드 셀은 같지 않다.
- 전체 콘텐츠 열과 각 영역의 로컬 그리드를 구분한다. 큰 tile·세로 slider·작은 grid·리스트를 한 균일 그리드로 설명하려 하지 않는다.
- 이미지 px / crop 좌표 / 원본 좌표 / 논리 좌표를 구분한다. 원본 크기·SHA·기기/버전 근거·crop 변환·리사이즈·마스크·합성을 기록한다. 미확인 배율로 dp·pt를 선언하지 않는다.
- 그리드에 origin·scope·anchors·gaps·근거·오차·불일치를 기록한다. 반복 표본이 있으면 차이를 측정하되 수동 주석 간 일치를 독립 정확도 평가로 주장하지 않는다.
- 광학 정렬·보이는 글리프·실제 클릭 영역은 bbox·그리드 검사와 별도로 확인한다.

## 역할 계층과 카탈로그 연결

각 노드는 `ID / parent / screen·state / 내용 / 의미 역할 / 형태 / 입력 전후 변화 / 영향 대상 / 근거·확신 / 카탈로그 연결 / 측정값 / 미확인`을 가진다. 읽기 전용·장식은 행동 N/A를 허용한다.

계층은 containment뿐 아니라 의미·반복·합성 관계를 표현한다. 공간상 부모, 의미상 부모, 실제 DOM/플랫폼 노드, 레이어·제어 대상을 서로 구분한다. portal·fixed·overlay처럼 부모 경계를 벗어나는 요소는 원인·관계를 명시한다. 모든 픽셀을 기능 컴포넌트로 만들지 말고 정보·자산·표면·상호작용 단위를 구분한다.

카탈로그는 해당 프로젝트의 기존 컴포넌트 목록을 우선 사용한다. 없으면 자체 seed 목록임을 밝히고 역할·행동·콘텐츠 슬롯·지원 상태로 정의한다. 다음 순서로 매핑한다.

1. **EXISTING:** 같은 역할·행동·데이터 계약으로 설명된다.
2. **VARIANT:** 같은 계약 안에서 크기·축·아이콘·슬롯 등 지원 변형이다.
3. **COMPOSITION:** 알려진 요소의 합성으로 설명된다. 조합의 역할·읽기 순서·행동 소유권을 정의한다.
4. **UNKNOWN:** 역할/동작/메타데이터가 부족하다. 필요한 근거를 기록한다. 이 단계는 신규 판정이 아니다.
5. **NEW_CANDIDATE:** 충분한 역할 근거가 있고 기존 요소·변형·합성으로 계약을 설명할 수 없다. 신규 기본 요소인지 도메인 조합인지 구분하고 잠정 등록한다. 다른 표본에서 재사용·계약을 확인한 뒤 안정 항목으로 승격한다.

우리 목록에 없다는 것과 업계에 전혀 없는 것은 다르다. 외형이 새롭거나 레이블이 없다는 이유로 primitive를 늘리지 않는다. 예: 이미지+링 게이지+값을 반복한 배터리 요약은 새 도메인 조합 후보이고, 지도·레이블·선택표시를 담은 위치 정밀도 카드는 알려진 choice의 변형/합성으로 설명할 수 있다.

## 구성 값 추출

각 값은 `value / unit / source / method / uncertainty / observed|inferred|proposed / scope`를 갖는다. 역할·내용·부모·anatomy와 연결되지 않은 좌표 덤프만 납품하지 않는다.

- 기하: bbox·공유 anchor·inset·gap·행/열·크기 모드·위치 기준·clip/overlap. 이미지 한 장에서는 fixed/intrinsic/fill 정책이 대부분 미확인이다.
- 콘텐츠: 제목/값/설명/상태 슬롯, 관찰 줄 수, 자산·종횡비. 조합 설명에 있는 이미지·값·게이지 등 필수 슬롯은 실제 노드/참조에도 존재해야 한다. 게이지 외곽 bbox에 값 레이블을 섞지 말고 슬롯별 기하 범위를 구분한다. 관찰 줄 수와 최대 줄 수를 분리한다.
- 시각: 표면·텍스트·상태 역할, R·border·font·행간·색·효과. 샘플 픽셀 RGB는 압축·합성 결과이며 원본 토큰과 구분한다. 모르거나 측정하지 않은 값은 TBD로 남긴다.
- 행동: 트리거·상태 축·선택 유지·확정 시점·영향 대상·focus/scroll/occlusion. 정적 외형으로 확인하지 못한 것은 가설이다.

원본/그리드/영역/전체 계층을 전환하고, 노드를 선택하면 원본 위치·계층 경로·카탈로그·구성 값·근거가 같이 보이게 한다. 분석용 구조 도면과 실제 UI 재구현은 별개의 산출물이다.

## 반복 실험

1. 표본의 버전·해상도·전체 viewport·편집 여부를 확인한다. 원본 수치만 크고 UI 자체가 작은 합성 이미지는 실효 해상도를 따로 평가한다.
2. 화면 읽기와 의미 명세를 작성하고, 그리드·계층·카탈로그·값을 추출한다.
3. 원본과 국소 확대를 대조해 오분류·누락·잘못된 부모·가림·정렬 가설을 검토한다. 모르는 상태를 만들어 채우지 않는다.
4. 다른 화면/스크롤/상태에서 기존 역할·슬롯·그리드 관계를 재적용한다. 같은 스크롤 문서의 위치 차이는 데이터 포화 조건이 아니다.
5. 발견→수정→영향 노드·규칙→재확인 결과를 기록하고 재사용 가능한 원인만 스킬에 반영한다. 특정 샘플의 좌표를 일반 지침에 복사하지 않는다.
6. 새 표본에서 오분류가 줄었는지 검토한다. 동작 검증·독립 검토·자동 인식이 없으면 각각 미실행으로 남긴다. 작성한 정답 라벨을 코드로 재확인한 결과는 일관성 회귀 검사이며 의미 인식 성공률이 아니다.

데이터 구조 검사는 중복/누락 ID, 카탈로그 매핑, 부모 cycle, bbox 유효 범위, 원본 변환, 설명 없는 경계 이탈, 필수 의미 필드를 검사한다. 이는 실제 화면 이해를 대신하지 않는다. 사용자가 반복 테스트를 요청하면 분석 예시를 만들고 실제로 대조한 뒤 그 발견으로 지침을 수정한다. 설치본 갱신 여부는 기존 사용자 지시를 따른다.

## 표본 확장 시 검토 기준을 먼저 고정

- 확대 전 카탈로그와 판단 기준을 스냅샷으로 보존한다. 새 화면을 보고 목록을 보완했다면 기준 목록으로 설명된 것과 보완 후 설명된 것을 구분한다.
- 표본 매트릭스에 플랫폼·앱/과업·입력/검색/탐색/미디어/오버레이·상태·해상도·원본/가공·출처·확인할 규칙을 기록한다. 같은 페이지의 스크롤과 편집 전후를 새로운 앱 종류로 세지 않는다.
- 유사 설정 화면만 늘리지 않는다. 키보드가 열린 입력, 범위를 고르는 검색, 하단 탐색과 플레이어가 겹친 화면, 중첩 메뉴, 독립된 선택 축이 있는 편집 팔레트 등 기존 가정을 반박할 표본을 포함한다. 모든 유형의 확보를 주장하지 말고 빈 범위를 남긴다.
- 카탈로그에 text input·keyboard·menu가 빠졌다고 업계 신규 요소로 부르지 않는다. `CATALOG_GAP`으로 기록한 뒤 일반 패턴/변형/합성/미확인 중 어디에 해당하는지 판정한다.
- 역할 분류, 슬롯 누락, 계층, 이미지 경계 정합, 행동 검증은 별개 결과로 보고한다. 부모 안의 좌표라는 이유로 실제 버튼에 맞는 bbox라고 판정하지 않는다. 같은 모양의 X는 입력 지우기/검색 종료처럼 영향 대상이 다를 수 있다.
- 정규화 주석을 원본으로 환산할 때 시작·끝 경계를 같은 변환으로 계산한다. 폭/위치를 독립 반올림해 생긴 1px 포함 관계 오류와 실제 주석 오류를 구분한다. 원본 대조에서 틀렸으면 표본 좌표를 수정하며 스킬에는 재사용할 검사 원리만 추가한다.
- 화면 안 웹 문서의 ‘iOS 26’ 같은 글자를 실행 OS 근거로 사용하지 않는다. 작성자·버전 표기·주변 문맥으로 확인하고 원본의 개인정보 가림을 복원하지 않는다.
- 출처가 같은 리뷰/작성자에 몰린 확장이라면 출처 편향을 표시한다. 단일 상태·표본 개수·노드 수가 늘었다는 이유로 분류 정확도나 실제 동작 일반화를 주장하지 않는다.
