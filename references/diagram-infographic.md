# 다이어그램·인포그래픽 설계

앱·웹·문서의 일부에 관계, 순서, 수치, 공간 구조를 시각적으로 설명해야 할 때 적용한다. 먼저 문장이나 표로 전달할 내용을 적고, 시각화가 독자의 이해를 실제로 개선하는지 판단한다. 그래프의 종류와 렌더러는 그 다음에 고른다. 원본 자료의 관계나 숫자를 꾸며내지 않는다.

## 표현 유형 선택

| 전달할 의미 | 우선 검토할 표현 | 필요한 확인 |
| --- | --- | --- |
| 정확한 값·속성을 찾아 비교 | 표 | 열·단위·정렬·정렬 기준 |
| 단계의 선후와 진행 | 단계/타임라인 | 시작·종료·분기·시간 간격의 실제 의미 |
| 조건에 따른 결정·상태 변화 | 흐름도/상태도 | 조건·예외·되돌림·종료 |
| 주체 간 메시지·책임 이동 | 시퀀스/스윔레인/서비스 블루프린트 | 행위자·순서·가시/비가시 경계 |
| 부모·자식, 포함·소유 | 트리/조직도/중첩 구조 | 깊이·다중 부모 여부 |
| 의존·연결·데이터 흐름 | 네트워크/아키텍처/의존 그래프 | 방향·연결 종류·순환·경계 |
| 범주 간 크기·시간 추세·분포 | 막대/선/점 등 정량 차트 | 축·척도·분모·누락값·표본 |
| 부분과 전체 또는 양의 분기·합류 | 구성비/트리맵/생키 | 합계·비율·면적/두께 인코딩 |
| 두 축의 위치·우선순위 | 산점도/사분면 | 각 축의 정의·측정/주관 판단 구분 |
| 여러 사실을 한 화면의 설명 흐름으로 요약 | 인포그래픽 | 주장·읽기 순서·각 조각의 데이터 출처 |

형태가 비슷해도 의미가 다르면 바꾸지 않는다. 목록을 과정처럼, 단순 비교를 인과관계처럼, 순위 변화를 규모 변화처럼 묘사하지 않는다. 주관적 범주를 연속 수치 축처럼 보이게 하지 않는다. 억지로 모든 내용을 한 그림에 넣지 말고 개요와 상세로 나눈다.

## 인포그래픽 전체의 편집 구조

여러 도표·문장·사진을 하나의 인포그래픽으로 묶을 때는 **전체 주장 → 독자의 첫 질문 → 각 조각이 답하는 하위 질문 → 마지막 판단/행동**을 먼저 연결한다. 조각이 많다는 이유만으로 인포그래픽이 되는 것은 아니다. 각 조각에 `주장·증거·설명·출처` 역할을 붙이고, 같은 증거를 다른 색의 차트로 되풀이하거나 출처가 없는 장식 숫자를 넣지 않는다. 독자가 실제로 스캔할 경로를 1차 요약과 2차 상세로 나눈다. 시각적 크기와 선후관계가 데이터의 중요도·시간·인과를 잘못 암시하는지 확인한다.

구성 전에 같은 자료로 최소 세 가지 **정보 구조**를 비교한다: 예를 들어 결론 먼저/질문 먼저/과정 먼저. 유형 이름만 바꾸거나 같은 카드 격자의 색을 바꾼 것은 대안이 아니다. 각 안에서 주장의 발견 속도, 원본 근거를 찾는 경로, 포화 자료에서 유지되는 읽기 순서를 기록한다. 추천안의 이유를 사용자에게 보여주고 확인 B를 받는다.

인포그래픽의 부분 도표마다 정량/범주/관계/절차/공간 중 하나의 인코딩 목적을 선언한다. 수치 시각화는 `원본값 → 가공식 → 그림 속 기하·색·라벨`의 계보를 유지한다. 길이·면적·두께·색 명도 중 무엇이 값에 대응하는지 적고, 값이 없거나 확인되지 않은 관계는 도형의 크기·화살표로 꾸미지 않는다. 원본의 모든 항목을 보여주지 않을 경우 제외 기준과 상세 표·부록으로 돌아가는 경로를 기록한다.

한 장을 웹·문서·발표 슬라이드에 함께 쓸 때 원본 SVG를 무조건 축소하지 않는다. 매체마다 `가용 폭·높이 / 실제 표시 배율 / 최소 판독 글자 / 허용 정보 밀도 / 상호작용 또는 정적 대안`을 정한다. 발표용은 핵심 주장과 첫 증거를 남기고 복잡한 라벨은 분리된 장 또는 배포본으로 보낼 수 있다. 문서용은 번호·캡션·본문 참조·출처·페이지 넘김을 포함한다. 웹용은 좁은 폭에서 재배치·스크롤·표 대안을 제공한다. 세 결과물은 같은 원본값과 의미를 공유한다.

독립 인포그래픽이나 여러 패널로 된 그림은 [인포그래픽 기록 검사기](../scripts/check_infographic_contract.py)에 `kind, audience, storyClaim, sourceSummary, panels, scanOrder, adaptations`를 선언한다. 각 패널은 `id, question, claim, source, encoding:{type,represents}, alternative, renderEvidence`가 필요하다. 정량 패널은 `unit, scale, sourceData`, 가공값은 `formula`, 부분/전체는 `denominator`, 관계 패널은 `sourceRelations`를 추가한다. 매체별 변형에는 `medium, displaySize, readingOrder, renderEvidence`를 적는다. 검사기는 기록 누락만 찾는다. 원본 데이터와 화면 기하의 일치, 실제 판독성은 내부 렌더와 최종 삽입 크기에서 별도로 검증한다.

## 시각 요소의 데이터·구조 계약

각 그림에 `목적 / 독자 / 핵심 주장 / 원본 출처·날짜 / 노드·항목 / 관계 또는 수치 / 단위·분모·척도 / 불확실·누락 / 읽기 순서 / 출력 매체 / 대체 설명`을 적는다. 원본에 없는 값·관계는 `미확인`으로 표시하고 도형이나 화살표로 확정하지 않는다. 요약하며 합치거나 생략한 항목은 기록한다. 시각화에 수치가 있으면 원본 표와 그림의 라벨·축·합계를 대조한다.

공통 그리드·정렬선·타이포그래피·색 역할은 승인된 디자인 시스템을 따른다. 노드와 연결선의 부착점, 라벨과 선의 간격, 영역 사이 여백, 그룹 경계, 범례의 위치를 실제 렌더에서 확인한다. 분기에는 출발 조건과 도착 대상을 명시하고, 좁은 폭에서 연결선을 생략한다면 문장·단계 ID로 관계를 유지한다. 정량 차트의 공통 기준선은 번역 라벨의 행수가 달라도 한 줄로 정렬한다. 장식적인 3D·그라데이션·아이콘은 구조 이해에 도움이 되는 경우만 쓴다. 시각 요소 내부의 카드도 기본 반복 단위로 가정하지 않는다.

처음 또는 짧은 자료와 현실적인 포화 자료를 같은 규칙에 넣는다. [다국어·RTL 검수](multilingual-review.md)에 따라 긴 한국어·영어·아랍어 라벨, 다수 노드·관계, 빈 값, 좁은 화면, 확대 및 인쇄 축소에서 라벨·선·범례가 겹치지 않아야 한다. RTL에서도 흐름과 시간축의 의미가 유지되어야 한다. 밀도가 높으면 축소만 하지 말고 수준을 나누거나 표를 병기한다.

## 그림 삽입 규칙

그림마다 원본 캔버스 폭, 의도한 **실제 표시 폭**, 최대 배율(기본 1.25배), 좁은 화면의 대체 방법을 정한다. 본문 폭이 넓어도 SVG를 무제한 늘리지 않는다. 320·360px에서 글자가 11px 미만이 되면 가로 스크롤 영역·수직 재배치·단계 목록 중 하나로 읽을 수 있게 하고, 스크롤 영역에는 키보드 접근과 이름을 준다. 본문 라벨은 표시 크기 13~16px, 보조는 11~13px을 시작 범위로 삼고 실제 제품 폰트에서 조정한다. 일반 라벨 400~500, 강조·판단 600, 700은 명시된 경우에만 사용한다. 그림은 페이지 글꼴과 승인된 색 토큰을 상속·주입한다. 상자 안쪽 12, 노드 간 최소 16, 화살이 있는 노드 사이 최소 32, 되돌림 선과 노드 사이 최소 16 단위를 시작 기준으로 검사한다. 검사기가 0건을 보고해도 표시 크기 캡처와 글자·선의 시각적 판독을 별도로 확인한다.

앱·웹에서는 터치·키보드 대상 크기와 포커스, 반응형 배치, 툴팁 없이도 읽히는 기본 정보, 정적 대체를 정한다. 문서에서는 그림 번호·캡션·본문 참조·출처·페이지 넘김·실제 인쇄 크기를 정한다. SVG에는 제목/설명과 의미 있는 읽기 순서를, 복잡한 정량 그림에는 수치 표 또는 텍스트 요약을 함께 제공한다. 모션은 시간 변화나 상호작용을 설명할 때만 사용하며 정적 상태만으로도 핵심 뜻을 읽을 수 있어야 한다.

## 내부 렌더러와 구성 선택

의미 유형을 결정한 뒤 [내부 시각화 카탈로그](visualization-catalog.md)의 55개 유형에서 실제 관계와 맞는 후보를 고른다. 샘플 그림의 이름만 보고 채택하지 않는다. 입력값·단위·합계·방향을 데이터 계약과 대조하고 내부 SVG 렌더러로 정적 결과를 먼저 만든다. 제공된 유형으로 원본 의미를 보존할 수 없다면 새 문법과 렌더러를 내부에 추가하고 검수한 뒤 사용한다. 외부 스킬, 외부 템플릿, 외부 렌더러, CDN을 실행 경로로 연결하지 않는다.

기능 구조 A1·흐름 A2·화면 분할 A3 확인 이후 구성 선택 B에서는 순서·분기·상태 변화·양의 변화를 설명하는 그림을 저충실도 구성안과 함께 실행한다. 같은 데이터에 최소 3개 와이어프레임의 그림 위치와 읽기 순서를 비교한다. 필요한 경우 흐름선 추적, 단계 공개, 값 성장, 초점 이동으로 변화의 원인을 보여주되 도형이 실제로 움직이는 것만으로 동작 검수를 통과시키지 않는다. 재생·일시정지·정적 화면에서 같은 관계를 읽을 수 있어야 한다. C 이후 브랜드 토큰과 최종 모션 시간·이징을 정한다.

## 기존 설계 절차와 연결

- **A 구조 확인:** 자료의 의미와 관계를 정의하고 표/문장/차트/다이어그램/인포그래픽 중 후보를 제시한다. 앱·웹·문서의 어느 화면·페이지에 왜 들어가는지도 표시한다.
- **B 와이어프레임 확인:** 최소 3개 구조 대안에는 그림 슬롯과 읽기 흐름을 포함한다. 그림 자체의 유형이 의사결정에 중요하면 같은 데이터로 내부 렌더러의 유형 후보를 실행해 비교한다. 모션이 관계 이해에 필요하면 저충실도 동작을 함께 보여준다. 사용자가 이미 그림 종류를 지정했다면 이를 따른다.
- **C 시각 방향 확인:** 승인된 구조·동일 데이터에 브랜드 토큰을 적용해 라벨·선·색 인코딩·캡션까지 보여준다. 렌더러가 바뀌어도 내용과 의미를 유지한다.
- **최종 검수:** 원본 데이터 대조, 흐름·방향·연결·척도 검증, 충돌/잘림/색 대비/폰트·내보내기 검사 결과를 `PASS / FAIL / NOT_RUN / NOT_APPLICABLE`으로 기록한다.
