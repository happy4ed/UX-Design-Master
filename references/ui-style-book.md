# UI 스타일북 (UI Style Book)

앱·웹·문서에 적용할 **명명된 시각 스타일**의 지식 베이스. 각 스타일을 "색 테마"가 아니라
**모든 디테일 토큰**(재질·곡률·아웃라인·그림자·글로우·블러·타이포·아이콘·컴포넌트 트리트먼트·모션)
으로 정의한다. `theme-exploration.md`(9테마 탐색 계약)와 짝 — 거긴 "어떻게 비교·확정하나",
여긴 "각 스타일이 무엇이고 무엇으로 이루어지나". `component-contract.md`·`design-system-production.md`
와 함께 쓴다(컴포넌트 유형·크기 변형을 먼저 고정한 뒤 스타일을 입힌다).

## 적용 지침 (스킬이 스타일을 입힐 때)

1. **색만 바꾸지 않는다.** 스타일을 고르면 그 스타일의 **전 토큰 묶음**을 적용한다. 버튼·입력·카드·토글·
   슬라이더·칩·아이콘·그림자·테두리가 전부 그 스타일의 규칙을 따른다. 색만 교체 = "스타일 미적용".
2. **간격 → 조작 영역 → 컴포넌트 순서로 먼저 고정한다.** 간격은 프로젝트의 콘텐츠·매체에서 도출한 단계와 **역할 맵**(화면 여백·카드 패딩·
   카드 간·라벨↔내용·관련 블록·구획·그룹 안·밀착)을 표로 먼저 정하고, 화면의 모든 마진·갭은 그 역할 값만 쓴다.
   조작 요소는 **최소 48×48**(보이는 크기가 작으면 투명 영역으로 확장), 인접 조작 영역은 실제 기기와 역할에 맞춰 겹침·오조작을 검사한다. 슬라이더는 상자 전체를 조작 영역으로 두고 트랙을 썸 반경만큼 안쪽에 둔다.
   그다음 컴포넌트 유형(버튼·입력·카드·토글·슬라이더·아이콘버튼…)과 **크기 변형(sm/md/lg)**
   의 높이·패딩·마진·R 을 토큰으로 정의하고 그 값만 쓴다. 화면마다 크기를 즉흥으로 바꾸지 않는다.
   **값은 최소화**한다 — 같은 역할=같은 크기, **원형 버튼은 2종 이하**(primary + standard). 크기 종류가
   많으면 화면이 정신없다. 본문·조작 글자는 **모바일 최소 14**(PC 13), 캡션/마이크로(대문자 라벨·시간 숫자)만
   사유를 적고 예외. 타입 스케일을 세우고 그 안에서만 쓴다.
3. **곡률(R)은 모양·역할로 고정한다.** 원형 버튼=50% · 알약=pill · 입력=field R · 카드=surface R. 다만 R 50%는 원형의 충분조건이 아니다. [형상 검증 계약](material-motion-shape-qa.md)에 따라 실제 가로·세로와 전환 중 비율을 재고, 의도하지 않은 타원은 고친다.
4. **이펙트는 토큰이다.** 아웃라인(두께·색)·드롭섀도·이너글로우·블러를 값까지 명시해
   `--outline`·`--shadow`·`--inner-glow`·`--blur` 로 둔다. 한 화면 안에서 효과 계열을 섞지 않는다.
5. **아이콘을 스타일에 맞춰 제작한다.** line/fill/geometric·굵기·모서리가 스타일과 일치해야 한다.
   이모지 글리프로 대신하지 않는다(실제 SVG).
6. **모드(light/dark)·재질**을 스타일 정의에서 가져온다. 재질을 가진 조작은 [재질·모션 검증 계약](material-motion-shape-qa.md)에 따라 뒤쪽 콘텐츠·Z층·투과/흐림/굴절·반사/그림자와 조작 중 변화를 함께 시험한다. 접근성(명암비·최소 글자·터치영역)은 스타일 무관하게 지킨다.
7. 실제 화면에 적용해 **렌더로 실측 검수**한다(6장). 간격·정렬·치수·조작 영역 겹침·최소 글자·줄바꿈을 실제 픽셀로
   재서 기대값과 대조한 **PASS/FAIL 표**를 남긴다. 눈대중·"맞췄다"는 말로 대신하지 않는다.
8. **같은 종류는 같은 배치 규칙.** 두 슬라이더의 값 표시처럼 같은 종류의 컴포넌트는 위치·정렬 기준·글자를 통일한다
   (한쪽은 바 위, 한쪽은 바 아래 금지).
9. **동작 문구는 실제로 검증한다.** 칩·추천·빠른 실행처럼 앱에 보내는 문구는 실제 해석기·API 코드에서 인식되는지
   확인하고, 생성 규칙·무작위 여부·숨김 조건·금지 문구를 사양에 적는다. 확인 안 된 문구는 시안에도 넣지 않는다.

## 상세 스타일 가이드

스타일별 A~L 값과 근거 목록은 [기본 스타일 가이드북](style-book/README.md)에 있다. 프로젝트·사용자·기본 세 층을 합쳐 찾고, 실제 사용 전에 해당 가이드의 미확인 값과 L절 검증 상태를 확인한다. 기존 한 줄 요약의 수치는 공식·실측 값이 아니며 플랫폼/실물 재현의 근거로 쓰지 않는다.

매체를 바꿀 때는 [스타일북의 앱·웹·문서 번역 계약](style-book/README.md#앱웹문서에-번역하는-공통-계약)을 따른다. 컴포넌트 사용 맵과 상태·입력·문서 의미를 먼저 정하고, 그 뒤에 스타일 토큰과 샘플을 만든다. 앱에서는 폰·파블렛·폴드, 웹에서는 좁고 넓은 폭, 문서에서는 실제 페이지와 인쇄 조건을 각각 검증한다.
