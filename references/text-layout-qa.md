# 텍스트 영역 설계와 렌더 검수

텍스트를 도형에 넣은 뒤 잘라 맞추지 않는다. 앱·웹·문서·도표의 **각 텍스트 슬롯**에 먼저 영역 `(x,y,w,h)`, 안쪽 여백, 정렬, 기본/최소 글자 크기, 최대 줄 수, 일반 줄 간격, 문단 간격, 이웃 슬롯과의 최소 간격을 기록한다. 제목·값·보조 설명·화살표 설명은 각각 다른 슬롯이다. **텍스트 박스를 명시적으로 사각형으로 지정한 경우를 제외하고, 도형 안의 문구에는 그 도형의 실제 내부 윤곽을 적용한다.** 각 줄의 글리프 높이 전체가 지나가는 위치에서 도형과 만나는 연속된 가로 구간을 구하고, 안쪽 여백을 뺀 폭으로 줄마다 다시 줄바꿈한다. 오목하거나 떨어진 영역은 여러 구간 중 하나의 연속된 구간을 선택하고, 도형 전체 너비를 글자 폭으로 오인하지 않는다. 페이지의 본문처럼 높이가 내용에 따라 늘어나는 슬롯은 높이 상한 대신 다음 요소를 밀어내는 흐름과 페이지 분할 규칙을 기록한다.

앱의 기본 최소 글자 후보는 **14**, 웹은 **실제 표시 기준 13 CSS px**, 인쇄 문서는 **최종 출력 기준 6.5pt**로 둔다. 앱의 브라우저 모형 CSS px와 네이티브 앱의 sp·pt는 별도 실측한다. 이는 축소 가능한 원본 사진 안의 글자처럼 별도 확대 경로가 있는 콘텐츠를 제외한 기본 하한이다. 예외는 위치·이유·확대 경로를 적는다. DESIGN.md의 타이포그래피 토큰에도 하한을 적용하고, 대상 프로젝트의 실제 좁은 화면·데스크톱 창 렌더에서 HTML뿐 아니라 SVG `viewBox` 축소를 반영한 표시 크기를 측정한다. 토큰·CSS 명목 크기만으로 통과시키지 않는다.

최소값은 확인 C에서 사용자에게 보이는 실제 문구·아이콘 라벨·차트 축으로 제시해 확정받는다. 큰 글자 설정이나 브라우저 200% 확대에서는 같은 상자를 억지로 유지하지 말고 열 수·고정 높이·줄 수·스크롤/시트 높이를 다시 정한다. 기본 크기와 확대 크기 각각에서 주요 행동, 읽기 순서, 잘림, 겹침을 검수한다. 글자 맞춤은 승인된 최소값 아래로 내리지 않는다.

**한글을 포함한 HTML 화면은 어절 단위 줄바꿈을 별도로 검수한다.** 모바일의 좁은 폭과 데스크톱 폭, 기본 글자와 150%·200% 확대한 상태에서 실제 렌더된 글자 위치로 줄을 복원해, 공백이 없는 한글 어절이 줄 사이에서 갈리는지 센다. 마지막 줄의 한두 글자 외톨이는 경고하고, 칸 밖 넘침·버튼 글자 잘림·고정 요소에 가려져 눌리지 않는 조작은 실패로 기록한다. 수정 뒤 **같은 폭과 배율**을 다시 재어 어절 분리 감소가 새 넘침을 만들지 않았는지 확인한다. 제목·본문은 어절 보존을 기본으로 하되, 좁은 표 칸·배지·버튼은 콘텐츠 계약에 따라 칸 확대·줄수·말줄임을 선택하고, 긴 코드·URL에는 별도 줄바꿈을 허용한다. 모든 요소에 `break-all`·`nowrap`·`keep-all`을 한꺼번에 적용하지 않는다. 한국어와 중국어·일본어가 섞인 문구는 언어별 줄바꿈을 다시 확인한다. 이 검사는 HTML 본문용이며 SVG·Canvas·인쇄물의 기존 텍스트 슬롯 검사를 대신하지 않는다.

## 결정 순서

1. 실제 문구와 긴 문구, 빈 상태와 포화 상태, 영어와 RTL 문구를 같은 영역에 넣어 본다. 예상 글자 수만으로 합격시키지 않는다.
2. 기본 글자 크기에서 들어가지 않으면 이웃 영역·화살표·안전 여백을 확인하고 **도형 또는 텍스트 영역을 넓힐 수 있는지** 먼저 판단한다. 늘어난 도형이 연결선 끝점과 그리드에 미치는 영향도 갱신한다.
3. 확대할 수 없거나 충분하지 않으면 계층별 최소 크기까지만 글자를 줄인다. 줄인 크기가 읽기 어려우면 화면/도표를 나누거나 설명을 별도 영역으로 옮긴다.
4. 작은 원형·마름모 등에서 전문을 넣을 수 없으면 도형 밖의 실제 텍스트 영역에 원문을 배치한다. 참조 키를 쓰는 경우에도 원문이 같은 화면의 도형 가까이에 즉시 보여야 하며, 숫자 하나만 보이는 상태를 합격시키지 않는다. 말줄임표만으로 정보를 잃지 않는다.
5. 일반 줄바꿈은 `lineRatio`, 빈 줄로 나뉜 문단은 별도의 `paragraphGap`을 쓴다. 문단 간격을 줄 간격과 같은 값으로 고정하지 않는다. 화살표 설명은 선에서 `gap`을 확보하고 연결선·도형·다른 글자와 겹치지 않게 한다.
6. 글자가 직선이 아닌 경로를 따르거나 회전해야 하는 경우에는 경로 길이·양끝 여백·읽는 방향·회전각·회전 후 경계를 슬롯 계약에 포함한다. 원형 외곽의 글자는 테두리와 글리프가 맞닿지 않도록 별도 반지름/간격을 둔다. 경로에 전문이 들어가지 않으면 억지로 압축하지 말고 다른 배치나 참조 키를 쓴다.

내부 [텍스트 배치 모듈](../assets/visualization/text-layout.mjs)의 `planTextRegion`은 `fit → grow-region → grow-and-shrink/shrink-font → external-reference`를 기록한다. `layoutShapeText`는 원·타원·마름모·사각형의 윤곽, 다각형의 교차점, SVG 경로 또는 커스텀 도형의 내부 판정에 따라 줄별 허용 구간을 계산한다. 도형 형상을 모르면 사각형으로 대체해 합격시키지 않고 원문을 별도 영역에 놓거나 형상 정의를 요청한다. [SVG Canvas](../assets/visualization/svg-core.mjs)의 `textBox`는 **명시된 사각형 텍스트 박스**에만, `shapeText`는 도형 안의 문구에, `edgeLabel`은 화살표 설명 슬롯에 쓴다. 브라우저에서는 실제 글꼴 폭으로 줄바꿈하고 `auditSvgLayout`의 `shapeLineOverflow`로 각 줄의 실측 폭이 허용 폭을 넘는지 확인한다. 좌표만 정한 `text()`는 짧고 길이가 고정된 값·축 표기에만 쓴다.

크기 조정이 필요한 경우 `size`부터 `minSize`까지 0.5 단위 후보를 하나씩 내려가며 재배치하지 않는다. 고정된 영역·글꼴·문구에서 맞음 여부가 크기에 대해 단조롭게 변하는 조건을 확인하고 중간값 탐색으로 **가장 큰 수용 크기**를 찾는다. 각 후보의 실제 줄바꿈·높이는 다시 계산하며, 경계 후보와 승인된 최소값을 검증한다. 단조성이 깨지는 커스텀 도형·가변 글꼴·임의 줄바꿈에서는 탐색 결과를 그대로 확정하지 말고 인접 후보를 실제 렌더로 확인하거나 영역을 키운다.

SVG의 곡선·외곽·회전 글자는 [경로 텍스트 계획](../assets/visualization/path-text.mjs)과 `Canvas.textOnPath`/`rotatedTextBox`를 쓴다. 경로 길이는 실제 SVG 길이를 측정하고, 양끝 여백을 뺀 사용 가능 길이와 글자 길이를 비교한다.

웹·앱 프로토타입·브라우저에서 렌더하는 문서는 각 텍스트 요소에 `data-text-region`을 표시한다. 필요하면 `data-text-max-lines`, `data-text-min-font`, `data-paragraph-gap-min`을 둔다. [공통 텍스트 영역 검사기](../assets/layout/text-region-audit.mjs)의 `auditTextRegions(root)`는 실제 글리프의 영역 이탈, 지정 줄 수·최소 글자 크기·문단 간격 위반, 이웃 문구 침범을 찾는다. 같은 모듈의 `auditRenderedFontFloor(root,{minimumPx})`는 HTML 글자와 `viewBox` 배율을 적용한 SVG 글자의 표시 크기를 잰다. 앱 화면은 확인 C에서 확정한 하한을 `minimumPx`로 전달하며, 확정 전의 기본 후보는 14다. 웹은 기본 13을 사용한다. 예외는 `data-font-floor-exception`과 사유로 기록한다. 네이티브 앱이나 PDF의 최종 파일에서는 같은 슬롯 계약을 토대로 실제 캡처/페이지를 확인한다.

브라우저에서 [SVG 레이아웃 검사 모듈](../assets/visualization/layout-audit.mjs)의 `auditSvgLayout(svg)`로 영역 밖 글자, 경로 길이 초과, 텍스트끼리의 침범, 화살표 설명 간격, 화살표 끝점, 시각 중심 후보를 확인한다. `probeMotion(svg)`는 실제 브라우저에서 애니메이션 속성이 시간에 따라 변하는지 확인한다. 검사가 통과해도 캡처를 실제 표시 크기와 확대 화면에서 읽고, 문제가 보이면 슬롯·도형 크기·배치 결정을 고쳐 다시 렌더한다. [대화형 점검 화면](../samples/text-layout-review.html)에서 줄/문단 간격·도형 크기·경로·회전을 시험할 수 있다.
