# 실제 화면의 정렬·연결 검수

좌표값이 맞아도 글리프와 도형의 무게 때문에 시각 중심이 어긋날 수 있다. 화살표의 좌표가 근처에 있어도 끝이 대상 경계에 닿지 않을 수 있다. 최종 판정은 실제 크기의 렌더를 보고 한다.

## 검수 순서

1. 모션을 정지하고 대상 프로젝트의 실제 모바일·데스크톱 창 크기와 전환점, 문서 최종 판형에서 전체 화면을 캡처한다. 같은 장면을 확대해 글자·선·화살표 접합부를 본다. 글자 확대는 별도 접근성 검사 범위에서 확인한다.
2. 반복 요소의 시작선·중심선·기준선, 좌우 패딩, 라벨과 본문 사이 여백을 서로 비교한다. 글꼴의 비대칭과 아이콘의 투명 여백을 고려해 **눈에 보이는 중심**을 조정한다.

**정렬 기준선은 박스 한 줄로 끝내지 않는다.** 같은 역할의 인스턴스마다 아래를 한 묶음으로 기록한다. 수치는 차이의 위치를 찾는 단서이며 광학적 합격 판정은 실제 크기 캡처에서 한다.

| 대상 | 별도로 잴 기준 |
| --- | --- |
| 아이콘·이미지 | 조작 영역 → 아이콘 슬롯 → SVG 경로/비트맵의 실제 보이는 경계 → 보이는 중심과 면적·획 두께. 슬롯 중심이 같아도 내부 도형의 크기·투명 여백·비대칭으로 달라 보일 수 있다. |
| 텍스트 | 텍스트 박스 → 실제 첫 글자 시작점/줄별 시작점 → 글리프 높이와 시각 중심 → 글꼴·굵기·크기·줄높이·들여쓰기. 박스 경계가 같다는 이유로 줄 시작이 같다고 판단하지 않는다. |
| 머릿글·목록 기호 | 기호의 보이는 오른쪽 경계, 문구의 첫 글자 시작점, 그 사이 간격, 기호·글줄의 수직 중심. 들여쓰기 단계마다 같은 관계를 확인한다. |
| 표면·도형의 R | 실제 가로·세로와 각 모서리의 CSS 반지름, 짧은 변 대비 R 비율, 인접·중첩 표면의 곡률 관계. 작은 도형과 큰 도형에 같은 절댓값이나 같은 비율을 기계적으로 강제하지 않고 선택한 스타일의 연속성을 화면에서 판정한다. |
| 원형 조작 | 보이는 원과 조작 영역의 가로·세로를 따로 잰다. R 50%라도 Flex 늘어남이나 유동 너비·고정 높이 혼합으로 타원이 되면 실패다. 펼침·축소 중 두 축의 비율, 이웃 원과의 간격, 아이콘 중심도 확인한다. [형상 검증 계약](material-motion-shape-qa.md) 참조. |

브라우저에서는 [가시 정렬 실측기](../assets/layout/visual-alignment-audit.mjs)의 `measureVisualAlignment(root)`로 같은 `data-align-group`을 가진 요소의 박스 중심, SVG 내부 경계·중심, 텍스트 첫 줄 시작점과 글꼴 값, 각 모서리 R/짧은 변 비율을 수집한다. 단순 SVG 사각형·원·타원의 면적 비율과 획 너비는 보조 단서로 기록한다. 머릿글은 `data-measure-marker-row` 안의 `data-list-marker`와 `data-list-label` 사이 간격을 잰다. 이 도구는 겹친 도형의 실제 칠 면적, SVG 경로·마스크·그림자·비트맵 투명 여백·글리프의 실제 잉크 외곽이나 광학적 무게를 완전히 재지 못한다. 측정되지 않은 항목은 추정값으로 채우지 않고 캡처 확대와 사람의 비교로 판정한다. 프로젝트별 허용 차이와 왜 그 차이가 자연스러운지는 디자인 결정에 기록한다.
3. 모든 화살표의 시작점과 끝점을 확대한다. 연결선은 출발 도형의 경계에서 시작해 도착 도형의 경계에 닿아야 한다. 화살촉은 선 굵기에 비례해 찌그러지지 않는지, 몸통이 화살촉과 라벨을 구분할 만큼 보이는지 본다. 노드·되돌림 선·라벨의 간격은 도형 크기와 실제 문구에 맞춰 정하고 겹침·오독이 없는지 실측한다. 단순 시간축·범례선·캔버스 경계로 이어지는 선은 그 용도를 명시한다. 사선은 중심 간 직선이 아니라 도형 외곽과 만나는 점을 계산한다.
4. 라벨과 도형 사이 패딩을 프로젝트의 글자·도형 크기에 맞춰 정하고, 긴 문구가 이웃 항목과 겹치거나 SVG 밖으로 잘리지 않는지 본다. 앱은 확인 C에서 확정한 하한(기본 후보 14), 웹은 13 CSS px, 인쇄 문서는 최종 6.5pt 하한을 실제 표시 크기에 적용한다. 긴 문구가 들어갈 수 없다면 넓은 레이아웃·다른 유형·전체 문구가 보이는 범례로 바꾼다. 글자 크기를 계속 줄여 해결하지 않는다.
5. 문제 구간을 `위치 / 보이는 문제 / 기대 경계·기준선 / 수정 / 재촬영 결과`로 적고 수정한다. 같은 템플릿의 초기·포화·다국어·RTL에도 영향을 주는지 다시 본다.

6. 카드·표·목록을 2열 이상에 배치했다면 실제 자료의 ID를 화면에 임시 표시해 가로 읽기와 세로 읽기의 순서를 비교한다. 같은 행의 높이 차와 다음 행 시작선 어긋남을 px로 기록한다. 정렬을 바꾼 뒤 DOM 순서, 화면 순서, 키보드 순서를 다시 확인한다. 여러 열 때문에 내용 묶음이 다른 순서로 읽히면 시각 배치 또는 자료 정렬을 바꾸고 재촬영한다.

다열 검사기의 `rowGroupingTolerancePx`와 `maxRowHeightDriftPx`는 해당 글꼴·행 높이·과업의 프로젝트 값으로 명시한다. 고정된 6px/8px을 모든 앱·문서에 적용하지 않는다. SVG 표시 크기 검사기도 접근성 글자 하한을 제외한 최대 글자 크기·표시 확대 한계·좁은 화면 경계를 해당 산출물의 명시 옵션으로 받는다.

7. 웹에서 거르기·정렬·보기 변경·펼치기가 콘텐츠 높이를 바꾸면, 각 조작 전후 앱바·제목·첫 행의 x 기준선을 같은 창에서 다시 잰다. **일반 스크롤바가 폭을 차지하는 데스크톱 환경**과 겹침형 스크롤바 환경을 모두 포함한다. 콘텐츠 길이에 따라 스크롤바가 생겼다 사라져 기준선이 흔들리면 `scrollbar-gutter: stable` 또는 같은 결과의 레이아웃으로 고친다. 이 기준선의 의도하지 않은 x 이동 허용값은 0px이다.

브라우저에서 [기하 후보 검사기](../assets/visualization/geometry-audit.mjs)의 `auditSvgGeometry(svg)`와 [표시 크기 검사기](../assets/visualization/layout-audit.mjs)의 `auditSvgLayout(svg)`를 사용할 수 있다. 화살표 끝·화살촉 단위·몸통 길이·노드 간격·상자 패딩·되돌림 선과 노드 거리, 표시 배율·글자 px·SVG 밖 텍스트를 찾는다. 시퀀스 선이나 시간축 끝처럼 연결할 도형이 없는 경우도 경고할 수 있으므로 결과를 그대로 합격/불합격으로 쓰지 않는다. 검사기에서 빠진 시각적 어긋남도 반드시 사람이 확인한다.

## 공간 그림

[3D 투영 모듈](../assets/visualization/project3d.mjs)은 장면 좌표 `(x,y,z)`와 상자의 가로·깊이·높이에서 보이는 면을 계산해 SVG 다각형을 만든다. 공간 조감과 부품 분해를 평면 마름모로 대체하지 않는다. 면의 앞뒤 순서, 두께, 높이 간격, 라벨 중심, 가림 관계를 정지 화면과 조립 모션에서 각각 확인한다. 이 투영은 정사영이며 원근 카메라나 임의 메시 자동 배치는 아직 지원하지 않는다.
