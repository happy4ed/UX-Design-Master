# 컴포넌트·데이터·정렬 계약

## 역할 정의에서 시작

[화면 의미·대안 설계](semantic-design.md)에 따라 과업·의미 역할·내용·입력 전후 상태·영향 대상·선택 유지 범위부터 정의한다. 제공된 화면은 관찰/추정/미확인을 구분하고 신규 디자인은 역할을 수행할 요소·구성 variation을 비교한다. 역할과 구조 대안을 정하기 전에 외형 기준으로 재사용 컴포넌트를 확정하지 않는다.

## 전체 화면에서 시작

주요 화면을 목록화한 뒤 screen→component 사용 맵을 만든다. 기본 요소 / 공통 구성 / 공통 화면 틀 / 기능 전용 / 페이지 전용을 구분한다. 같은 역할·데이터 구조·행동을 공유하는지 보고 재사용·변형·합성·신규를 선택한다. 비슷한 사각형이라는 이유로 다른 역할을 통합하지 않는다. 대표 화면 하나에 맞춰 나머지 제품을 억지로 변형하지 않는다.

[A1 기능·정보 명세](functional-inventory.md)의 기능 ID와 정보 ID를 각 컴포넌트의 실제 슬롯·입력·결과·상태에 연결한다. 화면 맵에만 있고 컴포넌트에 자리가 없는 필수 정보, 눈에 보이는 버튼이지만 기능 ID·결과가 없는 조작, 조건부 기능인데 조건이 드러나지 않는 상태를 와이어프레임 전에 수정한다. 확정되지 않은 제안을 기존 기능처럼 표시하지 않는다.

## 컴포넌트별 최소 명세

| 계약 | 정의 |
| --- | --- |
| 역할·범위 | 목적, 사용 화면, 소유 범위, anatomy·필수/선택 슬롯, 원본 API |
| 콘텐츠 | 필드 유형·출처·필수 여부·범위·언어·형식·우선순위 |
| 값의 계보 | 원본 값·사용자 수정 값·계산 값의 구분, 원본 위치, 계산식·입력값·단위·검산 결과 |
| 표시 | 한 줄/여러 줄·최대 줄 수·줄바꿈·말줄임·원문 접근·이미지 비율·크롭·실패 대체 |
| 크기·배치 | fixed/intrinsic/fill/proportional/bounded-fluid, min/max, flow/absolute/sticky/fixed, 기준 부모·앵커 |
| 정렬 | 공유 외곽·텍스트 시작선·baseline·숫자 끝선·공통 열·시각 중심·들여쓰기 |
| 시스템 | primitive→semantic→component 토큰, R·간격·색·폰트·상태별 매핑 |
| 동작 | 상태 축·합법 조합·트리거·공간 점유·레이어·가림·스크롤·포커스·중단·복구 |
| 입력 방식 | 인스턴스별 클릭/탭·호버·롱프레스·드래그/드롭·스와이프·키보드의 허용/불허/조건부, 대체 조작·충돌·취소 |
| 검증 | 초기/포화 fixture, 폭·확대·입력 조건, 관찰 근거, 실행 결과·미검증 |

다음은 정의 충돌이다: 고정 높이+무제한 줄+잘림 금지, 필수 원문 읽기+말줄임+원문 접근 없음, 이미지 크기 변경+예약 영역 없음, 가려진 배경의 포커스 허용+모달 포커스 한정. 충돌을 해결한 뒤 구현한다. 데이터 제한을 맞추려고 실제 내용을 몰래 자르지 않는다.

조작 가능한 인스턴스는 [마우스·터치·키보드 인터랙션 계약](multi-input-contract.md)을 추가로 작성한다. 기본 컴포넌트명만으로 드래그/롱프레스 허용 여부를 결정하지 않는다. 일반 버튼과 이동 손잡이는 같은 버튼 계열이어도 별도 변형·행동 계약을 가진다.

텍스트 슬롯은 [공통 텍스트 영역 계약](text-layout-qa.md)으로 확장한다. 제목·라벨·설명·값·빈 상태·오류 문구마다 실제 영역과 줄/문단 간격을 따로 두고, 포화·번역 문구를 넣어 도형 확대/재배치와 제한된 폰트 조정을 결정한다. 곡선·외곽선·회전 글자는 변형 후 외곽과 읽는 방향도 명세한다. 웹·앱 미리보기는 내부 `auditTextRegions`로 실제 글리프와 이웃 슬롯의 침범을 확인한다.

자동 추출·계산이 있는 화면은 원본 항목과 값을 그대로 보존해 보이고 계산 값은 별도 필드로 둔다. 계산 값마다 펼쳐 볼 수 있는 식, 사용한 원본 항목·단위·수정 이력을 연결한다. 원본 서식에 검산식이 있을 때만 그 식과 결과를 대조하고, 없으면 없다고 표시한다. [처리 유형별 과업 의무](../knowledge/task-obligations.json)의 자동 인식·계산 항목과 같은 ID로 A1→컴포넌트→검증을 추적한다. 원본 값을 집계값으로 덮거나 신청용 필드만 남기는 상태는 실패다.

## 단일 시나리오 사실 표

여러 화면에서 같은 대상을 보여주면 **단일 시나리오 사실 표**를 먼저 만든다. 대상 ID별 이름·날짜·수량·금액·상태·소유자·원본/계산 출처를 한 번 정의하고, 각 화면·오류/완료 상태가 그 ID를 참조하게 한다. 포맷과 요약은 달라도 원값과 상태 의미는 화면마다 달라지지 않아야 한다. 확인 B·C·D에서는 화면 캡처의 표시값을 사실 표와 대조하고, 한 화면의 숫자만 고친 채 다른 화면이 옛 값이면 FAIL로 기록한다. 가상 값은 데모 자료로 표시하며 실제 사실처럼 제시하지 않는다.

한 화면의 모든 조작을 **대상 자료 / 바뀌는 것 / 결과 집합·순서** 표에 함께 적는다. 필터와 정렬처럼 이름이 달라도 같은 결과를 만드는 조작이 있으면 하나를 제거하거나 둘 다 필요한 과업 근거를 적는다. 사용자 요청 밖의 조작·선택지는 제안으로 분리하고 기본 화면에 넣지 않는다. [조작 중복 검사기](../scripts/check_control_overlap.py)의 동일 결과·목적 겹침 경고를 실제 과업과 대조한다. 이 표는 확인 B 직전 리허설에서 실제 상태 전환으로 검증한다.

## 보이는 외곽·조작 영역·배치 공간

[공간 계약](component-knowledge.md)의 visibleBounds / componentBounds / hitBounds / layoutSlot을 구분한다. 부모를 내용 외곽에 맞춰 타이트하게 잘라 여백 정보를 없애지 않는다. 부모 inset·반복 행/열·슬롯·형제 gap·예약 공간을 먼저 연결하고 각 조작 요소에 플랫폼 기준의 최소 조작 크기·이격을 검토한다. 실제 hit 영역은 스크린샷만으로 확정하지 않는다.

## 정렬 관계를 설계하는 순서

1. 의미·비교·반복·위계를 기준으로 정렬 집단을 식별한다.
2. 집단이 공유할 외곽·baseline·열·숫자 끝선·앵커 축을 정한다. 기본값을 수평/수직 중앙 정렬로 통일하지 않는다.
3. gap·inset·indent·section 간격을 같은 단위·배수 체계와 의미 토큰에 연결한다. 부모 padding과 자식 margin의 누적을 계산한다.
4. 반복 요소의 슬롯, 선택 슬롯의 공간 유지/회수, 내용 변화 흡수 영역을 정한다. 길이가 다른 각 행을 독립적인 space-between으로 맞추지 않는다.
5. 좁아지거나 글자가 커질 때 무엇을 보존하고 무엇이 줄바꿈·재배치되는지 결정한다. DOM·읽기·키보드 순서를 유지한다.
6. 기준선·열 오버레이로 기하 관계를 확인하고, 오버레이 없는 실화면에서 글리프·아이콘·투명 여백의 광학 정렬을 확인한다. 보정은 해당 자산·컴포넌트 규칙으로 기록한다.

고정 크기와 절대좌표는 별개다. 정확한 설계는 모든 좌표가 고정이라는 뜻이 아니라 값·관계·전환 규칙이 명세되어 있다는 뜻이다. 모든 값이 배수여도 글꼴·아이콘의 시각 중심이 맞는지는 별도 검토한다.

## 동적 공간·가림

변화마다 trigger→state→space effect→affected component를 연결한다.

- 공간: 주변 밀기 / 겹치기 / 자리 예약 / 공간 회수
- 기준: 문서 / 부모 / viewport / named anchor
- 경계: flip / shift / resize / 내부 스크롤 / 다른 형태로 전환의 우선순위
- 레이어: z-index 이름뿐 아니라 실제 stacking context·portal·clipping ancestor
- 입력: 가려진 요소의 pointer·keyboard·스크린리더 접근 가능 여부
- 보존: 입력·선택·포커스 복귀·스크롤 위치와 anchoring
- 중단: 반복 입력·전환 역전·pointer cancel·앵커 제거·화면 회전·모바일 키보드

화면 밖 / 가려짐 / 접힘 / 투명 / 제거는 서로 다른 상태다. 모달과 비모달의 정책을 구별한다. 먼저 모션 없는 배치·입력을 올바르게 만든 뒤 모션을 적용하고, 전환 전·중·후·역전을 확인한다.

## 상태는 독립 축

hover·focus·pressed, selected·mixed, loading·empty·error·populated, disabled·readonly, expanded·collapsed를 하나의 선형 enum으로 섞지 않는다. 실제 적용되는 축과 합법 조합만 정의한다. 예를 들어 선택된 행의 키보드 포커스와 오류 입력의 편집 상태를 검사한다. 의미 없는 전체 조합을 생성하지 않는다.

대표 재사용 컴포넌트는 **실제로 도달 가능한 상태×변형×테마**를 임시 검토 화면에서 선택해 볼 수 있게 한다. 현실적인 데이터와 최소/포화 자료를 데이터 경계에 주입하고, 로딩·오류·빈 상태는 시간 타이머로 자동 사라지지 않게 유지한다. 합법 조합만 열고 코드에서 도달할 수 없는 상태는 구현 완료로 표시하지 않는다. 각 상태의 조작·포커스·읽기 순서·대비·텍스트 넘침을 실제 화면에서 확인한다. 시각 방향을 고를 때 변형은 실제 페이지의 주변 요소와 함께 한 번에 하나씩 전체 크기로 보여준다. 검토 화면의 PASS를 제품의 모든 화면 PASS로 확대하지 않는다.

합성 컴포넌트에는 필수 부모/자식과 슬롯 순서, 중첩 불가 관계를 기록한다. 예를 들어 선택 항목은 해당 목록/그룹의 소유 아래에 있고, 대화상자는 읽을 수 있는 제목과 닫기·포커스 복귀 경로를 가진다. 합법적 조합은 특정 프레임워크의 태그 이름이 아니라 역할·상태·입력 관계로 정의하고, 웹·앱 구현에서는 실제 라이브러리 API에 맞춰 검증한다.

## 두 필수 경계

Initial은 실제 최초 사용·최소 데이터·기본 선택이다. Saturated는 스키마·실제 지원 범위의 긴 콘텐츠·많은 항목·동시 노출 조건이다. 화면 크기·DPR·언어·상태·시간을 고정하고 같은 컴포넌트와 토큰으로 비교한다. 개발용 fixture 전환 UI는 제품에 배포하지 않는다.

경계 시험은 필드별 최악값과 실제로 동시에 가능한 최악 조합을 구별한다. 필요한 single/error/slow 상태를 추가한다. 실패→계약 분류→소유 컴포넌트·공유 토큰 수정→영향받는 화면과 양쪽 경계 재검증으로 연결한다. 한 조건 전용 임시 좌표로 문제를 숨기지 않는다.

**업무 규칙 → 시험 자료:** A1의 묶기·나누기·예외 규칙마다 규칙의 결과가 화면에 드러나는 자료를 최소 1건 만들고 fixture ID·해당 화면 캡처를 연결한다. 포화는 개수와 긴 문구뿐 아니라 동일 이름 아래 여러 묶음, 완료 후 새 묶음처럼 규칙의 경계도 포함한다. 카드·표가 2열 이상이면 [다열 읽기·정렬 측정기](../scripts/check_multicolumn_order.py)로 가로·세로 읽기 순서, 행 높이 어긋남, 정렬 변경 뒤의 순서를 DOM·스크린샷·실제 조작으로 기록한다. 순서가 과업의 기대와 다르면 배치나 정렬 모델을 고친다.

## 근거와 영향 추적

source ID·screen/state ID·component ID·token ID·fixture ID·검증 evidence를 연결한다. 제목 줄 수·폰트·토큰을 바꾸면 이 맵으로 높이·행동 위치·반복 정렬·사용 화면을 다시 검사한다. 관찰 수치, 추정, 새 제품의 채택 결정은 별도 필드로 보존한다.
