# 컴포넌트별 마우스·터치·키보드 인터랙션 계약

화면의 모든 **조작 가능한 컴포넌트 인스턴스**에 입력 방식을 명시한다. [역할별 시작 프로필](../knowledge/interaction-capabilities.json)은 후보일 뿐이며, 같은 button이라도 일반 실행 버튼과 재정렬 손잡이는 다른 계약이다. 정적 스크린샷 분석에서는 실제 동작을 추정하지 말고 미확인으로 적는다.

## 인스턴스 명세

| 항목 | 반드시 기록할 것 |
| --- | --- |
| 역할과 범위 | 컴포넌트 ID·변형·사용 화면, 조작이 바꾸는 데이터/상태, 실제 조작 영역 |
| 클릭·탭 | 누르는 위치, 실행 시점, 반복 탭, 실행 후 상태·포커스 |
| 호버 | 마우스에서만 가능한 보조 피드백·툴팁; 터치와 키보드에서 같은 정보에 접근하는 방법 |
| 누름·롱프레스 | 누름 피드백, 길게 눌렀을 때의 목적·시간, 이동/손가락 이탈/취소 시 결과, 발견 가능한 대체 버튼 |
| 드래그·드롭·스와이프 | 허용 여부와 이유, 시작 손잡이·이동 임계값·드롭 대상·미리보기·취소·실패 복귀, 단순 탭/클릭 대체 |
| 키보드 | Tab 진입·실행·방향키·Escape·포커스 복귀 및 같은 결과를 내는 대체 조작 |
| 충돌 | 탭 vs 롱프레스, 스크롤 vs 드래그, 선택 vs 이동, 자식 버튼 vs 카드, 텍스트 선택 vs 행 이동의 우선순위 |
| 상태와 검증 | hover/focus/pressed/dragging/disabled와 합법 조합, 마우스·터치·키보드 실기 검증 결과 |

각 입력 방식은 `supported`, `unsupported`, `conditional`, `unknown` 중 하나로 기록한다. `unsupported`에는 역할상 불필요하거나 충돌하는 이유를 쓴다. `conditional`에는 활성화 조건과 대체 경로를 쓴다. `unknown`은 관찰할 수 없었던 기존 화면의 분석 상태일 때만 쓴다. 새 디자인의 구현 명세에서 미확인 상태를 방치하지 않는다. 입력 가능 동작을 모두 넣으라는 뜻이 아니라 **가능/불가능/조건부를 명확하게 결정**하라는 뜻이다.

## 역할에 따른 차이

- **일반 버튼:** 클릭·탭·Enter/Space 실행. 호버·포커스 피드백 가능. 롱프레스·드래그는 기본적으로 비활성이다. 버튼 모양만 같다고 이동 기능을 붙이지 않는다.
- **이동 가능한 항목:** 드래그를 실제 과업으로 승인한 변형에만 이동 손잡이와 드롭 대상이 있다. 항목 본문의 탭/클릭은 기존 선택·열기 동작을 유지한다. 이동 위/아래 버튼 또는 목적지 선택처럼 끌지 않아도 같은 결과를 낼 수 있어야 한다.
- **카드·리스트:** 전체가 하나의 행동이면 전체를 조작 대상으로 삼을 수 있다. 내부에 여러 행동이 있으면 제목 링크·메뉴·이동 손잡이의 영역을 분리한다. 카드/행의 롱프레스 메뉴에는 보이는 메뉴 버튼을 둔다.
- **슬라이더·시트·캔버스:** 드래그가 자연스러운 경우에도 값 입력·증감 버튼·명시적 도구 등 단일 포인터 비드래그 경로와 키보드 경로를 설계한다. 시트 내용의 스크롤과 손잡이 이동을 분리한다.
- **파일 드롭 영역:** 파일 드롭이 있어도 파일 선택 버튼을 둔다. 업로드 검증과 오류 메시지는 두 경로에서 같다.
- **연속 이미지:** 이전·다음 버튼을 기본 경로로 제공한다. 스와이프는 선택적 추가 조작이고 이미지 확대 보기에서는 열린 영역에 한정한 방향키·Escape를 정의한다.

## 제스처 충돌과 실행

1. 포인터 종류를 감지하되 데스크톱 터치스크린처럼 여러 입력이 있는 환경에서도 기능이 유지되게 한다. hover만으로 필수 정보·명령을 보여주지 않는다.
2. 롱프레스의 시간과 이동 허용 범위는 프로젝트에서 명시하고 실제 기기에서 조정한다. 길게 누르기가 성립하면 손을 뗄 때 일반 클릭을 다시 실행하지 않는다. 이동·취소·화면 전환 시 타이머와 임시 상태를 지운다.
3. 드래그 시작 임계값을 정하고 스크롤 방향과 겹치는 경우 별도 손잡이 또는 명시적 이동 모드를 쓴다. `pointercancel`, 취소 키, 드롭 불가 영역에서 원래 상태로 복귀하고 포커스를 잃지 않는다. `touch-action`으로 페이지 스크롤을 불필요하게 막지 않는다.
4. 스와이프·드래그처럼 경로에 의존하는 조작에는 단일 포인터의 단순 조작 대안을 둔다. 그와 별도로 키보드로도 같은 과업을 완료한다. 실패·취소·재시도에서 결과가 일치하는지 본다.
5. 조작 영역과 최소 크기·인접 대상 간격은 [컴포넌트 계약](component-contract.md)에 기록한다. 화면의 보이는 도형 크기를 실제 터치 영역으로 오인하지 않는다.

설계 화면별 인스턴스 목록을 [입력 계약 매니페스트 예제](../assets/interaction-contract-example.json)처럼 작성하고 `python3 scripts/check_interaction_contract.py --input manifest.json`으로 필수 필드 누락을 검사한다. 검사 통과는 동작을 증명하지 않는다. 실제 포인터·터치·키보드 검수는 [접근성 계약](interaction-accessibility.md)과 [완성도 검수](quality-review.md)에 따른다.
