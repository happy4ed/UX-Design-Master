# 다국어·RTL 필수 검수

앱·웹·문서와 그 안의 표·차트·다이어그램·인포그래픽에 적용한다. 디자인이 한 언어로 출시되더라도 **한국어, 길이가 늘어나는 라틴 문자 언어, 아랍어 RTL** 표본으로 구조를 시험한다. 실제 지원 언어가 있으면 그 언어의 검토된 번역과 로케일 데이터도 모두 확인한다. 미출시 언어 표본은 레이아웃 스트레스 자료이며 번역의 출판 승인을 뜻하지 않는다.

## 시험 행렬

| 축 | 최소 표본 | 확인할 것 |
| --- | --- | --- |
| 언어·문자 | 한국어, 영어의 긴 문구, 아랍어 RTL | 실제 글리프·폰트 폴백·가짜 굵기·행 높이·줄바꿈·클리핑 |
| 길이·데이터 | 초기와 현실적 포화 조건을 각 언어에 적용 | 제목·버튼·노드·축·범례·표 셀·캡션의 확장·말줄임·스크롤 |
| 방향 | LTR과 RTL | DOM/읽기/키보드 순서, 시작·끝 정렬, 탐색·목록·레이아웃 미러링 |
| 의미 방향 | 순서·시간·흐름·축·숫자 | 화살표와 단계 진행, 시간축 방향, 숫자·단위 순서, 전화·URL·코드처럼 미러링하면 안 되는 토큰 |
| 지역 표기 | 날짜·시간·숫자·통화·단위·복수형 | 구분자, 자리수, 단위 위치, 반올림·표본·분모의 의미 보존 |
| 접근성 | 각 언어의 실제 렌더 | 문서/영역 `lang`·`dir`, 보조 기술의 읽기 순서·이름, 키보드 포커스, 이미지 설명 |

RTL은 문자열만 오른쪽 정렬하는 작업이 아니다. 논리 순서와 시각 순서를 각각 기록하고, 흐름·계층·타임라인의 방향을 의미에 맞게 정한다. 물리적 좌우를 뜻하는 그림, 로고, 수식, 지도, 브랜드 표식 등은 무조건 뒤집지 않는다. 숫자·영문 약어·괄호가 섞인 아랍어 문장은 bidi 격리 요소(`bdi` 등)로 시험한다.

## 수행과 판정

대표 화면·페이지마다 `언어 × 초기/포화 × 좁은/일반 폭 또는 인쇄 판형`을 확인한다. 전체 페이지의 가로 넘침과 각 텍스트·도형·연결선의 겹침을 실제 렌더에서 본다. 글꼴 파일을 선언했더라도 글리프가 실제 표시됐는지 확인한다. 자동 측정은 후보를 찾는 도구이며 번역의 자연스러움·의미·시각적 정렬은 사람이 읽어 판정한다.

표현 유형이 바뀌어야 하는 경우도 기록한다. 예를 들어 긴 번역에서 작은 타임라인이 실패하면 수직 단계와 상세 표를 선택할 수 있다. 의미 요소를 조용히 삭제하거나 글자를 읽을 수 없게 축소한 경우는 실패다.

결과는 언어·방향·조건·폭·폰트·실패 위치·수정·재검증을 남기고 `PASS / FAIL / NOT_RUN / NOT_APPLICABLE`로 보고한다. **다국어 또는 아랍어 RTL 검수를 실행하지 않았으면 전체 디자인 검수를 완료로 표시하지 않는다.** 실제 서비스가 해당 언어를 지원하지 않으면 번역 품질과 인터랙션 완결성은 별도 미적용으로 구분하되 구조 스트레스 검수는 수행한다.
