# 투명 소재·형상·모션 검증 계약

유리·크롬·클레이·뉴모피즘처럼 **재질이 스타일을 구분하는 화면**과 원·알약·타원처럼 **형상 이름이 사양에 들어간 조작**에 적용한다. 색·R·그림자 토큰을 적은 것만으로 해당 재질이나 형상이 구현됐다고 판정하지 않는다. 원본이 있는 스타일은 원본의 정지 화면과 조작 영상을 먼저 보고, 원본값과 내부 가설을 구분한다.

## 1. 재질을 Z층과 배경 조건으로 정의

각 재질 컴포넌트에 `역할/사용 조건 → 뒤쪽 콘텐츠와 Z순서 → 라이트·다크 바탕 → 투과·흐림·굴절·반사·그림자 → 글자/아이콘 대비 → 상태/모션 → 검증 장면`을 기록한다. 같은 화면에 풍부한 이미지, 단색 면, 긴 글자, 스크롤 중인 콘텐츠가 있으면 각각 뒤쪽 배경으로 시험한다.

투명 소재의 경우 **투과(뒤가 보임)**, **흐림(세부가 퍼짐)**, **굴절(뒤의 선·형상이 휨)**은 다른 속성이다. `opacity` 또는 `backdrop-filter: blur()`만 적용하고 굴절을 구현했다고 쓰지 않는다. 원본에서 관찰된 속성만 필수로 삼되, 굴절을 표방한다면 선·색 경계가 렌즈 안팎에서 어떻게 이어지는지 실제 렌더로 확인한다. 테두리 반사·색 채택·광도 변화는 배경을 가리지 않는 범위에서 쓴다. 라이트 모드에서 불투명한 흰 채움과 양쪽/바깥 그림자로 볼록한 양각 버튼처럼 보이면, 원본이 그런 물성이 아닌 한 실패다.

`clear`처럼 배경을 드러내는 소재와 `regular`처럼 글자를 읽기 쉽게 만드는 소재는 같은 스타일 안에서도 용도가 다를 수 있다. iOS Liquid Glass의 예시는 [iOS 27 E/G/L절](style-book/ios-27.md)에 있다. 특정 플랫폼의 소재 이름을 모든 스타일의 표준 토큰으로 만들지 않는다. 미디어 위에서 배경을 보여 주는 조작과 글자가 많은 일반 내비게이션, 본문 카드의 소재를 각각 분리한다. 배경이 바뀌면 전경의 대비를 재확인하고 필요하면 글자 주변만 보정한다. 투명도 감소·고대비에서는 불투명한 대체 상태를 제공한다.

### 정지 화면 비교

| 증거 | 확인할 것 |
|---|---|
| 배경만 | 콘텐츠/사진/단색의 실제 색과 선 경계, Z순서 |
| 재질을 겹친 화면 | 뒤의 색·윤곽이 얼마나 통과하는지, 굴절 위치, 가장자리 반사, 글자 대비 |
| 재질을 잠시 끈 화면 | 효과가 실제로 픽셀을 바꾸는지. 픽셀 차이는 구현 증거일 뿐 원본 일치 증거가 아님 |
| 라이트·다크·좁은 폭 | 탁한 막, 과도한 그림자, 배경별 대비, 잘림·넘침 |

## 2. 재질과 함께 움직이는 조작

재질 효과의 모션은 범용 `fade`나 `scale`을 이름만 바꿔 붙이지 않는다. 원본 조작에서 `누름 → 중간 형상·반사·배경 샘플 변화 → 정착 → 역전/재입력`을 관찰하고, 여러 조작이 합쳐지거나 갈라지면 각 요소의 시작·끝과 **중간의 연결 관계**를 명세한다. 정적 화면 두 장 사이에 갑자기 새 모양이 나타나면 형상 전환 구현으로 판정하지 않는다. 선택 표지가 이동한다면 기존 표지가 목적지로 이어지는지 본다. 반사 하이라이트는 상태 변화에 종속시키고, 원본 근거 없는 상시 반복은 넣지 않는다.

시연은 버튼·탭·시트가 실제로 눌리고 열리는 화면으로 만든다. 시작·중간·끝과 닫기/역전 프레임을 같은 배경·뷰포트에서 캡처한다. `prefers-reduced-motion`에서는 정보와 상태를 유지하면서 공간 모션을 줄인다. 원본 동작을 확인하지 못했으면 설계 가설로 표시한다. 효과의 수치(시간·거리·탄성)를 한 프로젝트의 값에서 다른 프로젝트의 기본값으로 옮기지 않는다.

## 3. 이름과 실제 형상을 일치시키기

**원형**으로 명세한 조작은 시각 요소의 렌더된 `width`와 `height`가 같아야 한다. `border-radius:50%`만으로 원이 되지 않는다. Flex/Grid의 늘어남, 유동 너비와 고정 높이의 혼합, 패딩·테두리, 전환 중 비균일한 `scaleX/Y`가 타원을 만들 수 있다. 원형은 같은 지름 토큰을 두 축에 쓰고 `box-sizing:border-box; flex:none; aspect-ratio:1` 등의 수단으로 늘어남을 막는다. 알약·의도한 타원은 다른 형상으로 명세한다.

보이는 원과 실제 조작 영역을 따로 잰다. 지름은 역할·콘텐츠·기기에서 정하고 접근성 최소 조작 영역만 공통 하한으로 적용한다. 두 원 사이 간격과 다른 조작과의 겹침을 실측한다. 펼침·축소 중에도 원형 비율이 유지되는지, 라벨과 아이콘이 닿거나 잘리지 않는지 확인한다. 폰의 실제 좁은 폭·기준 폭·폴드/태블릿·글자 확대에서 시작·중간·끝 각각 검사한다. CSS 픽셀의 분수 반올림은 프로젝트 허용 오차로 기록하되 원형 판정의 `|width-height|`는 기본적으로 1 CSS px 이내를 목표로 한다.

## 4. 제출 증거와 판정

| 단계 | 최소 기록 |
|---|---|
| 스타일 조사·C | 재질의 사용 위치/배경 조건, 원본 또는 설계 가설, 라이트·다크 비교, 일반 카드와 조작층의 구분 |
| 모션 확인 D | 실제 눌리는 시연, 시작·중간·끝·역전, 배경 변화와 모션 감소 상태 |
| 제작 검수 | 원형·알약 등 형상별 bounding box, 조작 영역·간격·넘침, 실제 크기 캡처와 수정 전후 |

내부 사례: [iOS 컴포넌트 시연](../samples/style-book-component-board.html?style=ios-27), [굴절·모션·원형 회귀 검사](../tests/test_ios_liquid_glass.py). 이 테스트의 48×48px 원은 그 시연의 접근성 하한 적용값이며 모든 제품의 원형 지름을 고정하지 않는다. 자동 검사의 PASS는 치수·상태 기록의 증거다. 유리처럼 보이는지, 플랫폼 원본과 동작이 같은지는 실제 재생과 나란히 본 화면으로 별도 판정한다.
