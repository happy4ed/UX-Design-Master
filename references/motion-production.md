# 원본 근거 모션 제작 모듈

이 모듈은 중복 판정이 끝난 **대표 모션 ID와 변형**으로 실제 앱·웹·문서 시연을 만들 때 사용한다. 2026-11-02 판의 분류 결과는 원본 414개 이름에서 단독 동작이 아닌 19개와 중복 52개를 분리한 **고유 모션 343종**이다. [고유 동작 분류 집계](../knowledge/motion-core-progress.json)의 대표 ID를 제작 기준으로 쓴다. 이 수는 모션 개념 분류 결과이며 시연의 원본 일치나 제작 완료 수가 아니다.

각 대표 ID의 구체적인 대상·핵심 변화·오용 방지·매체 변환은 [고유 모션별 제작 명세](motion-authoring.md)를 읽는다. 기존 원본 문구와 이후 사용자 수정을 분리해 기록한다.

## 입력 계약

| 입력 | 필수 내용 |
| --- | --- |
| 분류 | 대표 ID, 한글·영문 표시명, 검색 별칭, 변형 ID, 판정 근거와 미검증 범위 |
| 원본 동작 | 원본 시연/버전, 움직이는 대상, 시작·결정적 중간·끝 화면, 변화 축·궤적·사건 순서, 반복·역전 |
| 적용 맥락 | 앱/웹/문서, 실제 컴포넌트·화면 또는 장면, 사용자 사건, 정지 상태에서 남길 정보 |
| 수치 | 원본에서 확인한 거리·각도·투명도·시간·이징과 추정값의 구분 |
| 입력/중단 | 클릭·탭·스크롤·자동 재생 중 무엇이 시작하는가, 재입력·취소·뒤로가기·모션 감소의 결과 |

원본에서 확인할 수 없는 값은 새 제품용 설계값으로 명시한다. 원본과 맞는다고 주장하지 않는다. 이름만 다른 별칭은 한 대표 구현을 호출하고, 맥락 변형은 대상·변수·완료 상태를 별도 설정으로 둔다. 변화 순서나 결정적 장면이 다른 동작은 같은 렌더러의 이름 바꾸기로 처리하지 않는다.

원본 시연이 붙인 이름과 실제 현상의 원리가 다르면 현상의 정의를 별도 근거로 확인하고, 원본의 관찰 결과와 수정한 동작을 구분해 기록한다. 예를 들어 모아레는 교차 격자 자체보다 거의 같은 주기의 두 격자가 겹치며 생기는 큰 간섭 무늬가 보여야 한다. 이 경우 수정본을 원본 일치 PASS로 표시하지 않는다.

## 제작 순서

1. 원본을 실제 재생해 동작의 시작, 사건이 갈리는 중간 시점, 끝을 **시간축의 표**로 적는다. 중간 장면이 보이지 않는 원본은 대체 원본을 찾아 판정을 보류한다. 시작·중간·끝 3장만으로 결정적 프레임을 놓칠 수 있으면 추가 시점을 잡는다.
   - 캔버스나 WebGL 원본을 정지 시점 보드에 옮겼을 때 검은 화면이 나오면 캡처 성공으로 기록하지 않는다. 원본을 그대로 재생하는 보드를 열어 시작·중간·끝을 확인한다. 특히 애니메이션 프레임 예약, 기기 모션 감소 설정, 프레임 로드 완료 순서 때문에 빈 화면이 생기는지 확인한다.
2. 동작이 가장 잘 드러나는 샘플을 고른다. 화면 전환은 전후 장면, 숫자 모션은 실제 자릿수와 값, SVG 선은 경로와 끝점, 카메라 모션은 전경·배경 깊이가 있는 장면으로 보여준다. 같은 그룹의 카드를 일괄 재사용하지 않는다.
3. 효과를 상태 기계로 구현한다: `idle → triggered → active phases → settled`, 필요하면 `interrupted/reversed`. 실제 UI 사건과 완료 상태를 연결한다. CSS, Web Animations API, SVG, Canvas/WebGL, 영상 중 표현 가능한 경로를 고르고 표현 불가능한 원본 효과는 시연 스케치로 표시한다.
4. 정지 화면의 정보, 모션 감소, 키보드·터치 입력, 재생·일시정지·재시작을 함께 구현한다. 반복 시연은 검토 화면에서만 기본값으로 켜고, 제품에서는 사건에 맞춰 재생한다.
5. 원본과 내부 결과를 같은 표시 크기·대상·상태와 **결정적 시점**으로 나란히 본다. 대상, 변화 축, 경로, 순서, 중간 장면, 종료 상태를 각각 PASS/FAIL/NOT_RUN으로 기록한다. 시간·이징은 별도로 측정한다. 한 항목이라도 원본 의미가 다르면 내부 재현 PASS가 아니다.
6. 완성 예시를 앱 컴포넌트, 웹 화면, 문서/슬라이드에 적용할 때 각 매체의 시작 사건과 멈춘 상태를 다시 검사한다. 화면 밖·너무 작은 변화, 빈 프레임, 텍스트 가림, 클릭 후 상태 불일치는 수정한다.

## 산출물

대표 ID마다 `motionId / variantId / sampleTarget / sourceEvidence / phaseTimeline / implementationRoute / parameters / staticFallback / reducedMotion / inputAndInterruption / renderedFrames / sourceMatch / accessibility / status`를 남긴다. 시연 URL·실제 프레임과 소스 위치를 연결한다. 별칭만 추가된 경우 중복 구현을 만들지 않고 대표 시연으로 연결한다. **원본 대조 미완료, 임시 브라우저 스케치, 원본과 다른 대체 구현은 각각 별도 상태**로 표시한다.

모션 수를 다시 셀 때는 `원본 용어 수 / 검토 완료 용어 수 / 확정 대표 동작 수 / 별칭 수 / 맥락 변형 수 / 조합 레시피 수 / 보류 수 / 내부 원본 일치 PASS 수`를 나란히 제시한다. 이 값들을 하나의 “완료 모션 수”로 합치지 않는다.
