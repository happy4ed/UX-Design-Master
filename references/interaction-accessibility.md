# 키보드 인터랙션과 접근성 계약

컴포넌트의 외형보다 **역할과 상태 변화**를 먼저 정한다. [내부 키보드 패턴 20종](../knowledge/keyboard-interactions.json)은 진입, 내부 이동, 실행, 탈출, 포커스, 상태 알림을 함께 담는다. 새 화면의 모든 조작 가능 요소에 아래 계약을 적용하고 화면별 [지식 적용 표](knowledge-application.md)의 `interaction` 영역에 결정과 실제 검증 근거를 연결한다. 정적 스크린샷만 있는 경우 동작은 추정하지 않고 `미확인`으로 남긴다.

키보드 계약은 [마우스·터치·키보드 인스턴스 계약](multi-input-contract.md)과 함께 사용한다. 실제 기능의 클릭·탭·롱프레스·드래그 대체 조작까지 정의해야 같은 기능이 입력 장치에 따라 누락되지 않는다.

## 화면의 키보드 경로

| 단계 | 정의할 것 |
| --- | --- |
| 진입 | Tab/Shift+Tab으로 어디에 도착하는가; DOM·읽기 순서와 시각 순서가 맞는가 |
| 실행 | Enter/Space가 무엇을 실행하는가; 선택·이동·설정 변경을 구별하는가 |
| 내부 이동 | 복합 위젯의 화살표·Home/End를 어느 영역에서만 받는가 |
| 탈출 | Tab으로 다음 영역으로 갈 수 있는가; Escape가 닫기·취소·편집 종료 중 무엇을 하는가 |
| 포커스 | 열릴 때·닫힐 때·목록 변경 뒤 포커스가 어디에 있고 항상 보이는가 |
| 상태 | 이름·역할·값·선택·오류·진행과 현재 위치가 화면과 접근성 트리에 일치하는가 |

기본 버튼·링크·입력은 네이티브 요소를 먼저 사용한다. **Tab은 페이지의 조작 대상 사이를 이동**하며 일반 컨테이너에서 가로채지 않는다. 탭·메뉴·리스트박스·그리드처럼 하나의 복합 위젯 안에서는 한 Tab 정지점과 방향키 이동을 사용할 수 있다. `tabindex>0`로 순서를 꾸미거나, 시각적으로 숨긴 내용을 Tab 경로에 남기지 않는다. 버튼·이미지·아이콘의 포커스 표시가 배경·그림자·고정 헤더에 가려지지 않아야 한다.

## 연속 이미지 크게 보기

썸네일은 버튼 또는 링크로 만들고 접근 가능한 이름을 붙인다. 크게 보기를 열면 이름 있는 대화상자의 적절한 요소로 포커스를 옮긴다. 대화상자 안에 **이전·다음·닫기 버튼**을 두고, 열린 동안에만 `←`/`→`로 이미지를 이동한다. 버튼과 방향키는 동일한 현재 이미지·설명·`현재/전체` 값을 갱신한다. `Escape`로 닫고 원래 썸네일 또는 논리적인 다음 요소로 포커스를 돌려준다. 처음/끝에서 순환할지 멈출지 정해 버튼의 상태와 키 동작을 일치시킨다. 모달이 열려 있는 동안 배경은 포커스·클릭 대상이 아니다. 이미지마다 의미 있는 대체 텍스트를 제공하고 캡션을 읽을 수 있게 한다.

썸네일 목록이 캐러셀이면 이전·다음 버튼은 Tab으로 접근하며 누른 뒤 포커스를 유지한다. 자동 넘김을 쓰면 키보드 포커스가 들어올 때 정지하고, 사용자의 명시적인 재생 동작 없이 다시 시작하지 않는다. 방향키가 모든 캐러셀의 기본 동작이라고 가정하지 않는다. 방향키는 탭형 슬라이드 선택기나 열린 이미지 뷰어처럼 역할과 범위가 정해진 곳에서만 사용한다.

## 단축키와 충돌

- 제품 전역 단축키는 필요한 과업만 정의하고 사용자가 발견할 수 있는 도움말·메뉴에 표시한다. 브라우저·운영체제·보조기술의 기존 조합을 덮어쓰지 않는다.
- 문자 하나만 누르는 단축키는 해당 컴포넌트에 포커스가 있을 때만 활성화하거나 끄기/재매핑 기능을 제공한다. 텍스트 입력·contenteditable·IME 조합 중에는 전역 단축키를 실행하지 않는다.
- 화살표는 스크롤, 커서 이동, 슬라이더 값 조정 등 기존 용도가 있다. 관련 위젯이 활성화된 경우에만 `preventDefault`하고 다른 곳의 기본 동작은 보존한다.
- `aria-keyshortcuts`나 화면 도움말은 **실제로 구현된** 조합만 적는다. 마우스·터치·키보드가 같은 상태를 변경하도록 단일 동작 함수를 공유한다.

## 접근성 검수

1. 마우스를 내려놓고 Tab/Shift+Tab만으로 주요 흐름을 처음부터 끝까지 수행한다. 포커스가 사라지거나 갇히는 지점을 기록한다.
2. 각 복합 위젯의 방향키·Home/End·Enter/Space·Escape를 실제 상태와 비교한다. Tab으로 다음 영역에 나올 수 있어야 한다.
3. 모달 열기/닫기, 오류·로딩·선택 변화, 목록 재정렬에서 포커스와 접근 가능한 이름·상태·알림을 확인한다. 필요 이상으로 `aria-live`를 반복하지 않는다.
4. 초기·콘텐츠 포화, 좁은 폭·확대, 긴 번역·RTL, 모션 감소에서 키보드 경로와 포커스 위치를 다시 확인한다.
5. 브라우저·플랫폼 접근성 트리와 실제 키보드 조작을 함께 본다. 자동 검사 통과만으로 사용 가능하다고 선언하지 않는다.

[실행 예제](../samples/interaction-keyboard-review.html)에는 Tab 이동, 탭의 방향키 이동, 썸네일 크게 보기와 대화상자 안의 이전·다음·닫기 동작을 포함한다. 예제의 단축키를 모든 제품에 일괄 적용하지 않는다.
