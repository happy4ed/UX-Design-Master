# 화면·문서 문구와 목소리

문구는 디자인의 마지막 장식이 아니다. 버튼 이름, 빈 상태, 설명, 오류, 표제는 사용자가 다음에 무엇을 할지 정한다. 구성안을 만들 때 실제에 가까운 문구를 넣고, 시각 디자인 전에 길이와 의미를 확인한다. 이 지침은 스킬 내부의 작성·검수 원칙이다. 외부 언어 스킬이나 문구 생성 서비스를 호출하지 않는다.

## 문구를 쓰기 전에

각 문구마다 `읽는 사람 / 현재 상황 / 알아야 할 사실 / 할 수 있는 행동 / 말투 / 표시 공간`을 적는다. 출처가 없는 수치·성과·후기·확신은 만들지 않는다. 버튼은 누른 뒤 생기는 일을, 상태 문구는 실제 상태와 복구 방법을 말한다. 작은 UI 문구에 제품 자랑이나 추상적인 비전을 넣지 않는다.

기존 제품·브랜드의 문장 2~3개가 있으면 그 문장의 높임법, 문장 길이, 전문 용어, 어휘 선택을 내부 `voice profile`로 요약한다. 실제 사용자 문구가 없으면 과장 없는 평이한 한국어를 기본으로 한다. 언어마다 같은 목소리를 기계 번역하지 말고 그 언어의 자연스러운 문장으로 다시 쓴다.

## 작성과 수정

- 한 문장에는 한 가지 정보나 행동을 담는다. ‘경험을 제공한다’, ‘가치를 전달한다’, ‘최적화된 여정을 지원한다’처럼 대상과 행동이 빠진 표현은 실제 화면의 사실·동사로 바꾼다.
- 세 문장짜리 균일한 나열, 반복되는 대구, 불필요한 결론 문장, 매 항목에 같은 형용사를 붙이는 습관을 찾아 고친다. 단어 금지 목록만 돌려 어색한 동의어로 바꾸지 않는다.
- 번역투·추상 명사 연쇄·이중 피동·문장마다 이어지는 접속사를 문맥에서 확인한다. 고유명사·수치·날짜·단위·조건·불확실성은 보존한다. 사실을 바꾸어 문장만 자연스럽게 만들지 않는다.
- 브랜드가 진지한 화면이면 차분하게, 작업 화면이면 짧고 직접적으로, 도움말이면 충분히 설명한다. 모든 장르를 같은 말투로 평탄화하지 않는다.
- 정보가 빈약한 문장은 ‘인간적인’ 비유를 더해 감추지 않는다. 필요한 데이터가 없으면 담당자에게 확인할 항목으로 남긴다.

## 내부 문구 검수 지도

| 살필 문제 | 화면·문서에서의 판단 | 수정 방향 |
| --- | --- | --- |
| 번역투 | 짧은 안내에도 `~에 있어서`, `~를 통해`, 이중 피동이 반복되는가 | 사용자·시스템을 주어로 놓고 실제 동사를 쓴다 |
| 영어 병기 | 일상적인 말까지 매번 영어를 괄호로 붙이는가 | 제품 고유명사·표준 기술 용어만 남긴다 |
| 기계적 구조 | 모든 카드가 같은 세 문장, 같은 불릿 수, 같은 제목 꼴인가 | 정보량과 중요도에 맞춰 길이를 달리한다 |
| 상투 문구 | 기능 설명 없이 ‘혁신’, ‘새로운 경험’, ‘가치’를 약속하는가 | 지금 화면에서 가능한 행동과 결과를 말한다 |
| 일정한 리듬 | 안내 문장이 모두 같은 길이와 종결형으로 이어지는가 | 짧은 행동 문구와 설명 문구의 역할을 구분한다 |
| 수식 과다 | 같은 뜻의 형용사·부사가 겹치고 내용 명사보다 앞서는가 | 검증할 수 없는 수식어를 덜어낸다 |
| 과도한 완곡 | 확정 상태를 `~할 수 있을 것으로 보입니다`처럼 돌려 말하는가 | 실제 확실성에 맞춘다. 불확실하면 그대로 표시한다 |
| 접속사 밀집 | `또한`, `따라서`, `이를 통해`가 문구마다 등장하는가 | 앞 문장과 독립적으로 읽히게 쓴다 |
| 형식명사 | `~하는 것입니다`, `~할 필요가 있습니다`가 행동을 가리는가 | 행동 또는 상태를 직접 적는다 |
| 장식성 강조 | 이모지·굵은 글씨·따옴표가 의미보다 많이 보이는가 | 정보 계층과 실제 상태 표시만 남긴다 |

이 표는 자동 치환 규칙이 아니다. 한 번 나온 표현만으로 문구를 고치지 않고, 문맥·빈도·브랜드 목소리를 본다. 의료·법률·재무 안내의 불확실성, 인용문, 실제 제품 명칭은 정확성이 우선이다.

## 칸에 넣고 검수

문구 슬롯마다 `권장 줄 수 / 최대 줄 수 / 줄바꿈 / 원문 보기 / 숫자·이름 같은 가변 부분`을 정한다. 화면에는 가장 긴 현실적인 문구를 실제 글꼴로 넣어 본다. 글자가 넘칠 때는 문장과 영역의 우선순위를 다시 정하고, 필요하면 다른 구성으로 옮긴다. 최소 글자 크기 아래로 줄이거나 숨긴 말줄임표만 남기지 않는다.

검수는 다음 세 번으로 나눈다.

1. **의미:** 상태·행동·수치·출처·확신의 정도가 맞는가.
2. **목소리:** 읽으면 실제 제품 담당자가 쓸 법한가. 같은 어구·길이·종결이 반복되는가.
3. **실렌더:** 긴 한국어·영어·RTL 문구가 칸 안에서 정렬되고, 줄바꿈·터치 영역·이웃 요소를 해치지 않는가.

자동 패턴 검사는 검토 후보를 찾는 데만 쓴다. ‘AI 작성 여부’ 점수나 탐지기 회피를 품질 기준으로 삼지 않는다. 문제가 없는 문구는 괜히 고치지 않는다. 작성 전후의 의미가 달라졌다면 문구를 다시 확인한다.

[내부 문구 검사기](../assets/content/copy-audit.mjs)의 `auditCopy(text)`와 `auditVisibleCopy(document)`는 상투 표현·이름 없는 조작 요소·긴 버튼 문구의 후보를 찾는다. 검사 결과가 0이어도 실제 담당자가 쓸 법한 문장인지 사람이 읽어야 한다. 화면 문구를 만든 뒤 이 검사와 실제 글꼴 렌더를 함께 수행한다.
