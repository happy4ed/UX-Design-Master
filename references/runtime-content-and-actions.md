# 실제 동작 중 콘텐츠·행동 밀도 검수

## 적용 범위

B에서는 각 구조안의 열림·선택·포화 상태를, C에서는 선택한 구성에 테마를 입힌 상태를, D와 최종에서는 **실제 조작 뒤의 화면**을 검사한다. 정지 첫 화면 한 장이나 텍스트 박스의 선언값만으로 완료하지 않는다. 앱·웹의 목록, 입력, 필터, 시트, 팝오버, 확장 영역, 키보드 표시, 오류, 되돌림에서 발동한다. 문서의 링크·접기 등 대화형 요소에도 같은 정보 보존 원칙을 적용한다.

## 정보와 조작의 우선순위

[기능·정보 명세](functional-inventory.md)의 정보 ID를 화면의 표시 슬롯과 연결하고 `필수 / 부가 / 조건부`와 원문 접근 경로를 적는다. **필수 판단 정보와 주 행동의 뜻은 잘림·말줄임·가림 없이 읽혀야 한다.** 충분한 공간이 없으면 우선순위에 따라 줄바꿈, 행 높이 증가, 보조 정보 접기, 별도 상세, 스크롤 가능한 영역, 재배치를 비교한다. 부가 정보가 요약되면 전체를 열어 볼 수 있는 경로를 제공한다. 조건부 정보는 조건이 참인 상태에서 검사한다. 시트나 확장 영역 뒤에 필수 정보가 숨겨졌다면 열기 조작과 되돌아갈 경로를 실제로 확인한다.

한 줄에 놓인 조작은 **개수의 고정 상한**으로 판단하지 않는다. 같은 줄의 기능 역할, 주·보조 위계, 사용자에게 동시에 필요한 정도, 레이블의 가독성, 실제 hit 영역과 이격, 좁은 폭·큰 글자·긴 번역에서의 배치를 본다. 서로 다른 역할의 버튼이 빽빽하게 경쟁하거나 주요 행동이 더보기 안에 묻히면 재구성한다. 도구 모음에 둘지, 다음 줄/본문으로 내릴지, 드물게 쓰는 행동을 메뉴·시트·별도 화면에 둘지 과업과 플랫폼 관례로 결정한다. 버튼을 단순히 작게 줄여 같은 줄에 우겨 넣지 않는다.

## 상태 전환 실측 순서

1. 각 주요 과업에서 `초기 → 입력/선택 → 열림·확장 → 결과 → 오류/복구 → 뒤로/닫기` 중 실제 도달 가능한 상태를 조작한다. 일반·포화 자료, 좁은 폭, 사용자 확정 최소 글자, 150/200% 글자 확대, 긴 번역/RTL과 키보드가 영향을 주는 조건을 함께 고른다. 모든 조합의 기계적 전수 대신 실패 가능성이 큰 실제 조합을 설명한다.
2. 상태마다 기기·뷰포트·DPR·글자 배율·언어·데이터 fixture·조작 순서·스크롤 위치·포커스를 기록하고 캡처한다. 조작 전·중·후의 레이아웃을 비교해 제목, 값, 단위, 버튼 레이블, 선택 상태, 오류·복구 안내가 가려지거나 잘리는지 본다. 말줄임·클리핑이 의도된 부가 정보라면 원문 접근 경로를 실제로 연다.
3. 같은 줄의 조작 목록을 `의미 역할 / 중요도 / 현재 보이는 레이블 / hit 영역 / 이격 / 실행 뒤 상태`로 적고, 시각적 군집이 너무 빽빽한지 실제 크기에서 본다. 조작끼리 겹치거나 글자를 침범하면 FAIL이다. 주 행동이 구분되지 않거나 두 조작이 같은 결과를 내면 재구성한다.
4. 스크롤되는 화면에서는 화면 전체 스크롤과 시트·리스트 내부 스크롤을 모두 끝까지 움직여 필수 정보와 닫기·확인 행동에 도달한다. 키보드 표시, 시트 높이 변경, 확장/접기, 정렬/필터 변경 뒤 스크롤·포커스·선택이 보존되는지도 확인한다. 안전 영역과 고정 하단 버튼이 마지막 행을 가리지 않는지 실제 캡처로 확인한다.
5. 발견을 `화면/상태·정보/기능 ID·실제 잘림/밀도 문제·스크린샷 위치·사용자 영향·수정 방식·수정 후 재현 결과`로 남긴다. 좁은 폭 하나만 고치는 임시 좌표 대신 정보 우선순위와 컴포넌트 배치 계약을 고친다. 바뀐 규칙의 초기·포화·다국어 상태를 다시 본다.

브라우저에서는 [동작 중 콘텐츠 후보 검사기](../assets/layout/runtime-content-audit.mjs)를 실행해 명시된 필수 정보의 DOM 클리핑·말줄임, 조작 행의 겹침·hit 영역 후보를 수집한다. 이 검사는 캔버스·이미지 안의 글자, 시각적 복잡도, 접근 가능하지만 발견하기 어려운 조작을 완전히 판정하지 못한다. 후보를 실제 화면과 조작 결과로 확인한다. 네이티브 앱은 기기/에뮬레이터에서 동일 항목을 실측한다.

웹에서는 검사할 실제 값에 `data-information-id`와 `data-content-critical` 또는 `data-content-supporting`을, 행동 묶음에 `data-action-group`을 붙인다. 보조 정보가 요약되면 `data-full-content-target`에 전체 내용을 여는 대상 ID를 기록한다. 상태를 실제로 연 뒤 `import { auditRuntimeContent } from './assets/layout/runtime-content-audit.mjs'`로 불러와 결과의 `CRITICAL_CONTENT_CLIPPED`, `SUPPORTING_CONTENT_NO_FULL_PATH`, `ACTION_LABEL_CLIPPED`, `ACTION_HIT_OVERLAP`을 화면에서 확인한다. `ACTION_ROW_REVIEW`는 같은 줄의 개수·박스·최소 간격을 보고하는 **사람 검토용 측정값**이며 개수만으로 실패시키지 않는다.
