# 동작하는 프로토타입 계약

## 적용과 확인 시점

앱·웹·대화형 문서처럼 사용자가 조작하거나 여러 상태·화면을 거치는 결과물은 확인 D에서 **실행 가능한 프로토타입**을 보여준다. 화면 구조와 시각 방향은 확인 A1→A2→A3→B→C에서 합의한 범위를 따른다. D에서는 모션 후보와 조작의 실제 연결을 보고 확정한다. 읽기 전용 일반 문서만 조작형 프로토타입 의무에서 제외한다. 스크롤에 따라 내용이 바뀌거나 버튼·탭·폼·링크·확대 보기 등이 있으면 대화형으로 취급한다.

## 최소 작동 범위

| 대상 | 실제로 작동해야 하는 것 | 확인 근거 |
| --- | --- | --- |
| 화면·페이지 | 실제 길이의 세로/가로 스크롤, 고정·접힘 요소, 화면 이동과 뒤로가기 | 시작→목표→복귀 화면의 실제 렌더 |
| 조작 | 핵심 버튼·탭·필터·입력·선택·메뉴·대화상자의 실행, 취소, 비활성 조건 | 조작 전후 상태와 사용자에게 보이는 피드백 |
| 흐름 | A2의 대표 과업 하나 이상을 시작→실행→결과까지, 중요한 분기·오류·복구까지 | 단계별 경로와 재현 순서 |
| 모션 | 선택 후보의 트리거·시작/끝·시간·이징·중단/재입력, 정적 대안과 모션 감소 | 실제 프로토타입의 재생과 상태 유지 |
| 접근성·경계 | 키보드 Tab·실행·닫기·포커스 복귀, 터치 영역, 긴 내용·빈 상태·포화 상태 | 실제 조작 및 좁은/넓은 화면 확인 |

백엔드가 아직 없어도 결정 가능한 대표 데이터를 로컬 상태로 연결한다. 실제 서비스 결과처럼 보이는 가짜 성공은 `데모 데이터`로 표시하고, 미구현 기능은 눌러도 아무 일 없는 버튼으로 두지 말고 시연 범위 밖임을 명시한다. 외부 링크나 동영상, GIF, 클릭되지 않는 화면 묶음은 조작 가능한 프로토타입의 대체물이 아니다. 개별 모션 갤러리는 후보 비교에만 쓴다.

대표 과업의 일부 버튼만 시험하는 것으로 끝내지 않는다. **화면별 주 행동 버튼을 전수 나열**하고, 각 버튼을 그 화면의 첫 상태에서 실제로 눌러 `다음 상태/화면·취소/복귀·실측 근거`를 적는다. 시연도 결과 페이지가 아니라 버튼을 누르기 전 상태에서 시작한다. 업로드·촬영·공유처럼 플랫폼에서 선택 단계가 기대되는 행동은 해당 플랫폼의 화면 패턴과 대조해 진입 시트·권한·취소를 연결한다. 반응 없는 주 행동이 한 건이라도 있으면 D 제시 전에 고친다.

A1에서 핵심 대상으로 정한 항목은 D에서 `만들기 → 보기 → 수정 → 결과/완료 후 상태`를 실제 조작으로 전수 따라간다. 각 단계의 ID·표시값·상태를 단일 시나리오 사실 표와 대조한다. 결과 화면에 단순 목록만 있고 처리 결과나 다음 행동을 읽을 수 없으면 닫힌 과업으로 세지 않는다. 오류·확인·빈 상태는 A1 업무 규칙과 실제 조작에서 파생해 필요한 만큼 만들고, 정해진 개수만 채워 생략하지 않는다.

## 제작과 제시

브라우저에서 열 수 있는 HTML/앱 프리뷰 또는 동등한 실행물을 만든다. 화면별 상태를 한 상태 모델로 연결하고, 클릭·탭·스크롤·키보드가 같은 상태를 바꾸게 한다. 스크롤 위치와 포커스가 화면 전환·뒤로가기·대화상자 닫기에서 어떻게 복구되는지 정한다. 후보 모션의 정적/절제/표현적 비교는 같은 콘텐츠와 흐름을 유지하고 모션 축만 바꾼다. 모션을 사용하지 않는 방향도 같은 프로토타입에서 정적 피드백을 보여준다.

사용자에게는 **직접 열어 조작할 링크**와 3~6단계의 짧은 시연 경로를 준다. 어떤 조작과 분기가 실제 동작하는지, 데모 데이터와 미구현 범위가 무엇인지 적는다. 사용자가 직접 눌러 보거나 시연을 본 뒤 대상·강도·느낌을 확정한다. 침묵이나 검사기 PASS를 승인으로 기록하지 않는다.

모션을 비교하는 D 화면에는 기기의 `움직임 줄이기` 감지 상태와 현재 시연 모드를 표시한다. 시스템 설정은 제품 동작에 그대로 적용하되, 검토 화면에는 **검토용으로만 설정을 무시하고 재생하는 조작**과 여러 대상의 자동 시연을 둔다. 정적/절제/표현적 변경은 같은 문서·같은 상태에서 적용하여 iframe 재로드나 빈 화면 없이 비교한다. 모션 감소 켜짐/꺼짐 양쪽 환경에서 상태 표시, 정적 결과, 검토용 재생을 실제로 확인한다.

## 제시 전 검증

실제 브라우저/앱에서 대표 경로를 처음부터 끝까지 손으로 실행한다. 스크롤·버튼·화면 전환·뒤로가기·분기·오류 복구가 예상한 화면과 상태를 내는지 확인하고 캡처나 실행 기록을 남긴다. 키보드와 터치 판형, 모션 감소, 빠른 재입력, 긴 문구와 포화 데이터를 다시 본다. 연결이 끊긴 화면, 동작하지 않는 주요 버튼, 화면 밖에서만 재생되는 모션이 있으면 D를 제시하기 전에 수정한다. [프로토타입 기록 검사기](../scripts/check_prototype_contract.py)는 기록 누락을 경고하며 실제 동작 품질은 직접 확인한다.

각 경로의 조작 직후와 시트·메뉴·확장·입력 키보드가 열린 상태에는 [동작 중 콘텐츠·행동 밀도 검수](runtime-content-and-actions.md)를 실행한다. 필수 정보·값·단위와 주 행동의 의미가 잘리는지, 한 줄 조작이 서로 경쟁하거나 겹치는지, 보조 정보의 원문과 끝 행에 도달하는지 실제 스크롤·포커스·캡처로 확인한다. 정적 첫 화면의 PASS를 열린 상태나 포화 자료에 전파하지 않는다.

모션이 있는 대표 과업은 화면 한 장의 캡처만 남기지 않고 **트리거부터 완료·취소·뒤로가기까지 연속 화면 녹화**한다. 정상 속도로 한 번 보며 조작 감각과 지연을 판단하고, 프레임 단위로 다시 보며 시작/끝 튐, 빈 프레임, 잘못된 테마·색 한 프레임, 손가락과 분리된 이동, 키보드·시트 중간 끊김을 찾는다. 웹은 실제 지원 브라우저에서, 앱은 지원 기기의 시뮬레이터 또는 실기기에서 녹화한다. 정지 캡처와 연속 영상의 검사 결과를 별도로 기록한다.

화면 사이 이동에는 앞으로/뒤로의 방향과 공유 대상을 명세한다. 새 문서·라우트·테마를 여는 동안 본문을 숨겨 깜빡임을 가리지 않는다. 초기 테마·기본 글꼴·필수 스타일은 첫 프레임에 적용하고, 전환 기능이 없는 환경에서는 즉시 완성된 다음 화면을 보여준다. **진입 직후 25ms 간격의 프레임**에서 빈 본문·스타일 없는 본문·의도하지 않은 등장 재생이 0건인지 확인한다. 첫 방문의 등장 연출과 이후 화면 이동의 전환 연출을 구분한다.

모션은 [자연스러운 모션의 화면·흐름 계약](natural-motion.md)에 따라 첫 입력 반응, 처리 완료, 중간 재입력·역전, 빠른 연속 조작, 전체 화면의 움직임 밀도를 실제 프로토타입에서 각각 시험한다. 사용자가 보는 피드백과 진짜 상태가 어긋나면 효과가 매끄러워도 FAIL이다.
