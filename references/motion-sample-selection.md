# 모션 예시와 중복 판정 계약

## 분류와 동작을 분리

상위 그룹은 **찾기 위한 색인**이다. 그룹 이름이나 원본 계열 ID는 시연에 쓸 컴포넌트를 결정하지 않는다. 같은 그룹의 모션도 대상과 변화가 다르면 서로 다른 장면을 쓴다. 같은 컴포넌트를 쓸 수 있는 경우에도 그 컴포넌트가 해당 움직임의 핵심을 충분히 드러내는지 따로 검증한다.

모션마다 다음을 먼저 선언한다.

1. **핵심 변화:** 위치, 형태, 색, 경계, 깊이, 시간, 값, 관계 중 실제로 바뀌는 것.
2. **최적 예시 대상:** 변화가 가장 명확하게 드러나는 실제 객체와 상태. 예: 라인 드로는 화살촉이 따라가는 그래프 선, 라이트 스윕은 하이라이트가 지나는 로고 표면, 셰이프 모프는 같은 도형의 네모→원 변화.
3. **동작 단계:** 시작 상태, 트리거, 첫 변화, 경로·방향·축, 결정적 중간 변화, 종료 상태, 반복·역전. 시각적으로 구별되는 장면을 직접 본다.
4. **재생 조건:** 실제 시간, 이징, 반복·중단·재시작, 움직임 감소, 정지 상태의 의미. 동작 관계 판정과 별도로 기록한다.
5. **근거:** 원본 시연을 직접 본 시점과 캡처, 원본의 제작 문장, 내부 결과의 같은 시점 캡처.

샘플은 모션 이름의 뜻을 설명해야 한다. 화면 전환에 선 그리기를 얹거나 버튼 팝으로 숫자 회전을 대신하는 등, **동작 대상이 잘못된 예시**는 애니메이션이 재생돼도 FAIL이다. 강도를 무조건 키우지 말고 필요한 구간을 충분한 시간과 크기로 보여준다. 색·배경·초점 때문에 변화를 알아보기 어렵거나 중간 프레임이 화면 밖에 있으면 FAIL이다.

## 이름 중복과 구현 중복을 따로 판정

| 판정 | 의미 | 처리 |
| --- | --- | --- |
| 동일 개념의 별칭 | 이름만 다르고 대상·변화 순서·시각 결과가 사실상 같음 | 대표 용어 하나에 별칭으로 연결. 카탈로그에서는 검색 가능하게 유지 |
| 같은 원리의 맥락 변형 | 핵심 움직임은 같지만 적용 대상·목적이 다름 | 대표 원리 아래 변형으로 연결하고 예시 대상은 맥락에 맞게 고름 |
| 스타일·강도 변형 | 대상·상태·변화 축·사건 순서·결정적 중간 장면은 같고 색·재질·그림자·R·거리·시간·이징만 다름 | 새 고유 모션으로 세지 않고 같은 원리의 토큰/파라미터 변형으로 연결. 실제 시연에서 차이가 유의미한지는 별도 확인 |
| 다른 모션 | 대상·변화 순서·궤적·종료 중 의미 있는 차이가 있음 | 별도 모션으로 유지하고 시연으로 차이를 증명 |
| 구현 중복 오류 | 실제 뜻은 다른데 현재 렌더러가 같은 키프레임·장면을 사용 | FAIL. 이름을 합치지 않고 각각 재구현 |
| 판단 보류 | 원본 시연이나 비교 근거가 부족 | 미검증으로 남기고 대표 용어로 임의 병합하지 않음 |

키프레임 문자열이 같다고 의미상 같은 모션이라고 판정하지 않는다. 반대로 파라미터만 다르게 만들어 키프레임 검사에서 구별되더라도 시각 결과가 같으면 구현 중복이다. **원본과 내부의 시작·중간·끝 프레임을 실제 표시 크기로 함께 보고** 판단한다.

**동작 관계 판정표:** 원본 두 항목의 (1) 움직이는 대상, (2) 시작·종료 상태, (3) 변화 속성·방향·궤적, (4) 사건의 순서, (5) 결정적인 중간 장면, (6) 반복·역전 여부를 나란히 적는다. 공통 동작, 맥락 변형, 조합, 다른 동작 중 하나로 판정하고 각 항목의 실제 원본 화면을 근거로 붙인다. 이 여섯 항목 중 관계를 뒤집을 수 있는 장면을 못 봤으면 잠정이다. 속도·주기·이징은 **별도의 시간 판정**으로 남긴다. 두 원본의 동작 관계가 PASS여도 각각의 내부 재현은 별도 PASS가 필요하다.

## 항목별 검수 기록

`motionId`, `canonicalMotionId`, `aliasOrVariant`, `sampleTarget`, `sampleReason`, `referenceObserved`, `referenceFrames`, `internalFrames`, `motionVisible`, `sampleSuitable`, `semanticMatch`, `keyboard/reducedMotion`, `reviewerNote`를 기록한다. **원본 URL·확인 시각·데모 코드/버전 식별값·실제로 관찰한 동작 단계·원본과 내부의 대응 장면**을 근거에 포함한다. 시간·주기·이징의 관찰값과 미확인 상태는 별도 필드로 기록한다. 원본 페이지의 제작 문구, 내부에서 만든 시연끼리의 비교, 결정적 변화 장면이 없는 몇 장의 화면만으로 원본 일치나 중복 판정을 PASS로 만들지 않는다. 자동으로 채울 수 없는 세 판정(`motionVisible`, `sampleSuitable`, `semanticMatch`)은 직접 화면을 보고 PASS/FAIL/NOT_RUN으로 남긴다. 이 세 판정이 PASS가 되기 전에는 해당 항목을 구현 완료로 표시하지 않는다.
