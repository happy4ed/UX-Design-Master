# 앱 화면 패턴과 플랫폼 적용

[73개 모바일 패턴](../knowledge/mobile-patterns.json)은 화면 구조, 탐색, 목록, 입력, 행동, 피드백, 미디어, 기기 상태의 **역할 목록**이다. 이름만 맞춰 배치하지 말고 실제 상태 변화와 탐색 결과를 먼저 쓴다. [플랫폼 연결 후보](../knowledge/mobile-platform-bindings.json)는 SwiftUI, Flutter, React Native에서 시작할 수 있는 API 이름이며 프로젝트의 버전과 플랫폼을 확인한 뒤 사용한다. 이 스킬은 해당 라이브러리를 설치하거나 외부 스킬을 호출하지 않는다.

기본 앱의 실제 화면 구성을 비교할 때 [iOS 27 · One UI 9 화면 추출](mobile-app-study.md)을 본다. 화면 캡처를 먼저 의미·역할·상태로 읽고, 그다음 구조·색을 추출한다. 캡처의 데이터색과 테마색을 플랫폼 공식 토큰으로 오인하지 않는다.

## 화면 계약

1. `화면 목적 → 진입 경로 → 주 행동 → 보조 행동 → 뒤로/닫기 결과`를 쓴다. 전역 탭, 화면 안의 탭, 선택용 세그먼트, 켜고 끄는 스위치를 구별한다.
2. 상단 바, 본문 스크롤, 하단 행동, 키보드, 시트의 공간 소유자를 정한다. 안전 영역과 화면 회전, 작은 높이에서도 주 행동이 가려지지 않아야 한다.
3. 각 조작 요소는 시각적 외곽과 **실제 터치 영역**을 따로 기록한다. iOS/iPadOS는 기본 목표 44×44pt, Android는 최소 권장 48×48dp로 점검한다. 아이콘이 더 작아도 터치 영역을 확장할 수 있다. 서로 이웃한 대상은 영역이 겹치지 않게 한다.
4. 목록 행 전체가 눌리는지, 행 안에 별도 행동이 있는지 명확히 한다. 스와이프와 길게 누르기에 숨긴 행동은 발견 가능한 대체 경로를 제공한다.
5. 초기/콘텐츠 포화, 오프라인/오류, 권한 거부, 키보드 표시, 큰 글씨, 긴 번역, RTL을 같은 화면 계약으로 검수한다. 상태 전환은 이전 화면의 스크롤·선택·미저장 내용을 보존하거나 버리는 규칙을 정한다.
6. 진입·전환마다 **더 깊이 들어감 / 동급 목적지 이동 / 짧은 선택 / 독립 과업 / 되돌릴 수 없는 완료** 중 역할을 정하고 `뒤로·닫기·취소 후 어디로 가는가`를 적는다. 완료 후 이미 끝난 로그인·결제·온보딩 화면이 뒤로가기로 다시 나오면 안 된다. 반대로 잠깐 로그인·권한 확인을 거친 행동은 원래 과업과 위치로 돌아와 이어져야 한다. 화면 전환 API 이름은 이 의미 계약을 정한 뒤 플랫폼과 프로젝트 버전에 맞춰 선택한다.

## 패턴 검색과 선택

`python3 scripts/query_mobile.py --term 검색` 또는 `--family navigation`으로 역할 후보를 찾는다. `--platform swiftui|flutter|reactNative`를 붙이면 연결 후보도 함께 출력한다. 목록에 없는 복합 요소는 기존 패턴의 조합인지 먼저 확인하고, 실제 새 역할이면 `new-candidate`로 기록해 전체 화면의 공통/전용 사용 맵에 추가한다.

패턴을 선택한 뒤에는 `역할, 상태, 데이터 길이, 터치 영역, 안전 영역, 접근성 라벨, 애니메이션 필요성, 정적 피드백, 플랫폼 차이`를 남긴다. API 매핑이 없다는 이유만으로 화면 역할을 바꾸지 않는다.
