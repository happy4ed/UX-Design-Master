# 참고 화면 측정·치수 도면

## 입력과 목표부터 확인

분석 / 개선 / 정밀 재현을 구분한다. 플랫폼·OS 버전·앱 버전·기기·화면 상태·출처를 먼저 확인한다. 공개 여부가 확인되지 않은 버전의 화면을 다른 버전·콘셉트 이미지로 대체해 라벨 붙이지 않는다. 독립적으로 가능한 분석을 진행하며 대상 확인을 요청한다.

## 측정 전에 의미 구조를 확정

[화면 의미·역할 정의](semantic-design.md)에 따라 화면 내용을 먼저 읽고 목적·현재 상태·영역·각 요소의 역할 후보와 제어 관계를 작성한다. 형태를 보고 바로 tab/button/toggle로 이름 붙이지 않는다. 의미 역할·형태·구현 후보를 분리한다. 정적 자료의 미확인 동작은 후보로 유지하고 확인 방법을 남긴 뒤 측정한다. 최종 분석은 이 의미 구조를 치수 표보다 먼저 제시한다.

## 세 가지 측정 층

| 층 | 근거 | 한계 |
| --- | --- | --- |
| 선언·원본 | 디자인 변수·프로젝트 토큰·원본 속성 | 실제 로딩·배치·시각 결과의 보장은 아님 |
| 계산·기하 | computed style, bounding rect, 실제 렌더 조건 | 글리프의 보이는 외곽·블러·마스크·캔버스 내용을 모두 설명하지 못함 |
| 렌더·시각 | 화면 픽셀·부분 확대·영상 | 내부 CSS·논리 단위·숨겨진 상태는 역으로 확정할 수 없음 |

코드·DOM이 있으면 선언/계산/렌더를 연결한다. 스크린샷만 있으면 이미지 좌표·비율과 불확실성을 기록한다. px·CSS px·pt·dp를 혼용하지 않는다. DPR·줌·리사이즈·크롭·폰트 로딩·기기 프레임·원근을 확인한다. 마케팅 합성 이미지는 native screenshot과 구분한다. 여러 이미지를 같은 논리 폭으로 임의 환산한 값을 실제 기기 규격으로 제시하지 않는다.

각 값은 `value / unit / source / method / uncertainty / scope`를 가진다. 관찰·측정·추정·미확인을 구별하고 모르면 TBD로 둔다. 기존 값이 15px로 보인다는 이유로 몰래 16px에 스냅하지 않는다. 정형화 제안은 관찰값과 분리한다.

## 전체 화면의 그리드·영역·계층

[구조 추출과 반복 실험](screen-structure-lab.md)에 따라 의미 분석 후 가상 정렬선을 만든다. 실제 디자인 시스템 자료가 없으면 관찰 기반 가설로 표시한다. 전체 화면과 로컬 그리드를 나누고 각 영역의 역할·계층·카탈로그 항목·구성 값·원본 좌표를 연결한다. 카탈로그 누락은 신규 primitive라는 증거가 아니며 기존/변형/합성/미확인/신규 후보 순서로 판별한다.

## 화면→컴포넌트→규칙

1. 같은 화면의 다른 상태를 먼저 묶는다. 화면·상태 ID와 관찰 범위를 정한다.
2. 레이아웃·탐색·영역·반복 행·컨트롤을 anatomy와 슬롯으로 분해한다.
3. 여러 인스턴스의 공통 기준선·열·inset·gap·R·색·폰트·상태 차이를 비교한다.
4. 측정 샘플에서 규칙 가설을 만든다. 한 샘플의 크기를 전체 시스템 토큰이나 최대 줄 수로 확정하지 않는다.
5. 다른 콘텐츠·폭·상태 관찰로 규칙을 지지/반박한다. 없는 상태는 관찰 누락으로 남기고, 새 제안임을 밝히지 않은 채 복원하지 않는다.

브라우저에서는 fonts.ready·실자산·동적 로딩을 확인하고 before/after 상태에서 같은 측정 함수를 사용한다. 페이지 전체 computed-style 덤프만으로 시스템을 정의하지 않는다. 표본 컴포넌트의 실제 사용 조건과 선언 규칙을 비교한다.

## 치수 도면 산출물

치수 도면은 관찰값·추정값·설계 채택값을 분리하는 내부 출력 규칙을 따른다. 외부 도면 생성 스킬이나 drawing kit를 실행 의존성으로 연결하지 않는다.

- 실제 참고 화면과 모노크롬 구조 도면을 함께 보여준다. 실제 화면의 색·폰트 분석은 별도 유지한다.
- S=spacing, R=radius, H=height, W=width, I=icon 같은 코드와 실제 토큰·출처를 연결한다. 프로젝트 기존 명칭이 있으면 매핑한다.
- HUG/FLEX/FILL 또는 intrinsic/flex/fill로 내용에 맞춤·잔여 공간·부모 채움을 설명한다. 크기 모드와 위치 모드를 별도 표시한다.
- 정면도에 공유 기준선·치수 체인, 필요한 부분에 확대 상세도·레이어 분해도·viewport 배치를 표시한다.
- 모든 치수 코드가 표에 존재하고 수식이 닫히는지 검증한다. R_inner=R_outer−border−inset은 실제 동심원 구조에만 적용하고 0 이하·비동심 구조를 별도 처리한다.
- 그림자 영역·시각 외곽·클릭 영역을 서로 구별한다. 도면상의 분해 순서를 실제 z-index 증거로 오인하지 않는다.
- 실제 콘텐츠·말줄임·두 경계 조건은 [컴포넌트 계약](component-contract.md)에 연결한다. 슬롯 도면만으로 데이터 검증을 대체하지 않는다.
- 대표 패밀리와 복잡한 배치부터 도면화한다. 단순 변형마다 거대한 시트를 만들지 않는다.

## 분석용 HTML

출처 화면 / 표시 가능한 분석 오버레이 / 컴포넌트 목록 / 치수·규칙 표 / 데이터·상태 계약 / 근거·미확인 항목을 연결한다. 선택한 컴포넌트를 원본 위치에서 강조할 수 있게 한다. 정적 화면에서 동작을 추정한 경우 이를 명확히 표시한다. 비교 조건을 맞추고 annotation을 꺼도 원본을 확인할 수 있어야 한다.

실제 UI 설계를 바꿀 권한 없이 분석만 요청받았다면 분석 산출물로 끝낸다. 검증하지 않은 정확한 폰트·네이티브 단위·애니메이션 시간·전체 플랫폼 규칙을 선언하지 않는다.
