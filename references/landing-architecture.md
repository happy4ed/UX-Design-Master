# 랜딩·상세 페이지 구조 판단

랜딩 요청에는 먼저 방문자가 **무엇을 알고, 믿고, 결정하고, 할지**를 적는다. [섹션 후보 35종](../knowledge/landing-sections.json)은 이 네 단계와 탐색·상세 정보에 연결된 구조 지식이다. 섹션의 외형이나 색을 자동으로 고르는 템플릿이 아니다. 이름이 같은 섹션이라도 앱 설치, SaaS 가입, 동네 가게 방문, 상품 구매에 필요한 증거와 다음 행동은 다르다.

## 선택 순서

1. 페이지의 주 행동 하나와 보조 행동을 정한다. 실제 사용할 수 있는 화면·사진·가격·후기·수치·정책을 증거 목록으로 만든다.
2. [랜딩 선택기](../scripts/plan_landing.py)에서 업종별 초기 후보를 만들 수 있다. 증거가 없는 섹션은 `heldForEvidence`로 나오며 허구의 숫자·로고·후기로 채우지 않는다.
3. 방문자가 아직 모르는 것이 무엇인지에 따라 순서를 조정한다. 기능이 복잡하면 작동 순서를 먼저, 신뢰가 약하면 검증 가능한 사례를 먼저, 구매 제약이 크면 가격·반품·자격 조건을 행동 전에 보여준다.
4. **같은 내용의 와이어프레임 3안**을 만든다. 화면 위계·증거 위치·행동까지의 길이가 실제로 달라야 한다. 색과 폰트만 바꾼 안은 구조 대안이 아니다.
5. 화면에 들어가는 실제 길이의 문구·실물 화면·데이터로 초기/포화 조건을 검수한다. 제품 이미지가 없으면 자리와 필요한 촬영/캡처 조건을 명시한다.

## 세부 페이지의 판 리듬

제품 상세는 `주장 → 실물 → 사용 조건 → 제약 → 행동`의 읽기 경로를 유지한다. 연달아 놓인 섹션이 모두 같은 카드 그리드, 같은 높이, 같은 정렬이면 정보의 차이가 보이지 않는다. 섹션마다 **무엇을 판단하게 하는지**에 따라 문자 중심·실물 중심·표·단계·전체 폭 시연 등을 선택한다. 시각적 변화 자체를 목적으로 판을 번갈아 놓지 않는다. 섹션의 배경색을 바꿀 때는 내용 집단이 실제로 바뀌는 지점과 맞춘다.

## 컴포넌트 및 모션 연결

- 주 행동은 버튼, 보조 탐색은 링크로 명확히 분리한다. CTA가 반복되더라도 라벨과 결과가 일치해야 한다.
- 로고, 평점, 후기, 수치의 출처·기간·사용 허락을 확인한다. 없다면 적합한 다른 증거를 쓰거나 그 섹션을 보류한다.
- 실제 제품 화면을 쓰는 경우 캡처 상태·데이터의 진위·크롭을 확인한다. 아직 없는 화면을 실물처럼 꾸미지 않는다.
- 모션은 `무엇이 바뀌는지`를 보여줄 때 선택한다. 히어로에 자동 반복을 넣기 전에 정지 화면만으로 약속이 읽히는지 본다. 사용자가 선택한 모션 강도와 감소 설정을 따른다.
- 모바일에서는 접힌 순서가 논증 순서가 된다. 데스크톱의 좌우 열이 모바일에서 어떤 순서로 쌓이는지 와이어프레임에서 확정한다.

## 실행 예

```bash
python3 scripts/plan_landing.py --kind saas --evidence specific-outcome real-product-visual feature-list workflow pricing real-questions conversion-action
```

결과의 `heldForEvidence`는 누락 증거이며 검증 통과가 아니다. 페이지 구성은 기능 구조 A1·흐름 A2·화면 분할 A3, 와이어프레임 확인 B, 시각 방향 확인 C를 따른다.
