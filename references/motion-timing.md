# 모션 시간과 검토 속도

동작 시간은 효과 이름이 아니라 **입력 반응, 이동 거리, 화면 점유율, 정보량**으로 정한다. 작은 상태 변화는 빠르게, 화면을 크게 가로지르는 공간 이동은 길게 둔다. 같은 화면에서도 공간 이동과 색·불투명도 변화는 다른 시간 토큰을 쓸 수 있다. 스프링은 고정된 `duration`만으로 설명하지 말고 강성·감쇠·초기 속도와 실제 정착 시간을 기록한다.

## 제품 시안의 시간 결정

시간을 역할 이름만으로 고정하지 않는다. 아래 기준으로 대상 프로젝트의 시작값을 제안하고, 실제 콘텐츠·이동 거리·기기·사용 빈도에서 측정한 뒤 확정한다. 입력 직후 피드백은 즉시 시작해야 하며, 시간이 길어질수록 사용자가 다음 조작을 기다리는지 실제 기기에서 본다.

| 역할 | 시간 결정 기준 | 검토 기준 |
| --- | --- | --- |
| 버튼 눌림·토글·체크 | 작은 상태 변화와 반복 조작 빈도 | 입력 즉시 상태가 바뀌고, 작은 이동이 길게 끌리지 않는가 |
| 탭 지시선·메뉴·작은 내용 교체 | 이전·다음 항목의 거리와 정보량 | 항목 사이의 관계가 보이는가 |
| 목록 삽입·삭제·정렬 | 이동 거리·항목 수·재정렬 빈도 | 항목의 이전 위치를 추적할 수 있는가 |
| 시트·대화상자·부분 화면 이동 | 레이어 이동 거리와 내용 밀도 | 레이어가 어디서 왔는지 읽히는가 |
| 전체 화면 전환·큰 공간 이동 | 이동 범위·방향·과업 속도 | 이동 거리에 맞고, 작업 속도를 방해하지 않는가 |
| 데이터·도식·설명 순차 공개 | 단계 수·값의 변화·읽는 시간 | 값과 단계가 읽히는가. 실제 작업 진행은 작업 상태에 연동하는가 |

같은 역할이라도 이동 거리·밀도·디바이스·반복 빈도에 따라 조정한다. 앱의 생산성 흐름과 한 번 보는 설명 장면의 적절한 속도는 다르다. 이징이 시작에 변화를 몰아주면 전체 시간이 길어도 빠르게 느껴지므로 **첫 절반의 이동량과 정착 시간**을 중간 프레임에서 확인한다. 사용자에게 느리다는 의견을 받으면 `duration`과 이징·스태거 간격·완료 상태 유지 시간을 함께 조정한다.

## 시연·검토 모드

제품 시간과 시연 배율은 별개다. 기존 One UI 9 스타일 실험실의 `1×`는 임의 레시피 시간(예: 시트 360ms)을 그대로 실행한 값이었다. **삼성 공식 One UI 9의 1× 시간이라는 근거가 없으므로 제품 체감이라는 표기를 제거한다.** 이 실험실의 새 `1×`는 관찰용으로 원본 레시피 시간을 2.2배 늘린 속도다. 기본 `0.7×`에서 원본 시간은 약 3.14배가 된다. `2.2×`를 누르면 원본 레시피 시간으로 비교할 수 있다. 이는 해당 실험실의 설정값이며 다른 제품이나 시연의 기본값이 아니다. 시연의 끝 상태는 사용자가 읽고 비교할 수 있을 만큼 유지하고 자동 반복 주기와 모션 본체 시간을 따로 기록한다. 시연 시간을 제품 코드에 그대로 복사하지 않는다.

One UI 스타일 실제 제품 시안을 만들 때는 [삼성 One UI 모션 가이드](https://developer.samsung.com/one-ui/motion/basic.html)의 수치와 이동 크기·변화량·이징을 **해당 플랫폼 참고자료**로 검토한다. 이 공개 가이드는 특정 One UI 9 화면의 실측값이 아니므로 실제 제품 화면에서 별도 관찰이 필요하다. 플랫폼의 수치를 다른 앱·웹·문서의 공통값으로 이식하지 않는다.

검수 기록에는 `원본 시간 / 시연 배율 / 실제 재생 시간 / 이징 / 스태거 지연 / 끝 상태 유지 / 중단·재입력`을 적는다. 처음·중간·끝 프레임을 실제 화면에서 본다. 모션 감소에서는 핵심 상태가 정적으로 전달되는지 따로 검사한다.

## 근거와 적용 범위

- [Material 3 모션 물리 시스템](https://m3.material.io/styles/motion/overview/how-it-works): 작은 요소는 fast, 부분 화면은 default, 전체 화면은 slow. 공간 이동과 효과를 나누고 스프링의 강성·감쇠·초기 속도로 동작을 설명한다.
- [삼성 One UI 모션](https://developer.samsung.com/one-ui/motion/basic.html): 화면 깊이와 전후 관계를 설명하고, 100–500ms 범위와 기본 보간 곡선 `[0.22, 0.25, 0.00, 1.00]`을 제시한다. 공개 일반 가이드이며 One UI 9 특정 수치로 단정하지 않는다.
- [Carbon 모션 가이드](https://v10.carbondesignsystem.com/guidelines/motion/overview/): 이동 거리·크기가 커지면 시간을 늘리는 원칙과 70/110/150/240/400/700ms 토큰을 제시한다. 이 값은 Carbon의 토큰이며 위 표의 숫자를 직접 규정하지 않는다.
- [Fluent 2 모션](https://fluent2.microsoft.design/motion): 사용자가 변화를 알아보고 해석할 시간을 주는 것을 강조한다.
- [Apple UI 반응성](https://developer.apple.com/documentation/xcode/understanding-user-interface-responsiveness): 입력과 화면 반응의 지연, 연속 제스처의 유동성을 함께 본다.
