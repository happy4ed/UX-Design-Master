# 문서 디자인: 읽기 구조와 페이지 계약

보고서, 제안서, 가이드, 매뉴얼, 리서치 문서, 양식, 편집형 콘텐츠처럼 **읽고 찾고 이해하거나 작성하는 자료**에 적용한다. 앱 화면처럼 모든 항목을 조작 컴포넌트로 취급하지 않는다. 슬라이드·PPT 변환, 워드 프로세서 자동화, 인쇄소 제출용 파일 변환은 이 스킬의 핵심 능력이 아니라 선택한 결과물 형식에 연결할 별도 도구다.

발표용 PPT·키노트·슬라이드 PDF라면 이 문서의 근거·텍스트·출처·페이지 규칙과 함께 [발표 자료 디자인](presentation-design.md)을 적용한다. 발표 슬라이드의 정보 밀도와 시간 순서, 발표자 노트와 배포본의 경계는 일반 보고서의 페이지 규칙만으로 판단하지 않는다. 문서 본문의 그림을 독립 인포그래픽으로 재사용할 때는 [다이어그램·인포그래픽 설계](diagram-infographic.md)의 전체 주장·부분 도표 계보·매체별 재배치 계약을 추가한다.

## A: 내용과 독자의 계약

원문·근거 자료를 읽고 문서의 목적, 독자, 읽는 맥락(화면·인쇄·발표 보조), 핵심 주장/과업, 필요한 행동, 유지해야 할 표현과 출처를 정리한다. 아직 없는 데이터·인용·도표를 그럴듯하게 채우지 않는다. 내용 작성·편집이 요청되었는지, 제공 원문을 보존해야 하는지도 구분한다.

주장/질문 → 근거·데이터 → 결론/행동의 순서와 제목 계층, 목차·검색·교차 참조를 연결한다. 문서 유형에 따라 독자가 처음부터 읽는지, 필요한 항목을 찾는지, 비교·검토하는지를 표시한다. 키 프레임에 해당하는 문서 단위는 표지, 요약, 본문 대표면, 데이터/표 중심면, 결론, 부록처럼 **구성 원칙이 달라지는 대표 페이지·스프레드**다. 모든 페이지를 개별 유형으로 늘리지 않는다.

반복 요소는 전체 사용 맵에서 소유 범위를 정의한다: 문서 공통(그리드·본문·쪽번호), 장/절 공통(제목·러닝 헤더), 유형 전용(사례 카드·법적 고지), 한 페이지 전용(특정 그림). 비슷한 상자를 모두 카드로 묶지 않는다.

## 의미 요소 목록과 계약

먼저 의미 역할을 정하고 시각 처리와 구현 요소를 뒤에 붙인다. 아래는 시작 목록이며 한 페이지에 모두 넣는 체크리스트가 아니다.

| 요소 집단 | 후보 | 계약에서 확인할 것 |
| --- | --- | --- |
| 구조 | 표지, 장/절, 목차, 요약, 부록, 참고문헌 | 독자 경로·제목 수준·진입점·반복 여부 |
| 본문 | 리드, 단락, 목록, 인용, 강조문, 각주/미주 | 행 길이·줄높이·들여쓰기·문단 간격·출처 |
| 근거 | 도표, 그림, 사진, 캡션, 표, 주석, 범례 | 원본 데이터·단위·번호·본문 참조·대체 설명 |
| 안내 | 러닝 헤더/푸터, 쪽번호, 교차 참조, 링크 | 페이지와 장의 관계·읽기 순서·인쇄/디지털 차이 |
| 행동 | 입력란, 체크 영역, 서명, 검토 메모, CTA | 작성/제출 주체·상태·인쇄 가능성·조작 영역 |

관계·수치·과정을 시각화하는 그림은 [다이어그램·인포그래픽 설계](diagram-infographic.md)의 의미 유형·데이터 계약을 따른다. 표보다 그림이 더 명확한지 먼저 비교한다.

각 요소는 역할, 내용 출처, 최대 길이와 줄바꿈, 선택/반복 조건, 부모 페이지 슬롯, 인접 간격, 스타일 토큰, 페이지 넘김 정책을 가진다. 표는 열 너비·숫자 정렬·헤더 반복·긴 셀·단위·출처, 그림은 종횡비·크롭·캡션과 함께 이동/분리 가능 여부를 정의한다. 각주와 교차 참조는 실제 대상에 연결한다.

제목·본문·인용·표 셀·캡션도 [텍스트 영역 계약](text-layout-qa.md)을 따른다. 내용이 늘어날 때 슬롯 높이를 늘리고 뒤 블록을 밀지, 컬럼·페이지를 나눌지, 도형이나 여백을 조정할지 먼저 정한다. 한두 줄이 더 필요하다는 이유로 전체 글자 크기를 일괄 축소하지 않는다. 곡선·테두리·회전 문구를 쓰는 경우 경로 길이와 읽기 방향, 실제 인쇄 크기를 검사한다.

## B: GUI 이전의 구조 비교

새 문서나 큰 개편은 같은 목적·실제 콘텐츠 표본으로 **구조적으로 다른 저충실도 와이어프레임 3개 이상**을 만든다. 장 순서·요약 위치·페이지 그리드·본문/근거의 관계·탐색 방식 중 의미 있는 차이를 둔다. 색과 폰트만 바꾼 판은 구조 대안이 아니다. 각 안에 대표 표지/요약/본문/데이터 중심면 중 필요한 유형을 포함하고 장점·손해·권장안을 함께 보여 확인받는다.

두 콘텐츠 경계를 같은 규칙으로 시험한다: `Initial`은 실제 최소 분량·짧은 제목·소수 항목, `Saturated`는 현실적인 긴 제목·밀집 표/그림·긴 각주·많은 항목이다. 총 페이지가 늘어나는 상황까지 생각하되 모든 변수를 동시에 극단으로 몰아 가짜 실패를 만들지 않는다. 디지털 문서라면 지원 폭과 확대, 인쇄 문서라면 지정 판형과 여백을 고정해 비교한다.

## C: 시각 시스템

확인된 구조 위에서 타이포그래피, 페이지 그리드, 컬럼, 여백, baseline·들여쓰기, 제목 간격, 표/그림 문법, 색과 강조, 장치별 변형을 선택한다. `페이지 → 섹션 → 블록 → 행/그림`의 소유 관계를 먼저 정하고 margin·padding·gap 중 어디서 공간이 생기는지 기록한다. 본문 행 길이와 한글/영문 혼합 줄바꿈, 제목의 행 걸림, 캡션과 대상의 거리, 표의 스캔 방향을 실제 크기로 확인한다.

시각 방향은 같은 대표 페이지와 같은 콘텐츠로 비교한다. 레퍼런스의 페이지 질서·계층·타입 대비를 가져올 수 있으나 도표나 인용의 의미를 스타일 때문에 바꾸지 않는다. 스타일 샘플을 문서 템플릿으로 그대로 복사하지 않는다.

## 페이지 넘김과 렌더 검수

- 표제만 페이지 끝에 남거나 단락 첫/마지막 한 줄만 분리되는 현상, 캡션과 그림·표의 분리, 표 헤더의 반복 실패를 확인한다.
- 페이지 번호·목차·교차 참조·각주 번호·그림/표 번호를 실제 페이지와 대조한다.
- 표의 열 붕괴, 숫자/단위의 정렬, 긴 URL/코드/한글 혼합 행의 넘침을 확인한다.
- 실제 출력·화면 크기에서 읽기 순서, 대비, 링크 구별, 필요한 대체 설명, 인쇄 시 색 손실을 확인한다.
- 원문·근거와 최종 문서의 숫자·인용·표시 범위를 대조한다. 시각 품질만 보고 내용 정확성을 통과 처리하지 않는다.

최종 결과는 요청한 형식의 **디자인 원본, 렌더된 대표 페이지, 구조·토큰·반복 요소·페이지 규칙 명세**로 제시할 수 있다. 특정 파일 포맷으로 변환이 필요하면 별도 도구의 입력 제약과 검증 능력을 확인한 뒤 연결한다. 디자인 규칙과 변환기 요구사항을 혼동하지 않는다.
