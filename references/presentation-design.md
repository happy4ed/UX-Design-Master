# 발표 자료 디자인: 주장·증거·슬라이드 흐름

PPT, 키노트, 발표용 PDF, 화면 공유용 슬라이드의 **디자인 판단**에 적용한다. 파일을 만드는 도구의 형식이나 템플릿이 이 판단을 대신하지 않는다. 읽기용 보고서를 페이지마다 잘라 놓은 것을 발표 자료로 취급하지 않는다. 사용자가 문서형 슬라이드를 원하면 발표형보다 높은 정보 밀도를 허용하고 그 목적을 기록한다.

## A1 · 발표 과업과 증거 구조

브리프에 `청중 / 발표 상황·거리 / 발표 시간 / 발표자가 말할 내용과 화면에서 독자가 직접 읽어야 할 내용 / 발표 후 공유 여부 / 출력 형식 / 화면 비율 / 원본 자료`를 적는다. 빠진 도메인 수치나 인용을 만들지 않는다.

먼저 발표가 끝났을 때 청중이 기억하거나 결정해야 할 **핵심 질문과 결론**을 한 문장씩 쓴다. 그 결론을 지지할 주장, 원본 근거, 반론·제약, 요청 행동을 연결한다. 근거가 없는 주장은 표시하거나 빼고, 장식용 통계·고객 로고·인용을 채우지 않는다. 데이터가 많으면 발표 화면에는 판단에 필요한 부분을, 세부 표와 방법은 부록·배포본·발표자 노트에 배치할지 정한다. 부록으로 보냈어도 핵심 판단에 필요한 단위·분모·불확실성은 본 화면에 남긴다.

## A2 · 발표 흐름

도입 → 문제/맥락 → 근거 → 판단 또는 제안 → 결론/다음 행동의 실제 순서를 정한다. 이 순서는 고정 템플릿이 아니라, 청중이 이미 아는 것과 결정에 필요한 증거에 따라 바꿀 수 있다. 각 전환에서 `앞 장의 질문 → 다음 장의 답`이 이어지는지 확인한다. 같은 결론을 반복하는 장, 제목만 바뀐 같은 차트, 설명 없이는 인과로 오해되는 인접 장을 제거하거나 합친다.

발표형은 **한 장에서 청중이 따라갈 주된 판단**을 먼저 정한다. 복잡한 장은 한 장에 전부 집어넣기보다 단계 공개, 두 장으로 분리, 부록 이동, 설명 그림 재구성 중 하나를 선택한다. 단계 공개를 쓰더라도 모든 중간 상태와 정지 화면이 의미를 유지해야 한다. 애니메이션은 발표자가 조작하는 시점과 화면의 변화가 일치할 때만 쓴다. 자동 재생·영상 내보내기·PDF 정적 내보내기의 결과를 별도로 확인한다.

## A3 · 슬라이드 역할과 공통/전용 요소

구성 원칙이 다른 대표 슬라이드 역할을 정한다. 가능한 역할은 표지, 질문·전환, 근거, 정량 비교, 프로세스·시스템, 사례, 결정·권고, 요약, 부록이다. 모든 역할을 채울 필요는 없다. 슬라이드별로 아래 계약을 쓴다.

| 필드 | 확인할 내용 |
| --- | --- |
| 역할·목적 | 청중의 어떤 질문에 답하고 어떤 상태에서 다음 장으로 가는가 |
| 주장형 제목 | 장의 주된 판단. 모호한 주제어만 쓰려면 그 이유와 시각 근거를 적는다 |
| 핵심 근거 | 원본 수치·문장·그림의 출처, 날짜, 단위, 분모, 불확실성 |
| 화면과 발화 | 화면에서 직접 읽어야 할 것과 발표자 노트로 설명할 것의 경계 |
| 읽기 순서 | 제목, 증거, 설명, 출처, 다음 행동의 시각·접근성 순서 |
| 슬라이드 유형 | 문장, 사진, 표, 차트, 다이어그램, 인포그래픽 중 의미에 맞는 구성 |
| 재사용 범위 | 전체 슬라이드 공통 / 섹션 공통 / 역할 전용 / 한 장 전용 |
| 변형 | 발표 화면, PDF 배포, 인쇄 핸드아웃, 축소 썸네일에서 달라지는 배치 |

슬라이드 마스터에 넣을 반복 요소는 배경, 그리드, 제목 기준선, 페이지/섹션 표지, 출처·캡션 슬롯, 색·타입 토큰처럼 반복 근거가 있는 것만 둔다. 매 장에 불필요한 로고·테두리·카드를 강제하지 않는다. 같은 주장에 쓰이는 차트·표·인포그래픽은 [다이어그램·인포그래픽 설계](diagram-infographic.md)의 데이터 계약을 연결한다.

## B · 구조 와이어프레임 비교

신규 발표 자료와 큰 개편은 **같은 주장·자료·슬라이드 표본**으로 구조적으로 다른 와이어프레임 3개 이상을 비교한다. 차이는 주장과 근거의 위치, 한 장/두 장의 분할, 개요→상세 순서, 사진/표/그림의 역할, 설명 흐름처럼 내용 이해를 바꾸는 축이어야 한다. 색·폰트·장식만 다른 안은 구조 대안이 아니다. 발표자가 첫 30초에 설명할 때와 청중이 나중에 PDF만 읽을 때의 이해 차이를 함께 평가한다. 추천안과 다른 후보의 손해를 보여주고 사용자 확인 B를 받는다.

## C · 발표 환경의 시각 시스템

선택한 구조에 제목·본문·숫자·출처의 역할별 글자 크기와 줄높이, 그리드·안전 여백·정렬선, 색 역할, 이미지와 차트 문법을 적용한다. **실제 최종 표시 크기**에서 읽히는지를 우선한다. 무조건 큰 글자 한 줄로 밀어붙이지 않고, 발표 거리·화면 해상도·정보량과 자료 배포 여부를 기록해 크기를 선택한다. 작은 글자를 남겨야 할 경우 화면에서 꼭 필요한 근거인지, 부록이나 별도 표로 보낼지 먼저 판단한다. 폰트 크기는 소스 캔버스 수치가 아니라 투사/공유/인쇄된 결과의 판독성으로 검증한다.

정량 그림은 모든 장에서 축·단위·소수점·색 의미·범례·주석 위치를 같은 규칙으로 쓴다. 배경, 슬라이드 표면, 그래프 영역, 강조의 Z 층을 구분한다. 배경 이미지 위의 글자는 최악의 밝은/어두운 구간에서도 읽히는지 확인한다. 같은 색을 다른 의미로 재사용하거나 색만으로 항목을 구분하지 않는다. 발표형과 배포형은 같은 데이터와 주장으로 검증하되 필요하면 서로 다른 레이아웃을 쓴다.

## D · 전환과 단계 공개

모션 후보마다 `이해 목적 / 발표자 트리거 / 전·중·후 상태 / 변화하는 데이터와 고정 데이터 / 중단·건너뛰기 / PDF 정적 대안`을 적고 실제 조작 가능한 슬라이드 시안으로 보여준다. 단계 공개는 숨겨진 정보가 반론·단위·분모를 누락해 오해를 만들지 않는지 확인한다. 설명에 필요 없는 모든 장의 일괄 진입 모션은 쓰지 않는다. 확인 D에서 실제 슬라이드 이동과 단계 공개를 시연해 사용자와 확정한다.

## 최종 파일 검수

디자인 원본, PPTX 같은 편집 파일, PDF·이미지·영상의 납품 형식을 각각 **독립 결과물**로 취급한다. 생성 도구가 성공했다는 사실만으로 검수를 끝내지 않는다.

1. 전체 슬라이드를 실제 파일에서 열고 발표 화면 크기와 배포·인쇄 크기로 렌더한다. 글자 잘림, 자동 축소, 폰트 대체, 이미지·차트 품질, 캡션 분리, 마스터의 반복 일관성을 본다.
2. 첫 장부터 끝까지 실제 발표 순서로 넘겨 주장과 근거가 이어지는지 확인한다. 애니메이션·단계 공개는 실제 클릭, 자동 재생, PDF 내보내기에서 각각 다른 결과가 없는지 본다.
3. 읽기 순서와 제목, 정보성 그림의 대체 설명, 색 이외의 부호를 확인한다. 장식 요소는 읽기 경로에서 빼고, 표·차트의 자세한 값은 접근 가능한 표/노트 또는 배포본으로 연결한다.
4. 출처, 표/차트 값·단위·분모, 발표자 노트, 숨긴 장, 링크, 페이지 번호와 최종 파일의 장 수를 원본과 대조한다.
5. `PASS / FAIL / NOT_RUN / NOT_APPLICABLE` 및 화면 캡처·파일 경로·측정값을 남긴다. 자동 [발표 자료 계약 검사기](../scripts/check_presentation_contract.py)는 기록의 완전성만 보며 내용 정확도와 시각 품질의 PASS를 선언하지 않는다.

검사기 입력은 슬라이드별 `id, role, claim, evidence, readingOrder, renderEvidence`를 가진 JSON이다. 증거 항목에는 `source`와 `use`를, 렌더 근거에는 `preview`와 `exported`를 기록한다. 대표 슬라이드만 보지 않고 납품하는 전체 장을 기록한다. 주장·근거가 없는 표지/구분 장은 `claim` 대신 `purpose`를 적고, 예외 이유를 `exceptionReason`에 남긴다.
