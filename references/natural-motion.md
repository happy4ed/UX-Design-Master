# 자연스러운 모션: 보기와 조작의 연결

모션의 이름·수량보다 **사용자 행동과 화면 변화의 인과관계**를 먼저 설계한다. 자연스러움은 하나의 이징 곡선이 아니라, 입력 직후 반응·움직이는 대상의 연속성·정착·재입력·화면 전체 리듬이 서로 맞는 상태다. [컴포넌트 모션 판단](component-motion.md)의 사건별 후보를 실제 화면·흐름으로 묶을 때 이 계약을 적용한다. 원본 효과를 재현한다면 [모션 예시와 중복 판정](motion-sample-selection.md)의 원본 대조가 별도로 필요하다.

## 1. 사건을 네 층으로 나눈다

| 층 | 사용자가 알아야 할 것 | 시작 조건 | 기본 검토 |
| --- | --- | --- | --- |
| 즉시 피드백 | 입력을 받았는가 | 눌림·선택·키보드 실행 순간 | 보이는 반응과 실제 상태가 즉시 연결되는가 |
| 상태·공간 연속성 | 무엇이 어디로 바뀌었는가 | 열기·닫기·추가·삭제·정렬·화면 이동 | 같은 대상이 같은 대상으로 추적되고 출발점·도착점이 맞는가 |
| 설명·초점 | 왜 순서·값·관계가 바뀌었는가 | 데이터·도식·온보딩·발표 단계 | 내용의 인과와 모션의 순서가 일치하는가 |
| 분위기·장식 | 화면의 성격을 느끼는가 | 첫 방문·전시·드문 완료 | 앞의 세 층과 읽기·조작을 가리지 않는가 |

한 사건에 여러 층이 필요하면 **즉시 피드백은 먼저**, 공간 이동과 설명은 그 뒤 또는 함께 이어진다. 실제 작업이 끝나기 전의 완료 모션은 거짓 피드백이다. 로딩 모션은 실제 진행·대기 상태와 동기화하며, 단순 장식 재생이 완료를 지연시키지 않는다. 실패·취소에도 사용자가 다음 행동을 알 수 있는 정적 결과를 남긴다.

## 2. 화면 전체의 움직임 밀도

각 주요 상태에서 `동시에 움직이는 대상 / 그중 시선을 끌어야 하는 하나 / 반복되는 장식 / 사용자가 읽거나 누르는 영역`을 적는다. 핵심 행동의 피드백과 경쟁하는 자동 반복, 모든 카드의 동일한 등장, 마우스를 따라오는 장식이 자료를 가리는 경우는 줄인다. 움직임이 전혀 없어 상태 변화가 보이지 않으면 필요한 사건에 피드백을 보강한다. **적당함은 전체 효과의 개수가 아니라, 관심을 둘 사건과 가만히 있을 영역의 대비**로 검토한다.

같은 종류의 사건은 같은 공간 방향·거리·정착 방식으로 연결하고, 다른 의미의 사건은 필요한 경우 구분한다. 예를 들어 같은 위치에서 열리는 메뉴가 어느 화면에서는 위에서, 다른 곳에서는 아래에서 날아오면 출처가 불명확해진다. 모션 토큰에는 단순 `fast/slow` 외에 `입력 피드백 / 작은 내용 교체 / 공간 이동 / 설명 공개` 역할과 매체별 변형을 둔다. 모든 사건을 같은 프리셋으로 통일하지 않는다.

## 3. 동작의 물리·의미 일치

- **앵커와 방향:** 누른 요소에서 나오는 패널은 그 요소와의 관계가 읽히는 기준점에서 시작한다. 닫힐 때도 실제 복귀 대상과 연결한다. 화면 이동은 탐색 계층과 뒤로가기 방향을 배반하지 않는다.
- **대상 보존:** 목록 재정렬·확대 보기·카드 펼치기에서 같은 항목의 ID와 내용이 유지된다. 다른 항목으로 변한 것처럼 보이는 교차는 피한다.
- **속도와 정착:** 거리·크기·정보량·사용 빈도에 맞춰 시간을 정한다. 처음에 거의 다 움직이고 끝에서 오래 멈칫하는 곡선, 과한 오버슈트, 반복 입력마다 처음부터 튀는 키프레임은 실제 화면에서 교정한다. [모션 시간](motion-timing.md)의 수치는 시작 범위이며 원본 재현의 정답이 아니다.
- **제스처 결합:** 드래그·스와이프·스크롤에 반응하는 대상은 손가락/포인터와 동기화하고, 놓은 뒤 정착·취소·경계 복귀를 정의한다. 사용자 입력과 무관한 자동 전환으로 제스처 결과를 흉내 내지 않는다.
- **정보 보존:** 애니메이션 중간에 값·라벨·버튼이 읽히거나 눌려야 하는지 정한다. 움직임 감소·일시정지·PDF 정적 내보내기에서도 핵심 관계와 결과가 남아야 한다.

## 4. 사건별 검토 기록

선택한 모션마다 다음을 한 행으로 남긴다.

`화면·사건 / 사용 빈도 / 목적 층 / 입력 방식 / 즉시 피드백 / 실제 상태가 확정되는 시점 / 움직이는 대상과 앵커 / 시작·결정적 중간·끝 / 거리·시간·이징 / 동시에 움직이는 다른 대상 / 재입력·역전·취소 / 정적·모션 감소 대안 / 실측 화면·기기 / 사용자 결정`.

탈락한 후보도 `왜 정적 처리 또는 다른 효과가 더 적합한지` 남긴다. 원본 모션을 썼다면 원본 장면과 내부 장면을 각각 연결하고, **원본 동작 정확도 / 제품 상호작용 적합성 / 시각적 자연스러움**을 별개로 판정한다. 원본에 정확해도 제품 조작에는 과할 수 있고, 제품에서 자연스러워도 원본 재현에 실패할 수 있다.

## 5. 확인 D의 실제 조작 시험

정적/절제/표현적 후보는 같은 데이터·같은 화면에서 **사용자가 직접 입력하며** 비교한다. 다음 순서가 재현 가능해야 한다.

1. 첫 입력: 즉시 피드백이 보이고, 완료·오류 표시가 실제 결과와 맞는가.
2. 애니메이션 도중 같은 입력과 반대 입력: 중간 상태에서 이어지거나 취소되며 대상이 순간 이동하지 않는가.
3. 연속 입력과 빠른 탐색: 대기·중복 실행·초점·스크롤이 어긋나지 않는가.
4. 키보드·터치·포인터: 같은 상태 결과가 나오고 hover 전용 정보가 없는가.
5. 느린 기기·긴 내용·좁은 폭·모션 감소: 프레임 저하, 잘림, 정보 소실이 없는가.
6. 화면 전체 재생: 중요도 낮은 반복 효과가 주요 피드백을 가리지 않는가.

각 시험은 화면 캡처나 재생 기록과 `PASS/FAIL/NOT_RUN`을 남긴다. 자동 픽셀 변화나 애니메이션 객체의 존재만으로 자연스러움 PASS를 선언하지 않는다. 사용자의 체감은 실제 조작 가능한 프로토타입에서 확인 D로 결정한다.
