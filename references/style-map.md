# 웹 스타일 맵: 관찰값과 적용값 분리

사용자가 스타일 레퍼런스를 요청하거나 승인된 와이어프레임에 시각 방향을 적용할 때 [30개 스타일 프로필](../knowledge/web-style-profiles.json)을 필요에 따라 조회한다. 전체를 한꺼번에 읽지 말고 제품 유형·콘텐츠 밀도·브랜드 제약에 맞는 후보를 좁힌다. 브라우저 비교 화면은 릴리즈 패키지에 포함하지 않는다. 비교에 필요한 관찰값은 내부 스타일 프로필 JSON에 포함되어 있다.

```bash
python3 scripts/query_styles.py --list-kinds
python3 scripts/query_styles.py --kind editorial --limit 3
python3 scripts/query_styles.py --query ruled --limit 4
python3 scripts/query_styles.py --diverse --limit 10
python3 scripts/query_styles.py --family style-family-03
```

명령 경로는 스킬 디렉터리를 기준으로 한다.

## 필드 해석

- `observed`: 실제 공개 랜딩 페이지의 1440×900 CSS px 표본에서 읽은 헤딩 CSS/box, nav padding, 반복 gap/radius 후보, x 정렬선, SVG/icon class/img DOM 수. 하나의 화면·시점·viewport에서 관찰된 값이다. 빈도는 공식 디자인 토큰의 증거가 아니다.
- `projection`: 원본 특징을 Core UI KB에 적용할 수 있도록 새로 구성한 배경·글자·강조색, 정렬·구획·아이콘 처리, 데모용 spacing/typography/radius 값. **원본 CSS의 정확한 복제나 사이트의 공식 디자인 시스템이 아니다.** 실제 프로젝트의 브랜드·접근성·콘텐츠·플랫폼에 맞게 다시 결정한다.
- `surfaceMode`: `open`은 여백·서체, `ruled`는 선·행, `bands`는 배경 구획, `feature`는 기능/미디어 표면 강조. 시연의 해석값이며 사이트 전체의 카드 개수나 규격을 주장하지 않는다.
- `styleFamily`: [구조군 데이터](../knowledge/style-families.json)의 탐색용 묶음. 표면·정렬·간격·서체 분류 등 제한된 표본으로 계산한 유사도이며 브랜드나 전체 사이트의 동일성을 뜻하지 않는다. 30개 원본 프로필은 그대로 유지한다. `--diverse`는 구조군마다 대표 1개씩 먼저 보여주고 `--family`는 군 안의 차이를 살펴본다.

## 스킬 동작에 반영

1. 화면의 과업·영역·의미 역할을 먼저 정의한다. 특정 사이트 외형으로 tab/button/switch 등 역할을 결정하지 않는다.
2. 후보 사이트의 원본을 열어 현재 화면과 원본 출처를 다시 확인한다. 사이트 변경·지연 로딩·쿠키/지역 UI가 보이면 저장된 프로필보다 현재 증거를 우선한다.
3. 팔레트와 폰트만 고르지 말고 hero 정렬, 반복 기준선, nav inset, 그룹 간 거리, 표면 구분, 아이콘 사용량을 한 묶음으로 비교한다. 유사한 사례를 여러 개 나열하기보다 서로 다른 구조군을 먼저 보여주고, 선택한 군 안에서는 색·글꼴·밀도·그라데이션 차이를 다시 비교한다. CSS px 표본과 새 제품의 토큰은 분리한다.
4. 같은 콘텐츠·컴포넌트 계약의 대표 화면에 최소 두 스타일 방향을 시연하고 사용자와 색상·폰트를 결정한다. 신규 제품의 기능 구조 A1·흐름 A2·화면 분할 A3와 세 가지 와이어프레임 확인 B 전에 GUI를 확정하지 않는다.
   앱 또는 앱 같은 웹에 이 구조군을 적용하면 [플랫폼 관례 표](mobile-app-study.md#플랫폼-관례와-관찰된-부재)를 대조하고 충돌하는 웹 헤더 경계·그림자를 수정한다. 표본에서 관찰되지 않은 스타일을 플랫폼의 불변 규칙으로 단정하지 않는다.
5. 카드형 컨테이너는 독립 정보 단위, 자체 행동·상태, 배경이나 미디어를 묶어야 할 때 선택한다. 역할 경계가 제목·구분선·여백·배경 구획으로 충분하면 그 방법을 우선 검토한다. 포화 데이터에서 카드 반복이 시각적 소음과 높이 증가를 만드는지 검수한다.

스타일은 Core KB 항목의 의미·상하위·junction 관계를 바꾸지 않는다. 같은 역할을 다른 토큰으로 표현한 시연일 뿐, 외부 사이트의 아이콘·이미지·코드를 가져온 자산 목록이 아니다.

색상과 그라데이션은 [색상·그라데이션 지식 그래프](color-knowledge-graph.md)에서도 조회한다. 이전 DOM 표본의 색 출현값, 내부 시연 팔레트, 새로 측정한 실제 CSS 그라데이션을 서로 다른 관계와 증거 등급으로 기록했다. 색 이름이나 시연색 하나만으로 원본 사이트의 공식 팔레트라고 추정하지 않는다.
