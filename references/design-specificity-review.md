# 고유한 화면 구성과 AI 반복 패턴 검수

이 검수는 앱·웹·문서 모든 산출물에 적용한다. 특정 외부 스킬의 명령을 호출하지 않는다. 실제 제품의 목적·자료·사용 맥락을 먼저 확인하고 우리 제작 시스템과 렌더 검사에 연결한다. 규칙을 통과했다는 사실만으로 화면이 좋다고 판정하지 않는다.

## 1. 만들기 전 기록

누가 / 어디서 / 무엇을 하려는가 / 가장 중요한 한 행동 / 반복해서 보는 정보 / 실제 근거 화면·자산 / 채택한 시각 세계 / 금지할 오해를 한 화면 명세에 적는다. 운영 도구·읽기 화면은 밀도와 탐색성을, 발표·전시 화면은 장면의 순서와 인상을 우선한다. 기존 제품 화면을 따라야 하면 캡처의 바탕, 레이어, 글자·아이콘, 여백, 접점과 동작을 먼저 측정한다. **실제 GT 없이 플랫폼 이름만 붙여 임의 테마를 만들지 않는다.**

## 2. 편집 검수

| 질문 | 수정 기준 |
| --- | --- |
| 핵심 행동과 현재 상태가 첫눈에 보이는가 | 모든 조작이 같은 굵기·색으로 경쟁하면 우선순위별로 줄인다 |
| 카드가 실제 객체·레이어·조작 단위인가 | 단순 목록·설명·필터를 같은 크기의 둥근 카드로 반복하지 않는다. 밀집형 인덱스는 행과 구분선이 더 적절할 수 있다 |
| 각 그룹의 간격이 관계를 설명하는가 | 가까운 정보는 좁게, 다른 역할의 영역은 넓게. 같은 gap만 반복하지 않는다 |
| 도입 라벨·부제·설명이 중복되는가 | 제목 위 장식용 영문 소제목과 같은 뜻의 부연을 제거한다. 계열·상태처럼 탐색에 필요한 라벨은 남긴다 |
| 색이 역할을 갖는가 | 실제 GT의 바탕·surface·강조·기능색을 분리하고, 채도가 높은 색을 모든 카드와 아이콘에 반복하지 않는다 |
| 글꼴과 아이콘에 근거가 있는가 | 플랫폼/브랜드의 실제 서체 후보와 글리프를 확인한다. 유니코드 기호를 완성된 아이콘 시스템처럼 쓰지 않는다 |
| 장식이 콘텐츠를 대신하는가 | 숫자·스파클라인·그라데이션·그림자·글로우가 정보와 상태를 설명하지 않으면 제거한다 |
| 모든 구역에 같은 등장 애니메이션을 붙였는가 | 하나의 주요 장면과 실제 상태 변화에만 목적 있는 모션을 둔다. 반복 UI의 가독성을 우선한다 |
| 문구가 제품 상황을 말하는가 | 범용 AI 문장, 과장, 이름만 바꾼 설명을 실제 과업과 데이터에 맞게 다시 쓴다 |

금지 목록을 취향처럼 절대화하지 않는다. 실제 One UI 설정 캡처의 흰 그룹 면은 내용과 조작을 묶으므로 유효하다. 반대로 모션 카탈로그의 414개 동일 카드는 정보 구조가 아니라 생성 습관일 수 있으므로 행 목록으로 정리한다.

반복 장식·카드·칩·구분선·그림자·모션이 의심되면 **제거 시험**을 한다. 하나를 임시로 뺀 화면을 실제 콘텐츠로 렌더해 과업 정보, 상태, 시각 계층, 브랜드 식별이 유지되는지 비교한다. 유지되면 덜어내고, 잃는 것이 있으면 그 역할을 명세한다. 단순 개수 제한으로 판단하지 않는다. 실적·후기·고객 로고·지표처럼 사실로 보이는 요소는 원본 출처가 없으면 장식으로도 남기지 않는다.

## 3. 브라우저에서 확인

1. 대상 프로젝트의 데스크톱 창·중간 폭·가장 좁은 사용 기기 폭에서 첫 화면을 흐리게 보아 주요 미리보기 → 선택 목록 → 상세 근거 순서가 보이는지 확인한다.
2. 제목/본문/보조 정보 역할을 3–4단계 안에 두고 실제 폰트 로딩과 200% 확대를 본다.
3. 긴 한글·영어·RTL, 항목 없음·선택·재생·완료·움직임 감소 상태를 실제 DOM으로 확인한다.
4. 포커스 순서, 최소 터치 영역, 키보드 조작, 시연의 중간·끝 프레임을 본다.
5. 검사기의 경고와 실제 화면을 따로 기록한다. 카드 수·색 수·점수 하나로 고유성을 증명하지 않는다.

검토 기록에는 GT 근거 → 화면 역할 → 적용 토큰/컴포넌트 → 실제 캡처 → 문제 수정 → 재검증을 남긴다. 참조 스타일이 없으면 “원본 재현”이라고 쓰지 않는다.
