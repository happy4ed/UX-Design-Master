# 모션 × 컴포넌트 지식 그래프

[그래프 데이터](../knowledge/motion-component-graph.json)와 [탐색 화면](../samples/motion-component-graph.html)은 확정 고유 모션 343종을 `활용 유형 / 움직임 규모 / 변화 축 / 원본 계열 / 컴포넌트 후보`로 연결한다. 컴포넌트 ID는 [기본 컴포넌트 지식 기반](../knowledge/core-components.json)의 ID를 사용한다. `candidate_for`는 화면의 역할과 상태가 맞을 가능성이다. 실제 컴포넌트 인스턴스에서의 재생 검증이나 제품 적용 승인이 아니다.

## 태그의 의미

| 축 | 사용법 | 혼동 방지 |
| --- | --- | --- |
| 활용 유형 | 탐색·전환·데이터 변화·입력 피드백처럼 정보가 바뀌는 목적을 고른다 | 원본 분류 계열과 다를 수 있다 |
| 움직임 규모 | 작음=요소 내부, 중간=요소 크기, 큼=영역 대부분, 화면 전체=뷰포트 경계까지 영향을 주는 변화 | 시간·이징·세기·물리적 px 거리를 뜻하지 않는다 |
| 변화 축 | 위치·크기·회전·깊이·투명도 등 실제로 변하는 속성 후보 | 제품의 시작/종료 수치를 정한 결과가 아니다 |
| 컴포넌트 후보 | 해당 상태 변화가 발생할 수 있는 기존 기본 컴포넌트 | 모든 후보에 무조건 모션을 붙이라는 뜻이 아니다 |

## 적용 절차

1. 실제 화면의 컴포넌트 ID, 사용자 사건, 전후 상태와 정적 피드백을 정한다. [컴포넌트 사건 목록](../knowledge/component-motion-coverage.json)으로 놓친 상태가 있는지 본다.
2. 그래프에서 컴포넌트와 활용 유형을 함께 필터링해 후보를 좁힌다. 원본 계열 기본 연결은 특히 넓은 후보이므로 화면 목적에 맞는지 확인한다.
3. 각 후보의 [동작 시연](../samples/motion-verified-lab.html)과 원본 근거를 확인한다. 사용 대상의 크기, 이동 거리/각도, 시간, 중단·역전, 모션 감소와 종료 상태를 구체화한다.
4. 실제 컴포넌트에 적용한 프로토타입에서 사건→중간→끝을 확인하고 기록한다. 다른 컴포넌트에 같은 모션을 사용하더라도 입력 방식과 종료 상태가 다르면 별도로 검증한다.

`scripts/build_motion_component_graph.py`로 분류표와 컴포넌트 KB의 ID를 다시 연결한다. 특정 상태에 대한 명시 규칙이 없는 연결은 원본 계열 기본 후보로 표시한다. 새 컴포넌트나 고유 모션을 추가하면 생성기와 검사기를 실행해 빠진 연결·없는 ID·이전 집계값을 확인한다.
