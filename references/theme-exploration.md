# 와이어프레임 이후 9개 테마 탐색

확인 B에서 선택한 **같은 와이어프레임**을 확인 C의 9개 시각 테마로 렌더한다. [9개 탐색 원형](../knowledge/theme-exploration-archetypes.json)은 후보를 넓히는 출발점이며 제품의 공식 스타일 이름이나 필수 외형이 아니다. 플랫폼·브랜드·과업에 맞지 않는 원형은 이유를 적고 다른 시각 문법으로 교체하되 9개 비교를 유지한다. 사용자가 이미 확정한 브랜드 시스템이 있으면 그 제약 안에서 9개 변주를 만들고 확정된 규칙을 바꾸는 제안은 따로 표시한다.

## 만들기

1. 승인 와이어프레임 ID, 같은 실제 콘텐츠·초기/포화 자료, 같은 표시 크기·상태를 비교 기준으로 고정한다. 테마마다 다른 데이터를 넣어 보기 좋게 꾸미지 않는다.
2. 각 후보의 **구성, 색 역할, 여백 체계, R/형상, 컴포넌트 스타일, 재질·표면, 글꼴 운용, 이미지·아이콘**을 별도 축으로 정한다. 수치는 제품과 실제 화면에서 결정한다. 색만 바꾼 후보는 테마 수에 넣지 않는다.
3. 안정적 사용형, 표현형, 탐색형을 모두 포함한다. 유리 레이어·오리가미 같은 재질적 표현도 후보에 넣되 텍스트 대비, 컴포넌트 의미, 터치 영역, 플랫폼 관례를 해치면 고치거나 교체한다. 유리는 불투명 대안을, 접힘은 실제 열림·단계 변화와의 관계를 보여준다.
4. 9개를 실제 대표 화면·페이지의 **선택 가능한 미리보기**로 보여준다. [9안 비교 보드](../samples/theme-nine-board.html)는 `?manifest=프로젝트-기록.json`으로 각 안의 렌더 이미지와 전체 크기 화면을 불러온다. manifest가 없는 보드는 원형 설명일 뿐 실제 시안이 아니다. 각 미리보기는 확대해 원래 표시 크기로 열 수 있어야 한다. 색상 견본이나 스타일 이름만으로 후보를 세지 않는다. 앱/웹은 상태와 반복 컴포넌트가 보이는 대표 화면을, 문서/PPT는 표지와 정보 밀도가 있는 대표 면을 포함한다.
5. 각 후보를 같은 조건으로 병렬 비교하고 `과업 적합성 / 고유한 시각 문법 / 읽기·조작 / 초기·포화 / 기술·자산 부담 / 접근성`을 근거와 함께 적는다. 적합한 추천안과 의도적 실험안을 구분한다. 사용자가 구성·컴포넌트·색·밀도·재질을 축별로 섞어 선택할 수 있다.

## 사용자 선택 이후

선택된 후보 또는 조합을 **새 방향 ID**로 기록하고, 그대로 전체 주요 화면·페이지의 디자인 시스템과 실제 결과물에 옮긴다. 9개 미리보기의 토큰을 무심코 섞지 않는다. 선택안의 `palette / typography / spacing / radius / surface / component states / imagery / motion policy`와 적용 화면·예외를 한 표로 이월한다. 초기·포화·오류·다국어/RTL과 큰 글자에서 실제 렌더를 확인한다. 대화형 결과물은 작동하는 프로토타입으로 주요 과업을 연결한다.

완성 후 제작자가 아닌 [독립 사용자 관점 검증 에이전트](independent-review.md)를 새 문맥에서 실행한다. 에이전트에는 목적 한두 문장과 실제 결과물만 전달한다. 평가자는 **화면 간 테마·컴포넌트의 일관성**, 처음 보는 사람이 기능·이름·상태를 이해하는지, 잘림·중복·부적절한 컴포넌트·입력 후 상태 문제를 확인한다. 사용자 선택안과의 정확한 이월 여부는 선택 명세를 아는 제작자가 별도 비교하고, 평가자에게 정답을 주지 않는다. 제작자가 발견을 수정하고 새 독립 검수로 재확인한다. 에이전트를 실행하지 못하면 `NOT_RUN`으로 기록한다. 사용자의 C 선택과 독립 검수 PASS는 서로 다른 게이트다.

[테마 탐색 기록 검사기](../scripts/check_theme_exploration.py)는 9개 후보의 렌더 근거, 축별 차이, 사용자 선택, 선택안의 제작 이월 및 독립 검수 기록 누락을 찾는다. 숫자·스타일 값의 품질이나 시각적 차이를 검사기 PASS로 선언하지 않는다.

비교 보드와 검사기는 같은 manifest를 읽는다. 최상위에 `stage: C-candidates`, `approvedWireframeId`, `sameContentFixtureId`, `comparisonViewport`, `directions` 9개를 둔다. 각 방향에 `id/name/role/archetypeId`(교체 시 `replacementFor/replacementReason`), `renderEvidence`(이미지), `fullSizePreview`(전체 화면 URL), `sameScreenState`, `taskFit`, `accessibilityEvidence`, `axes`의 8개 값을 기록한다. 경로는 manifest 파일을 기준으로 해석한다. 선택 후 `stage: C-selected`와 `selection`, 실제 제작 후 `stage: final`과 `productionHandoff/independentReview`를 채운다. 미리보기의 선택 표시는 사용자 승인 자체가 아니다.
