# 스타일 미확인값의 임시 추정과 갱신

## 언제 적용하나

스타일 가이드의 C·D·E·G·K절에 필요한 값이 `미확인`이면 **그대로 빈칸으로 넘기지 않는다.** 해당 화면에서 실제로 필요한 부품·상태·테마·기기를 먼저 적고, 같은 스타일의 확인된 값을 이용해 임시값을 만든다. 이 절차는 화면 제작을 진행하기 위한 것이며 원본 복제 판정은 아니다. 사용자에게는 확정값과 추정값을 다른 표시로 보여준다.

## 추론 우선순위

1. **같은 부품의 다른 상태·테마·기기:** 원본의 반복값, 중앙값, 역할 비율을 쓴다. 라이트에서 다크로 색을 옮길 때는 색상각만 복사하지 않고 각 표면의 실제 대비를 다시 맞춘다.
2. **같은 스타일의 형제 부품:** 같은 역할의 버튼·행·입력에서 간격 단계, 글자 위계, R/크기 비율을 추출한다. 아이콘 외곽 상자만 같다고 가시 형상까지 같다고 추론하지 않는다.
3. **공식 디자인 체계나 실물 구조:** 해당 버전의 알려진 토큰·제조사 치수에서 파생한다. 버전이 다르거나 모델이 다르면 오차 범위와 차이를 명시한다.
4. **동일 스타일의 내부 가안:** 위 세 근거가 없을 때 기능·접근성·레이아웃 원칙에 맞는 설계 가설을 만든다. `공식/실측/관찰/파생`으로 승격하지 않는다.

수치가 여러 개면 단일값을 즉시 고르지 않는다. 후보의 최소·최대와 중앙값, 사용 맥락을 기록한다. 설계 토큰의 단계로 반올림할 때는 원값과 반올림값을 모두 남긴다. 이진 탐색이 가능한 범위값(글자 크기·간격·폭)은 허용 가능한 최소/최대의 **중간값**부터 실제 렌더에서 시험해 범위를 좁힌다.

## 값 하나의 기록 계약

`스타일/버전 | 부품·속성 | 상태·테마·기기 | 임시값/범위/단위 | 등급(추정 또는 설계 가설) | 원본 앵커 ID·위치 | 추론식·선택 이유 | 신뢰도·오차 | 검사 화면/결과 | 확인일 | 새 근거가 오면 교체할 조건`

- **추정:** 같은 스타일의 실측·공식값 등 원본 앵커와 재현 가능한 계산이 있다.
- **설계 가설:** 원본 앵커가 부족하지만 실제 화면에서 쓸 임시 구현값을 정한다. 시연 CSS에서 역추출한 값은 여기에 속한다.
- **미확인 유지:** 원본의 사실 자체를 가리키는 항목(정확한 서체명, 원본 기호의 경로, 정적 화면에 없는 움직임, 실제 터치 영역, 제품 API 동작)은 추론으로 확정할 수 없다. 필요하면 별도의 설계 가설을 함께 둔다.

숫자 또는 문자열만 적고 `추정`이라고 쓰면 실패다. 출처 앵커, 계산/선택 이유, 실제 화면 검사, 교체 조건을 모두 남긴다. 한 부품의 추정값을 다른 부품에 자동 전파하지 않는다.

## 사용 전 검사

임시값을 같은 콘텐츠의 폰/폴드 × 라이트/다크에 적용하고 ① 글자·조작 영역 하한, ② 대비, ③ 겹침·잘림·정렬, ④ 상태 구분, ⑤ 탭·키보드·느린/빠른 끌기와 끝 동작, ⑥ 모션 감소 상태를 해당 부품에 맞춰 시험한다. 실패하면 후보를 조정하거나 안전한 기능형으로 되돌린다. 시각 비교에는 실제 화면과 같은 배율의 캡처를 사용한다. 검사기 PASS는 원본 일치 PASS가 아니다.

현재 기준 화면의 임시값은 [추정값 등록부](style-book/provisional-estimates.json)에 있다. 이 값은 [76상태 DOM 측정](../samples/style-book-audit.json)과 [세부 결정표](style-book/detail-decisions.json)에서 생성한다. 앱/웹/문서의 실제 과업에 적용할 때는 그 제품의 콘텐츠·기기·사용자 승인값으로 다시 측정한다.

## 나중에 근거를 찾았을 때

새 공식 토큰·버전 일치 화면·실물 사진이 생기면 기존 추정값을 삭제하지 않고 `이전값 → 새 측정값 → 차이 → 영향 화면 → 재렌더`를 기록한다. 새 근거가 같은 버전·상태인지 먼저 검증한다. 차이가 허용 범위 안이면 근거 등급과 신뢰도를 갱신한다. 범위를 벗어나면 관련 토큰·컴포넌트·화면을 재렌더하고 사용자에게 이미 확정받은 시각 방향과 충돌하는지 보여준다. 변경 전후의 같은 과업으로 비교한 뒤 등록부의 상태를 `대체됨`으로 바꾼다.

`scripts/reconcile_style_estimate.py --style <id> --key <key> --value <새값> --grade 실측 --basis <원본-버전-좌표>`로 새 근거를 기록하면 상태가 `재검증 필요`가 된다. 새 값으로 기준 화면과 해당 과업 화면을 다시 렌더해 검사한 뒤 `--style <id> --key <key> --qa-evidence <보고서/캡처 경로>`로 검증을 확정한다. 도구는 이전값을 history에 보존하고 가이드 K.1표를 동기화한다. QA 파일이 있다는 사실만으로 시각 품질을 자동 판정하지 않으며 사람이 결과를 읽어야 한다.
