# 스타일 가이드북

이미지 분석 실험 후보: [모듈형 데이터 아틀라스 A–L](studies/modular-data-atlas.md) · [앱·웹 컴포넌트와 모션](../../samples/modular-data-atlas-components.html). 기존 Flat 2와 Swiss Grid의 변형 후보이며 원본에 없는 앱·웹 부품은 guess다.

브라우저에서 [인터랙티브 가이드북](../../samples/style-guidebook.html)을 열면 26개 스타일의 A~L 절, 원본 미확인 건수와 현재 임시값, 글꼴·아이콘·슬라이더 결정, 원문과 기준 화면을 볼 수 있다. 두 가이드를 같은 절에서 나란히 비교할 수 있다. E·G·L 절에는 선택한 스타일의 컴포넌트·모션 시연 링크가 있다. 기준 화면에 적용한 속성은 [세부 결정표](detail-decisions.json)의 제안을 포함하며 원본 복제의 증거가 아니다.

스타일의 부품 범위는 [컴포넌트 시연](../../samples/style-book-component-board.html)에서 확인한다. 앱바·탭·버튼·입력·선택·슬라이더·목록·카드·진행·피드백·시트·대화상자·빈/오류 상태를 같은 콘텐츠로 비교한다. 샘플에 무엇을 넣을지는 [범위 계약](../style-sample-coverage.md)으로 결정한다.

26개 기본 스타일에는 각각 [guess 기본 레퍼런스](../../samples/style-guess-books.html)가 있다. 각 가이드 E.4에 13개 부품 역할, G.1에 5개 모션 장면을 기록했고, 같은 화면에서 부품을 조작하고 모션을 재생할 수 있다. 구현값의 근거는 [스타일별 추론 프리셋](guess-presets.json)에 있다. `guess`는 보류 표시가 아니라 **현재 작동하는 추론값**이다. 실제 원본의 같은 요소·상태가 확인되면 대조하여 값을 수정하고 해당 태그를 제거한다.

태그를 제거할 때는 [확인값 등록부](confirmed-style-values.json)의 `styles.<style-id>.tokens|components|motions.<row-id>`에 `source`, `date`, `sameStateEvidence`, `renderUpdated: true`와 측정값을 넣는다. `renderUpdated`는 실제 CSS·모션 샘플까지 고친 뒤에만 설정한다. [동기화 스크립트](../../scripts/sync_style_guess_books.py)는 근거와 렌더 갱신이 모두 있는 행만 `관찰`로 바꾼다. 다른 행의 `guess`는 유지한다.

One UI와 iOS를 제외한 24개 스타일은 [컴포넌트별 형태·상태·모션 변환표](component-expression.json)를 각 가이드 E.2절에 동기화한다. 표에는 원본에서 관찰한 범위와 아직 측정하지 못한 범위를 나누고, 부품 구현을 설계 가설로 표시한다. [현재 시연의 68상태 실측](../../samples/style-book-component-expression-audit.json)과 [폰 캡처](../../samples/style-book-renders/component-expression/)는 **내부 구현 검증**이며 외부 원본의 측정이나 일치 판정이 아니다.

`ui-style-book.md`는 적용 순서만 다룬다. 실제 스타일을 고를 때는 이 목록에서 해당 **상세 가이드의 A~L 절과 값의 근거 등급**을 읽는다. `제안`과 `미확인`은 플랫폼의 공식값이나 원본과 일치하는 값이 아니다. 스타일 이름만 보고 부품을 그리지 않는다.

**스타일 채택 조건:** [이미지·화면 실측 절차](../image-to-style-guide.md)로 관찰 가능한 원본을 측정한다. 없거나 보이지 않는 요소는 알고 있는 스타일 원리로 추론하고 A~L 구현값을 `guess`로 채워 작동 샘플을 만든다. 원본 미확인은 구현 보류가 아니다. 과업별로 필요한 부품을 빠짐없이 적은 **컴포넌트북**과 그 부품·화면 전환에 적용할 **모션북**을 함께 만들어 확인 C에서 사용자에게 보여주고 선택·수정을 반영한다. 원본 확인·guess·미구현을 나누며, 새 부품·동작이 추가되면 두 책을 갱신한다.

## 앱·웹·문서에 번역하는 공통 계약

자유 스타일은 한 매체의 색을 다른 매체에 복사하는 테마가 아니다. 실제 샘플을 만들기 **전에** 각 가이드의 D(매체·화면 폭과 페이지 구조), E(컴포넌트 역할·해부·상태), F(과업 패턴), G(동작과 정적 대안), J(접근성·인쇄), L(매체별 렌더 근거)을 작성한다. 기존 A~L 형식은 유지한다. 가이드에 아직 없는 매체는 `미확인/설계 가설`로 표기하고 원본 재현으로 소개하지 않는다.

1. [컴포넌트·데이터·정렬 계약](../component-contract.md)으로 화면/페이지 사용 맵과 단일 시나리오 사실표를 먼저 만든다. 앱은 폰·태블릿·폴드의 같은 역할이 어떻게 재배치되는지, 웹은 좁음/넓음과 포인터·키보드·스크롤바, 문서는 페이지 격자·표·캡션·쪽번호를 정의한다. 문서에는 [문서 디자인 계약](../document-design.md)을 추가한다.
2. 각 부품에 `역할/내용 슬롯 → primitive/semantic/component 토큰 → 기본·선택·포커스·오류·포화 상태 → 입력 방식·hit 영역 또는 인쇄 의미 → 매체별 변형`을 붙인다. 문서의 버튼은 실제 누를 수 없는 버튼처럼 그리지 않고 다음 행동이나 상태 표시로 번역한다.
3. 같은 기능·문구·데이터를 앱·웹·문서에 쓰되, 문서는 시점이 고정된 스냅샷이면 그 시점과 계산식을 밝힌다. 정적 레퍼런스에서 보이지 않는 모션·터치·다크 모드는 원본 미확인과 시연용 가설로 구분한다.
4. 샘플은 [컴포넌트 범위 계약](../style-sample-coverage.md)의 매트릭스가 작성된 뒤 렌더한다. 앱은 폰/태블릿/폴드, 웹은 주요 폭과 상태, 문서는 실제 출력 페이지와 흑백·페이지 넘김을 직접 확인한다. 검사기 PASS는 원본 일치나 시각 품질 PASS가 아니다.

[네오 부르탈리즘 N6 변형](neo-brutalism.md#e3-n6-변형의-매체별-컴포넌트-계약)은 이 순서의 첫 적용 예다. 동일한 번역 계약을 다른 자유 스타일에도 적용하되 N6의 색·간격 숫자를 다른 스타일의 값으로 옮기지 않는다.

유리·금속·클레이처럼 재질이 핵심이거나 원형·알약처럼 형상이 조작 명세에 들어가면 [투명 소재·형상·모션 검증 계약](../material-motion-shape-qa.md)을 함께 쓴다. iOS 시연의 투명 유리와 48×48px 원형 조작 회귀 시험은 적용 사례이며 다른 스타일의 수치 기본값은 아니다.

원본에서 미확인인 값도 실제 디자인에서는 비워 두지 않는다. [임시 추정 절차](../style-estimation.md)를 적용하고 각 가이드 K.1절과 [추정값 등록부](provisional-estimates.json)에 현재 구현 후보·근거·신뢰도·검증·교체 조건을 둔다. `추정`과 `설계 가설`은 원본에서 확인된 사실과 시각적으로 구분한다.

| 실물 | [오디오 하이파이](skeuo-audio-hifi.md) | 실제 장비의 소재·부품 구조를 사진·제조사 자료로 대조한다. |
| 자유 | 아래 22종 | 제품 과업에 맞춰 변형할 수 있다. 기존 요약의 값은 별도 조사 전까지 `제안`이다. |

기존 `ui-style-book.md`의 목록은 **총 20개**이며 플랫폼 4개(Material, Fluent, One UI, iOS), 실물 1개(일반 스큐어모픽), 자유 15개로 구성된다. 의뢰 문구의 “기존 1~20번 중 플랫폼 제외 자유 20종”은 산술상 맞지 않는다. 기존 자유 계열 15개를 우선 이관하고, 근거 없는 다섯 계열을 수량 채우기용으로 만들지 않는다. Fluent는 아직 별도의 버전·실측 조사가 없어 플랫폼 후보로만 남긴다.

현재 활성 목록은 플랫폼 3개, 실물 1개, 자유 22개다. 추가 자유 스타일 7개는 사용자가 명칭과 핵심 특징을 지정했다. 이후 실제 제작자 사이트·브랜드 가이드·공공 아카이브를 브라우저에서 확인해 [관찰 근거](additional-style-references.json)와 각 가이드 B절에 기록했다. 관찰한 특징만 원본 근거이며, 내부 토큰·컴포넌트·모션 중 대조되지 않은 값은 계속 `guess`다. 외부 캡처는 배포 스킬에 넣지 않는다.

## 스타일 고르기

제품 성격·사용 플랫폼·정보 밀도·기기 성능·접근성·브랜드 제약으로 후보를 좁힌다. 같은 구조와 실제 콘텐츠를 가진 기준 화면에 서로 다른 후보를 적용해 **버튼·입력·목록·슬라이더·시트·타입·표면**까지 비교한다. 색만 다른 방향은 별도 스타일로 세지 않는다. 플랫폼의 관례와 자유 스타일이 충돌하면 플랫폼의 기능·접근성 요구를 먼저 검토하고 차이를 기록한다. 실제 서비스 사례 3개와 상태별 부품 근거가 확보되지 않은 자유 가이드는 디자인 가설로만 제시한다.

## 기본·사용자·프로젝트 세 층

1. 기본: 이 디렉터리. 스킬 업데이트 대상.
2. 사용자: 스킬 밖 `~/.claude/ux-design-master/style-book/` 또는 `UX_DESIGN_MASTER_USER_STYLE_BOOK`이 지정한 지속 경로. 설치·업데이트 후에도 보존.
3. 프로젝트: `<project>/design/style-book/`.

목록은 **프로젝트 → 사용자 → 기본** 순서로 합친다. 같은 ID는 앞선 층을 우선하지만 변경된 값과 상속 대상을 기록한다. 사용자가 준 스타일 이미지는 [이미지 등록 절차](../image-to-style-guide.md)로 분석하고 이름을 확정한 뒤 기본적으로 사용자 층에 등록한다. 사용자 층 폴더가 없으면 만든다. 층마다 `README.md` 목록을 유지한다. 현재 세 층을 병합해 보여주는 조회·등록 도구는 `scripts/style_book.py`다.

## 공통 기준 화면

미디어 리모컨: 앱바·검색·포스터·재생 버튼·재생 위치·음량·칩·목록 행·설정 진입을 포함한다. 전체 26개 스타일에 같은 문구·상태·콘텐츠를 적용하고 폰/폴드 × 라이트/다크 104개 상태에서 비교한다. 실제 버전 근거가 없는 원본 사실은 `미확인`으로 남기고, 현재 구현할 값은 K.1절에서 추정/설계 가설로 표시한다. 렌더와 실측은 각 가이드 L절에 연결한다.
