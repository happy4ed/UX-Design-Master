# 미니멀리즘 — Minimalism

## A. 신원

| 이름 | 분류 | 계열·기원 | 대상 버전 | 가이드 버전·확인일 |
|---|---|---|---|---|
| 미니멀리즘 / `minimalism` | 자유 | 핵심 내용·선택·행동에 집중하도록 시각 요소를 줄이는 계열. 단일 공식 표준 없음 | 브랜드·제품 웹/앱, 2026-11 관찰 | 0.1.0 · 2026-11-05 |

미니멀은 `흑백·얇은 선`과 동의어가 아니다. 아래 세 실사례는 각각 제품 이미지 중심, 타이포 중심, 업무 도구 중심의 절제를 보여 준다. 이 가이드는 공통 원리를 정리하되 실제 제품의 기능을 지우지 않는다.

## E.1. 글꼴·아이콘·슬라이더 결정

이 표는 컴포넌트별 구분이 누락되지 않도록 한 적용 계약이다. `제안`은 시연용 방향이며 원본 재현값이 아니다. 폰/폴드와 라이트/다크에서 각 부품의 기본·누름·포커스·끌기 상태를 따로 확인한다.

| 부품 | 형태·사용 규칙 | 근거 등급 | 상세 근거 |
|---|---|---|---|
| 글꼴 | 절제된 산세리프, 크기보다 여백으로 위계 | 제안 | minimalism.md C/E |
| 아이콘 | 동일 획의 작은 윤곽 기호 | 제안 | minimalism.md C/E |
| 재생 위치 | 선 하나와 작은 점, 포커스 상태는 확장 | 제안 | minimalism.md C/E |
| 음량 | 선형 트랙과 수치 병기 | 제안 | minimalism.md C/E |

시연 SVG·CSS의 실제 속성은 [기준 화면](../../samples/style-book-reference-screen.html)에서 확인한다. 근거 없는 시연값은 이 가이드의 원본값으로 승격하지 않는다.

### E.2. 컴포넌트별 형태·상태·모션 변환

색 토큰만 바꿔 스타일을 적용했다고 판정하지 않는다. 아래는 [시연용 변환표](component-expression.json)의 기능형 **설계 가설**이다. 원본 사례 B절에서 확인된 성격과 E절의 부품 제안을 분리한다. 실제 원본 부품의 형상·누름·선택·모션을 확인하기 전에는 원본 일치로 쓰지 않는다. 같은 콘텐츠로 [13개 역할 보드](../../samples/style-book-component-board.html)에서 확인한다.

**원본 관찰 범위:** B절 N1–N3 — 세 운영 사이트의 1280×577 정보 밀도·행동 수 관찰. **원본에서 아직 측정하지 못한 것:** 하위 기능 화면의 전 상태·동작 측정. 내부 [컴포넌트 계산 스타일·렌더 측정](../../samples/style-book-component-expression-audit.json)은 원본 실측이 아니다.

## F. 패턴

하위 화면+스위치 행, 목록|상세, 설정 묶음, 필터 고르기, 확인, 빈/로딩/오류, 여러 개 선택의 최대 상태를 모두 실제 기능 계약으로 정의한다. 미니멀 적용은 **불필요한 장식 제거**이며 필수 정보·복구·상태를 제거하는 것이 아니다. 결과가 같은 조작을 합치고, 한 줄에 보조 버튼이 몰리면 메뉴·시트·펼침으로 분산한다.

## G. 인터랙션

누름은 낮은 강도의 색·테두리·위치 피드백을 준다. 페이지 전환은 이전 화면과 현재 화면 사이의 맥락을 보존하고 빈 프레임을 만들지 않는다. 시트/대화상자 등장, 끌기, 진동은 실제 과업에 필요할 때 명확한 상태 변화를 보여 준다. N1~N3의 정확한 동작은 재생·실측하지 않았으므로 C의 모션값은 제안이며 원본 일치라고 표시하지 않는다.

## H. 문구 관례

제목은 화면의 기능/목적을 한두 단어로 표현한다. 버튼에는 결과를 예측할 수 있는 동사를 쓴다. 명확한 아이콘에 중복 설명을 붙이지 않는다. 단위·대소문자·다국어 줄바꿈은 데이터와 언어별 규칙으로 정하고, 과장된 감성 문구가 정보를 대체하지 않게 한다.

## I. 해도 되는 것 / 안 되는 것

1. N1처럼 한 제품 이미지와 두 행동에 시선을 집중할 수 있다. 모든 화면을 광고 히어로로 만들지 않는다.
2. N2처럼 어두운 면과 큰 글자로 명확한 위계를 만들 수 있다. 미니멀=흰색이라는 공식으로 두지 않는다.
3. N3처럼 한 곳에 색 강조를 둘 수 있다. 무채색만 허용한다는 규칙을 만들지 않는다.
4. 여백은 관계를 보여 주는 역할로 쓴다. 기능을 찾기 어렵게 숨기거나 긴 글자를 잘라 얻은 빈 공간은 품질이 아니다.

## J. 접근성 덮어쓰기

모바일 조작 영역 48×48 이상, 인접 8 이상, 본문·조작 글자 14 이상, 일반 텍스트 4.5:1·의미 있는 비문자 3:1을 검사한다. 희미한 회색 글자, 아이콘만 있는 행동, 얇은 입력 경계는 특히 확인한다. 폰트 150/200%에서 큰 제목과 CTA가 겹치면 제목 줄수와 히어로 높이를 늘리고 실제 스크롤 순서를 검수한다. `원안 값 → 접근성 변경값 → 이유 → 캡처`를 기록한다.

## K. 미확인 목록

- N1~N3의 실제 CSS 값·글꼴 파일·색 픽셀·R·반응형 전환점·상태/모션 미측정.

### K.2. guess 교체 기록

[기본 레퍼런스](../../samples/style-guess-books.html?style=minimalism)의 C.1 토큰·E.4 부품·G.1 모션은 `정보에 필요한 최소한의 선·면·행동`을 구현한 `guess`이다. A는 스타일 신원, B는 실제 출처만 기록하고 추론으로 출처를 꾸며내지 않는다. D/F/H/I/J는 이 기본 레퍼런스를 기기·과업·문구·접근성에 맞게 재배치·확장하는 계약이다. L의 내부 렌더 PASS는 원본 일치 판정이 아니다. 새 원본에서 같은 부품과 상태를 발견하면 원본 화면의 값·프레임을 실측 → 현재 guess와 차이 기록 → 코드와 책 수정 → 다시 렌더 검수 → 해당 항목의 `guess` 태그 제거 순으로 갱신한다.
