**표본과 한계.** R1은 33장을 요약하고 회고 본문은 60장이라고 적는다. 중복·버전별 원본 목록이 이 스킬에 없으므로 **독립 표본 수는 미확인**이다. 아래 `실측` 수치는 R1의 측정 기록을 재사용하며, 이번 작업에서 원본 캡처를 다시 픽셀 측정했다고 주장하지 않는다. `공식` 등급의 일반 삼성 문서는 One UI 9 고유 숫자를 채우는 근거로 쓰지 않는다.

**측정 재현법.** 원본 PNG에서 대상 외곽·중심을 픽셀로 표시하고 `측정 px ÷ (이미지 폭 px / 360dp)`로 환산하되 실제 기기 dp 폭을 확인하면 그 값으로 다시 환산한다. R1의 360dp 가정은 실제 384~412dp 기기에서 약 1.07~1.14배 차이가 날 수 있다. 색은 평탄한 영역의 5×5 중앙값을 sRGB HEX로 기록하고 JPEG 압축 오차를 표시한다. 반투명 표면은 바탕과 합성색을 분리해 추정한다. R은 모서리의 45°점과 원 접선 위치를 대조하고 추정 오차를 쓴다. 실측·공식 토큰이 다르면 둘 다 적고 재현 기준을 명시한다.

## E. 컴포넌트 명세

### 공통 기록 계약

아래 표의 **미확인**은 해당 컴포넌트를 부정하는 뜻이 아니다. 실측 부재 상태에서 One UI 9 고유 치수나 모양을 상상해 그리지 말라는 뜻이다. 각 부품은 프로젝트에서 채울 때 `역할/쓰지 않는 곳 → 해부 → 크기 단계·안쪽 여백·R·글자·아이콘 → 기본/누름/선택/비활성/포커스/끌기 → 라이트/다크 → 조작 영역·인접 간격 → 모션 → 값·단위·등급·출처·확인일 → 바꾼 것·미확인` 순으로 기록한다. 기본 공통 누름층은 C1 §2.2의 **9.5 파생값**이며 부품별 상태가 입증되지 않았으면 그대로 One UI 9 공식값이라 부르지 않는다. 접근성 조작 영역은 J절의 덮어쓰기다.

## G. 인터랙션

- 누름은 즉시 피드백을 주고 상태층을 쓰되 값은 해당 부품 토큰에서 읽는다. C1의 누름층은 9.5 **파생값**이다.
- 화면·시트 전환은 공간 관계가 읽혀야 한다. 공식 곡선은 `cubic-bezier(.22,.25,0,1)`이며 공식 문서는 동작을 최소 100ms, 최대 500ms로 설명한다(S4). 모든 동작을 한 시간으로 고정하지 않는다.
- 이미지 교체 시 이전 이미지가 완전히 사라지기 전에 새 이미지가 들어와 빈 프레임을 피하고, 본문 글자는 서로 겹치지 않도록 완전히 교체한다(S4).
- 슬라이더 끌기·탭·키보드·스크린리더는 **해당 구현에서 시험**한다. R1 캡처만으로 드래그의 관성·고무줄·햅틱을 추정하지 않는다.
- 진동 패턴·세기와 One UI 9 고유 햅틱 값은 **미확인**.

## H. 문구 관례

목적이 드러나는 짧은 명사 또는 동사구를 쓴다. 삼성 공식 목록 가이드는 설정 이름을 가능한 한 31자 안에 두고, 상세 화면이 따로 있으면 보조 설명을 그 화면으로 옮기라고 권한다(S2). 한 화면에서 선택과 과업을 지나치게 늘리지 않는다(S5). 빈 화면은 실행할 수 있는 다음 행동을 제시한다. 대소문자·단위는 앱 언어와 실제 데이터 단위를 따른다. 한국어 라벨을 임의 영어 Title Case로 바꾸지 않는다. 버전 9 고유 문구 규칙은 **미확인**.

## I. 해도 되는 것 / 안 되는 것

1. **된다:** 재생 위치용 얇은 트랙과 파형·링 썸(R1). **안 된다:** 옛 스타일북의 “모든 One UI 슬라이더 = 굵은 트랙 + 큰 thumb” 일반화.
2. **된다:** 앱바를 아래로 확장하고 스크롤에 따라 접기(S2). **안 된다:** 모든 화면 앱바 아래에 웹 헤더식 선·그림자 추가(R2에서 관찰된 부재).
3. **된다:** 곡 재생·이전·다음과 셔플·좋아요의 시각 위계 구별(R1). **안 된다:** 모든 미디어 버튼에 같은 배경 원 적용.
4. **된다:** 9.5 색 토큰을 9.0 시안의 *대응 후보*로 사용(C1). **안 된다:** 이를 One UI 9 공식 픽셀이라고 주장하거나 8.5 표본을 9 확정값으로 승격.
5. **된다:** 큰 화면에서 과업에 맞는 여러 칸(S3). **안 된다:** 폰 화면을 폴드 폭만큼 일률적으로 늘림.

[기본 레퍼런스](../../samples/style-guess-books.html?style=oneui-9)의 C.1 토큰·E.4 부품·G.1 모션은 `큰 제목에서 내용으로 내려오는 부드러운 계층과 넓은 손가락 조작`을 구현한 `guess`이다. A는 스타일 신원, B는 실제 출처만 기록하고 추론으로 출처를 꾸며내지 않는다. D/F/H/I/J는 이 기본 레퍼런스를 기기·과업·문구·접근성에 맞게 재배치·확장하는 계약이다. L의 내부 렌더 PASS는 원본 일치 판정이 아니다. 새 원본에서 같은 부품과 상태를 발견하면 원본 화면의 값·프레임을 실측 → 현재 guess와 차이 기록 → 코드와 책 수정 → 다시 렌더 검수 → 해당 항목의 `guess` 태그 제거 순으로 갱신한다.

## L. 검증 렌더

- **같은 기준 화면:** 앱바, 카드/포스터, 재생·이전·다음, 재생 위치, 음량, 검색, 칩, 목록 행을 가진 미디어 리모컨. 플랫폼별 같은 콘텐츠로 비교한다.
- **현재 기존 내부 렌더:** [`artifacts/cinema-frame-oneui-screens.html`](../../../artifacts/cinema-frame-oneui-screens.html). 이 렌더는 회고의 제품 시안이며, 이 상세 가이드 재적용의 독립 검증으로 보지 않는다.
- **새 검증 렌더:** `미실행 / 경로 미정`. 이 가이드의 원본 캡처 대조도 새로 수행해야 한다.
- **자동 실측:** `NOT_RUN`. 대상 폰/폴드 × 라이트/다크, hit area·글자·여백·R·줄바꿈·겹침·기준선 확인 후 결과 경로를 기록한다.
- **사람 시각 확인:** `NOT_RUN`. 자동 검사 PASS만으로 시각 일치 PASS가 되지 않는다.
