위 3곳은 작동하는 도구·부품·제품 데모다. **실사용자의 데이터가 운영되는 완제품 3건은 확보하지 못했다.** 그러므로 이 스타일을 범용 앱 규격이라고 주장하지 않는다. N1의 기본 그림자 예제 CSS는 직접 확인했지만, 이는 250px 예제 한 개의 생성값으로 앱 버튼·카드의 원본 치수가 아니다. 원본 앱 화면의 픽셀 실측은 0건이다. 앞으로 실제 서비스 화면 3건과 출처 이미지 해시를 확보한다.

## E.1. 글꼴·아이콘·슬라이더 결정

이 표는 컴포넌트별 구분이 누락되지 않도록 한 적용 계약이다. `제안`은 시연용 방향이며 원본 재현값이 아니다. 폰/폴드와 라이트/다크에서 각 부품의 기본·누름·포커스·끌기 상태를 따로 확인한다.

| 부품 | 형태·사용 규칙 | 근거 등급 | 상세 근거 |
|---|---|---|---|
| 글꼴 | 낮은 대비를 보완하는 굵은 산세리프 | 제안 | neumorphism.md C/E |
| 아이콘 | 면 안으로 눌린 둥근 윤곽 | 제안 | neumorphism.md C/E |
| 재생 위치 | 음각 트랙과 양각 원형 썸 | 제안 | neumorphism.md C/E |
| 음량 | 트랙 안쪽 그림자와 명확한 채움 경계 | 제안 | neumorphism.md C/E |

시연 SVG·CSS의 실제 속성은 [기준 화면](../../samples/style-book-reference-screen.html)에서 확인한다. 근거 없는 시연값은 이 가이드의 원본값으로 승격하지 않는다.

### E.2. 컴포넌트별 형태·상태·모션 변환

## G. 인터랙션

누름은 양각 면의 그림자 축소/음각 전환 **후** 행동 결과가 보이게 한다. 끌기는 썸·트랙·값 표시가 손가락을 따라가야 하며 그림자만 움직이는 연출을 금지한다. 시트/대화상자 등장과 화면 전환에는 깊이 변화가 결과를 가리지 않게 한다. 진동은 의미가 있을 때만. 시간·이징·누름 깊이는 원본 1차 측정이 없어 `미확인`(N2,N3 파생).

## H. 문구 관례

버튼은 명확한 행동 이름으로, 카드 제목은 목적/데이터를 구분한다. 물리 은유를 설명하는 장식 문구를 만들지 않는다. 숫자와 단위는 실제 입력/출력과 대조한다(제안).

## I. 해도 되는 것 / 안 되는 것

1. 같은 바탕에서 빛 방향을 일관되게 한다 / 카드마다 그림자 방향이 바뀌지 않게 한다(N1–N3 파생).
2. 누름·선택에 그림자 외의 단서를 붙인다 / 저대비 양각을 유일한 클릭 단서로 삼지 않는다(N2,N3).
3. 반복 목록은 평면 구분을 허용한다 / 모든 행을 솟은 카드로 만들지 않는다(N3 파생).
4. 다크 토큰이 없으면 미확인으로 둔다 / 라이트 그림자를 부호만 바꿔 다크 정본이라 주장하지 않는다(N1–N3).

## K. 미확인 목록

실서비스 화면 표본 3건, 원본 이미지 해시, 5×5 색 표본, 모든 반경·그림자 수치, 폰/폴드 다크 모드, 31종 부품의 상태·모션은 미확인. N4의 `#e0e5ec`, ±6px 그림자는 내부 가설이지 사용 제품의 실측값이 아니다. 실제 적용 전에 대상 프로젝트에서 계열의 적합성과 대비를 검증한다.

### K.2. guess 교체 기록

[기본 레퍼런스](../../samples/style-guess-books.html?style=neumorphism)의 C.1 토큰·E.4 부품·G.1 모션은 `같은 재질의 빛과 어둠으로 양각·음각 구분`을 구현한 `guess`이다. A는 스타일 신원, B는 실제 출처만 기록하고 추론으로 출처를 꾸며내지 않는다. D/F/H/I/J는 이 기본 레퍼런스를 기기·과업·문구·접근성에 맞게 재배치·확장하는 계약이다. L의 내부 렌더 PASS는 원본 일치 판정이 아니다. 새 원본에서 같은 부품과 상태를 발견하면 원본 화면의 값·프레임을 실측 → 현재 guess와 차이 기록 → 코드와 책 수정 → 다시 렌더 검수 → 해당 항목의 `guess` 태그 제거 순으로 갱신한다.
