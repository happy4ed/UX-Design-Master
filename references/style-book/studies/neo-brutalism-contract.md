# N6 네오 부르탈리즘 변형 — 샘플 제작 전 컴포넌트 계약

상태: **샘플 제작 입력**. 원본 핀은 정지된 디자인 시스템 포스터다. 원본에서 관찰된 형상과 아래의 작동·배치 **설계 가설**을 구분한다. 이 문서를 먼저 정하고 앱·웹·문서 샘플을 같은 사실표로 만든다. 실제 제품 PRD나 사용자 승인값으로 쓰지 않는다.

## 1. 과업과 단일 시나리오 사실표

과업: `스타일 제작 작업의 진행 상황 확인 → 항목 완료 표시 → 새 항목 추가 → 기록 확인`. 샘플에서만 쓰는 가상 데이터다. 총 4건, 처음 완료 1건이므로 완료율 25%. 앱·웹·문서가 같은 ID·문구·상태를 보여 준다. 문서에서는 2026-11-05 10:30 시점의 **정적 스냅샷**으로 표시하고, 앱·웹의 조작 뒤에 문서 숫자가 실시간으로 바뀐다고 주장하지 않는다.

| ID | 작업 이름 | 분류 | 상태 | 시점 | 샘플에서의 출처 |
|---|---|---|---|---|---|
| T1 | 기획서 목차 정리 | 웹 개편 | 진행 중 | 오늘 14:00 | 가상 |
| T2 | 컴포넌트 상태 검토 | 디자인 시스템 | 진행 중·우선 | 오늘 17:00 | 가상 |
| T3 | 모바일 화면 대조 | 샘플 검증 | 진행 중 | 내일 | 가상 |
| T4 | 참고 이미지 분석 | 스타일 조사 | 완료 | 09:40 완료 | 가상 |

`완료율 = 완료 개수 ÷ 전체 개수 × 100`, 0건일 때 0%로 표시한다. 앱과 웹에서 완료를 바꾸면 지표·목록·진행바가 함께 갱신된다. 추가한 작업은 `신규/진행 중`이다. 저장소나 계정 연결은 범위 밖으로, 새로고침 후 유지되지 않는 시연 상태임을 표시한다.

## 2. 화면/페이지 → 컴포넌트 사용 맵

| ID | 영역·목적 | 공통 요소 | 전용·조건 요소 | 데이터·상태 |
|---|---|---|---|---|
| A1 | 앱 개요: 현재 일과 진행 상태 | 앱바, 화면 제목, 하단/측면 탐색, 지표, 작업 행, CTA | 진행바, 완료 확인 | T1–T4, 필터 all/open/done, 빈 결과 |
| A2 | 앱 작업: 목록 조작 | 앱바, 탐색, 작업 행, CTA | 필터, 새 작업 입력 대화상자 | T1–T4, 입력 공백/유효, 추가/취소 |
| A3 | 앱 기록: 완료된 항목 | 앱바, 탐색, 작업 행 | 정적 기록 목록 | T4, 나머지 완료 시 추가 |
| W1 | 웹 작업 보드: 넓은 탐색과 상세 | 제목, 필터, 지표, 작업 행, CTA, 진행 | 레일 탐색, 표, 메모, 범위 입력 | 같은 T1–T4, 기존 웹 시연 |
| D1 | 문서 1면: 검토용 진행 보고 | 제목, 요약, 작업 목록, 진행 수치 | 범례, 출처·시점, 쪽번호 | 같은 T1–T4의 10:30 스냅샷 |

탐색은 실제 A1/A2/A3 또는 해당 섹션으로 이동해야 한다. 의미 없이 모양만 있는 페이지 번호·메뉴·버튼은 넣지 않는다. 모바일 하단 탐색은 세 화면이 있으므로 사용한다. 펼친 폴드는 같은 세 화면을 측면 레일로 옮긴다. 웹의 레일은 기존 한 페이지의 실제 섹션 앵커를 이동한다. 문서에는 앱 탐색과 버튼을 이식하지 않는다.

| 계열 | 대표 인스턴스·위치 | 필요한 상태 | 근거 등급 | 빠진 계열의 이유 |

| 피드백 | 진행률, 앱·웹 알림, 우선 배지 | 0/중간/100%, 성공·주의 | N6 진행·알림 형상 관찰 + 시연 설계 가설 | 무한 로딩은 비동기 처리 없음 |
| 임시 화면 | 작업 추가 대화상자 | 열림/취소/공백 오류/추가/포커스 복귀 | N6 모달 형상 관찰 + 시연 설계 가설 | 시트·팝업 메뉴는 이 과업에 불필요 |
| 경계 | 완료 0건 기록, 필터 결과 0건, 긴 제목 | 빈/포화/확대 | 샘플 설계 가설 | 서버 오류·권한 오류는 연결된 백엔드가 없음 |
| 문서 | 제목·요약·표·계산식·캡션·쪽번호·다음 작업 | A4 1쪽/긴 행/흑백 의미 | N6 조판·색 관찰 + 문서 설계 가설 | 사진·차트는 이 네 건의 이해에 추가 이득이 작음 |

## 3. 토큰 의존성과 기하

| 계층 | ID/역할 | 이번 샘플 값·판정 | 적용 위치 |
|---|---|---|---|
| primitive | `color.paper/teal/pink/yellow/white` | N6 JPEG 5×5 출력색 `#F1EEDB/#00BBC0/#FE00F9/#FDD901/#FFFFFF` · 실측 이미지 | 매체별 의미값 후보 |
| primitive | `color.ink` | `#111111` · 샘플 설계값, N6 원본 `#010101` 출력색과 구분 | 글자·윤곽·포커스 |
| semantic | `canvas/surface/action/selection/attention` | paper/white/teal/yellow/pink. `attention`은 우선 표시, 완료는 청록+글자/체크 | Z0/Z1/행동/선택/상태 |
| component | `line.structural/line.internal` | 2px/1px · 샘플 설계값, 원본 CSS 미확인 | 구획·입력/행 |
| component | `shadow.primary/raised` | 5px/3px 하드 오프셋 · 샘플 설계값 | 주 CTA/떠 있는 층만 |
| component | `radius.control` | 직각 또는 작은 모서리 · 원본의 직각 계열 관찰, 숫자는 샘플에서 결정 | 버튼/입력/칩 |
| component | `focus.visible` | 윤곽과 떨어진 이중 링 · 설계값 | 키보드 조작 |

간격 숫자는 제품 공통 규격으로 승격하지 않는다. 이 시연의 부모 여백·반복 행 inset·구획 간격·레이블 gap을 **서로 다른 역할**로 두고, 폰/태블릿/폴드 화면에서 실제 렌더로 결정한다. 도형 외곽과 글리프의 시각 중심은 따로 확인한다. 스크린의 CSS px, 앱 모형의 CSS px, 인쇄의 mm/pt는 동일한 물리 크기라고 간주하지 않는다.

## 4. 앱 컴포넌트 규칙 — 화면보다 먼저 확정

| ID·소유 | 역할·해부·내용 | 형태·정렬·배치 | 상태/입력/모션 · 실패 조건 |
|---|---|---|---|
| `APP-BAR` 공통 | 제목, 현재 화면, 필요 시 뒤로 | paper 바탕, 검정 하단 기준선, 제목 시각 시작선 고정 | 탐색 후 제목 갱신; 임의 검정 그림자·구분선 중복 금지. N6의 포스터 제목 크기를 그대로 앱에 적용하지 않음 |
| `NAV-3` 공통 | 개요/작업/기록 3개 목적지 | 폰 아래, 펼친 폴드·태블릿은 측면 레일. 선택은 노랑 면+검정 외곽+현재 표시 | 탭/클릭·Enter/Space 가능, 마지막 선택 유지. 롱프레스·드래그는 불허. 화면이 바뀌면 제목·본문도 실제 변경 |
| `METRIC` 개요 | 라벨, 원값, 단위/설명 | 큰 숫자는 끝선 또는 공통 열, 청록/노랑/흰 면. 전체 카드에 같은 강한 그림자 금지 | 값이 바뀔 때 수치와 진행바 동시 갱신. 0건·3자리 수·확대에서 잘림 금지 |
| `TASK-ROW` 개요/작업/기록 | 체크, 제목 1–2줄, 분류/기한 1–2줄, 상태 단서 | 흰 면+내부 구분선, 체크의 가시 형상과 텍스트 시작선 정렬. 폭이 줄면 상태를 다음 줄로 이동 | 체크 탭/클릭·Space, 완료/재개. 두 번 누름은 두 번 토글; 더블탭 전용 기능 없음. 전체 행 드래그·롱프레스·우클릭 명령 없음. 제목·기한이 잘리면 행 높이 증가 |
| `FILTER-3` 작업 | 전체/진행 중/완료, 동일 자료의 결과 집합 변경 | 각진 칩, 선택은 노랑 면+굵은 선, 한 행 과밀 시 줄바꿈 | 탭/클릭·키보드; 변경 후 목록/빈 상태와 개수 갱신, 스크롤·포커스 보존. 정렬과 중복되는 조작 추가 금지 |
| `CTA-ADD` 작업 | 새 작업 입력 열기 | 청록 면+검정 윤곽+하드 그림자. 화면의 한 주 행동 | 클릭/탭·Enter/Space로 대화상자 열기. 누름은 면과 그림자가 같이 이동. 드래그·롱프레스 불허 |
| `DIALOG-ADD` 작업 | 이름 입력, 취소/추가, 오류 | 종이 면, 검정 윤곽, 배경 가림; 제목→입력→행동 순서 | ESC/취소 닫기, 포커스 반환; 공백·빈 입력은 추가 불가. 완료 시 새 작업과 지표 갱신. 폰에서는 화면 폭 안쪽, 폴드에서는 중심 패널. 원본 모션 미확인이라 등장 모션은 가설 |
| `PROGRESS` 개요 | 완료율과 분자/분모, 진행 막대 | 테두리 트랙·청록 채움, 수치 텍스트를 반드시 함께 | 체크 즉시 갱신. 0/전체·100%·0건, 색만으로 의미 표현 금지 |
| `FEEDBACK` 작업 | 저장/완료/취소 결과 | 화면 정보 가리지 않는 단일 알림, 검정 선·선택적 노랑 면 | 자동 사라지기 전 읽을 시간 확보, 닫기 가능. 스크린리더 상태 알림. 원본 모션 미확인 |

**입력 공통:** 조작 가능 요소의 hit 영역은 샘플에서 최소 48×48 CSS px, 앱 실제 구현에서는 플랫폼 단위로 다시 확인한다. 버튼/체크/탭은 좌클릭·단일 탭 허용, 호버는 시각 보조만, 더블클릭/롱프레스/드래그/드롭/우클릭 전용 행동은 불허한다. 필수 기능은 키보드 경로가 있다. 필터·내비의 선택은 의미 상태와 시각 표지가 일치한다. 입력 중 중단·닫기 뒤 포커스는 트리거에 돌아간다. 모션 감소 환경에서는 상태가 즉시 보이게 한다.

## 5. 폰·태블릿·폴드 앱 배치 조건

이름은 **화면 변형**이며 고정 폭 표준이 아니다. 미리보기의 폭은 검수할 특정 fixture이고 모든 제품의 break point로 옮기지 않는다.

| fixture | 정보 순서 | 재배치 규칙 | 실측 실패 조건 |
|---|---|---|---|
| phone | 앱바→제목/지표→주 행동→필터/목록→진행→하단 탐색 | 한 열, 작업 메타 2줄 허용 | 본문 가로 넘침, CTA와 하단 탐색 겹침, 제목/상태 잘림 |
| tablet | 같은 DOM/읽기 순서 | 넓은 측면 레일+본문 2열; 지표와 목록/진행의 비율을 폴드와 별도로 조정 | 손가락 조작 영역 축소, 허공 같은 과도한 여백, 리스트/수치 기준선 이동 |
| fold | 접힘은 phone, 펼침은 측면 레일+목록/상태 2열 | 힌지/안전 영역은 실제 대상 기기에서 추가 확인; UI는 컨테이너 폭으로 재배치 | 포커스 순서와 시각 순서 불일치, 레일·그림자의 본문 침범 |

초기 자료 T1–T4와 포화 자료(길어진 작업명, 8건 이상, 완료 0/전체, 폰트 200%)를 모두 같은 컴포넌트로 검토한다. 단일 화면을 위해 제목을 무단 줄이거나 정보를 숨기지 않는다.

## 6. 웹·문서 컴포넌트 번역

| 앱 역할 | 웹 번역 | 문서 번역 |
|---|---|---|
| 탐색 | 실제 섹션 레일/탭, 키보드·포커스, 일반 스크롤바 자리를 안정적으로 확보 | 목차·러닝 헤더·쪽번호; 클릭 가능한 버튼처럼 보이게 하지 않음 |
| 작업 행 | 2줄 목록과 상태 배지, 넓은 폭에서는 별도 표 가능. 필터는 같은 자료만 바꿈 | 작업 표. 제목·상태·기한 열, 헤더 반복, 긴 제목은 행 높이 증가 |
| 지표·진행 | 상호작용 직후 실시간 갱신, 시각 값과 텍스트 값 동기화 | 10:30 스냅샷의 분자/분모/25% 명시. 차트는 동일 데이터에서 산출 |
| 주 CTA·대화상자 | 실제 입력과 닫기, 포커스 복귀 | 행동 단추 삭제; 다음 작업 문장·담당 확인란으로 변환 |
| 상태 색 | 청록/노랑/마젠타를 의미 역할에 맞춰 제한 | 흑백 출력에서도 상태 글자·기호·선으로 구분 |

문서 공통 요소는 페이지 바탕·제목 계층·구획선·쪽번호, 대표 페이지 전용은 요약·작업 표·다음 작업이다. 표 헤더와 데이터 분리 금지, 캡션/출처는 대상과 함께 이동, 페이지 끝의 외톨이 제목 금지. 인쇄용 최소 6.5pt 예외만 기록하고 본문은 실제 출력 크기에서 더 크게 읽히도록 설계한다.
