N6은 한 장의 **디자인 시스템 포스터**다. 파생 토큰을 네오 부르탈리즘 전체의 표준값으로 합치지 않고 `neo-brutalism--teal-magenta-yellow` 변형으로 다룬다. [원본 해부·한계·가안 대조](studies/neo-brutalism-study.md)에 포스터의 바탕·구획·부품과 앱 화면에 적용하며 바꾼 것을 나눠 기록했다.

### C.1. N6 포스터 변형의 관찰 토큰

아래는 원본 JPEG의 평평한 면 안쪽에서 채널별 5×5 중앙값을 잰 **이미지 출력색**이다. 원본 CSS·인쇄 원색이나 네오 부르탈리즘 계열 전체의 공통 팔레트가 아니다. 다크 대응안은 원본에 없으므로 `미확인`이고, 이 변형의 현재 샘플은 라이트만 제작한다. 굵기·R·하드 그림자 거리는 보이는 특징과 포스터의 자체 표기일 뿐 실제 웹 px로 환산하지 않는다.

| 이름 | 라이트 | 다크 | 단위 | 근거 등급 | 출처 번호·위치 | 확인일 |
|---|---|---|---|---|---|---|
| 포스터 종이 바탕 | `#F1EEDB` | 미확인 | JPEG RGB | 실측 | N6 이미지 `(300,660)` | 2026-11-05 |

## D. 기기 모드·레이아웃

폰은 단일 주요 열, 폴드/태블릿은 같은 콘텐츠를 넓은 그리드로 재배치한다. 두 모드 모두 **색면·선·하드 그림자의 역할은 동일**해야 한다. 화면 여백·칸 수·앱바 높이·시트 폭·안전 영역은 N1~N3 실측 전 `미확인`이다. 가로 모드에서 장식 도형보다 본문·조작의 읽기 순서를 우선한다.

**매체 번역은 색 교체가 아니라 구조와 조작의 번역이다.** 아래는 N6의 포스터를 토대로 한 시연용 설계 가설이며 원본의 앱·웹·문서 공식 규격이 아니다. 폭 경계와 간격·행 높이는 프로젝트 콘텐츠를 렌더한 뒤 정한다.

| 매체 | 읽기 구조·탐색 | 부품·공간 변환 | 고정해야 할 공통 규칙 |
|---|---|---|---|
| 폰 앱 | 주요 과업 한 열, 하단 탐색은 실제 화면 수가 정당화할 때만 | 긴 제목은 접고, 작업 행은 2줄로 재배치; 액션은 겹치지 않는 조작 영역 | 종이 바탕, 검정 구조선, 한 화면 하나의 주 행동, 선택 표지 |
| 태블릿 앱 | 넓은 캔버스에서 측면 탐색과 본문 2열 | 펼친 폴드와는 별도 폭 fixture에서 레일·지표·목록/상태의 비율을 다시 검증 | 폰과 같은 토큰, 행 패딩·글자 계층·상태 의미 |
| 폴드 앱 | 펼침 폭에서 목록+상세/상태 2열, 접힘 폭에서 폰 흐름으로 환원 | 힌지·안전 영역과 가시 순서 유지; 카드 오프셋 그림자는 이웃 열을 침범하지 않게 | 데이터/선택 상태와 접근 경로, 색 역할 |
| 웹 | 넓은 화면에서 탐색 레일+본문, 좁으면 레일을 탭/메뉴로 이동 | hover·focus·키보드, 일반 스크롤바 공간, 표의 가로 넘침 처리 | 부품 해부, 강조 빈도, 제목·구획선·리스트 역할 |
| 문서·PDF/인쇄 | 제목→요약→본문→표→근거 순서, 페이지 넘김 시 표 머리 재표시 | 버튼/토글은 상태 설명·범례로, 그림자는 인쇄에서 단순화; 여백·단·쪽번호 유지 | 종이 바탕·굵은 검정 구조선·선택적 청록/노랑 강조 |

스크린의 포스터 제목 크기와 인쇄 문서의 글자 크기를 같은 px로 옮기지 않는다. 문서의 pt·mm, 앱의 dp/sp 또는 pt, 웹의 CSS px를 별도 측정한다. 문서의 마젠타·노랑 면은 출력 잉크·명도 대비를 확인하고, 흑백 출력에서도 선·문자·범례로 의미가 남아야 한다.

## E. 컴포넌트 명세

각 프로젝트에서 부품마다 `역할·금지 맥락 / 해부 / 크기 단계·안쪽 여백·글자·아이콘·R / 기본·누름·선택·비활성·포커스·끌기 / 라이트·다크 / hit area·인접 간격 / 모션 / 근거·바꾼 것·미확인`을 기록한다. **아래의 형태는 N4에서 옮긴 제안이지 세 사례의 검증된 공통 부품이 아니다.**

| 부품·변형 | 적용 출발점 | 근거 등급·출처 | 바꾼 것·미확인 |
|---|---|---|---|
| 앱바(작은·큰 제목·부제), 뒤로 | 큰 제목과 구획선, 탐색 경로를 분명히 | 제안 N4 | 현행 사례의 높이·상태 미확인 |
| 아이콘 버튼 단계, 주 버튼·보조 버튼·글자 버튼, 떠 있는 버튼 | 강한 면색/선/하드 그림자는 **주 동작에만**; 나머지는 시각 무게 낮춤 | 제안 N4 | 단계별 크기·색·R 미확인 |

## E.1. 글꼴·아이콘·슬라이더 결정

이 표는 컴포넌트별 구분이 누락되지 않도록 한 적용 계약이다. `제안`은 시연용 방향이며 원본 재현값이 아니다. 폰/폴드와 라이트/다크에서 각 부품의 기본·누름·포커스·끌기 상태를 따로 확인한다.

### E.3. N6 변형의 매체별 컴포넌트 계약

N6의 작업 보드 시연은 [샘플 제작 전 컴포넌트 계약](studies/neo-brutalism-contract.md)을 먼저 작성한 뒤 제작한다. `APP-BAR / NAV-3 / METRIC / TASK-ROW / FILTER-3 / CTA-ADD / DIALOG-ADD / PROGRESS / FEEDBACK`의 역할·슬롯·상태·입력·포화 조건과 화면 사용 맵을 그 문서에서 확정했다. 웹과 문서는 같은 데이터·의미 역할을 각각 레일/표·인쇄 페이지로 번역한다. **원본 이미지에서 실제로 보이지 않는 조작과 모션은 모두 설계 가설**이다.

앱 샘플은 컴포넌트 명세 없이 포스터의 버튼·카드를 화면에 먼저 배치하지 않는다. 폰·태블릿·폴드는 색만 공유하는 별도 시안이 아니라 같은 컴포넌트의 읽기 순서·탐색 위치·열 관계가 달라지는 변형으로 검증한다. 웹은 hover/키보드/스크롤바 조건을 추가하고, 문서는 대화상자·토글을 인쇄 가능한 상태·다음 행동으로 바꾼다.

| 역할 부품 | 폰·태블릿·폴드 앱 | 웹 | 문서·인쇄 | 상태·근거 |
|---|---|---|---|---|
| 앱바·제목 | 검정 기준선과 읽기 시작선; 펼친 폴드에서 레일과 나란히 | 페이지 제목+탐색 레일 | 러닝 헤더+문서 제목 | N6 제목·구획 관찰, 배치는 설계 가설 |

글꼴: 두꺼운 제목과 단단한 본문 · `guess` 구현에서는 실제 프로젝트 글꼴을 선택하고 글자 확대를 검수한다. 아이콘: 각진 검은 기호와 굵은 획 · 실루엣 중심을 박스 중심과 별도로 실측한다. 슬라이더: 재생 위치는 검은 외곽의 평평한 트랙과 정사각 손잡이; 음량은 각진 기하와 즉각적인 상태 변화. 이 값 가운데 원본 관찰로 확인된 부분과 추론 부분은 E.1의 등급을 유지하고, 추론 부분에 `guess`를 붙인다.

## F. 패턴

하위 화면+스위치, 목록/상세, 설정 묶음, 필터 고르기, 확인, 빈/로딩/오류, 여러 개 선택과 최대치 모두 **정보 구조는 기능 요구에서 먼저 결정**한다. 이 스타일은 그 구조에 선·면·그림자 언어를 입히는 선택이다. 선택/확인 패턴의 조작 상태를 먼저 그린 뒤 스타일을 부여한다. 특정 서비스에서 확인한 패턴 조합은 아직 `미확인`.

N6 샘플의 과업 패턴은 `오늘 상태 파악 → 항목 완료/추가 → 결과 확인`으로 제한한다. 같은 작업 ID를 앱·웹·문서가 공유하며 문서는 지정 시점의 스냅샷이다. 앱에서 사용한 하단 탐색·필터·추가 대화상자는 실제 화면/상태가 연결될 때만 남긴다. 문서에서는 탐색·실행 부품을 목차/표·다음 행동으로 번역한다.

## G. 인터랙션

누름의 그림자 이동과 면 위치 변화를 같은 값으로 연결하고, 릴리스 시 원위치로 돌아간다(제안 N4). 팝업·시트·끌기·진동의 스타일 고유 모션은 `미확인`; 프로젝트에서 각각 실물 시연 후 정한다. 스크롤 중 하드 그림자가 텍스트를 침범하면 z층·클리핑을 조정한다.

N6 정지 이미지에는 시간·이징·동작 경로가 없다. 앱·웹 샘플의 눌림 위치/그림자 동시 이동, 내비 전환, 완료율 채움은 기능형 **설계 가설**로만 적용한다. 문서에서는 필수 정보가 한 프레임에 남도록 정적 상태·범례를 쓴다. 모션 감소·인쇄에서는 변화 결과가 즉시 보인다.

## H. 문구 관례

짧은 기능명과 직접적인 동사를 쓰고, 장식형 대문자 제목이 실제 행동 라벨을 대체하지 않게 한다. 단위는 데이터 그대로. 전용 문체·문장부호 규칙은 `미확인`.

## I. 해도 되는 것 / 안 되는 것

1. 선과 하드 그림자를 시각 위계에 맞춰 제한한다. 화면의 모든 상자에 같은 그림자를 주지 않는다.
2. 강한 색을 사용하되 글자 대비를 실제 전경·바탕 조합으로 잰다. 충돌 색을 무작위로 늘리지 않는다.
3. 크기·R·선·그림자 값은 선택한 프로젝트의 **실제 사례**에서 다시 잰다. N4 제안을 표준 수치처럼 쓰지 않는다.
4. 포스터의 촘촘한 부품 격자와 96/64px 타이포 표기를 앱·문서의 실제 치수로 복사하지 않는다. 정보 위계와 조작/인쇄 조건을 먼저 맞춘다.

## J. 접근성 덮어쓰기

조작 영역 최소 `48×48`, 모바일 조작 글자 최소 `14`, 작은 글자 대비 `4.5:1`을 프로젝트 접근성 계약으로 적용하고, 원본보다 키운 hit area/글자/선택 대비를 `바꾼 값`에 적는다. N1~N3에서 접근성 원값을 아직 재지 않아 현재 차이표는 `미확인`. 글자 150/200%와 폰/폴드에서 그림자·테두리가 정보를 가리지 않는지 확인한다.

N6 포스터에는 `44px` hit area가 적혀 있지만 이 샘플의 모바일 조작 하한은 48×48 CSS px로 바꾼다. 실제 네이티브 앱에서는 CSS px를 dp/sp 또는 pt로 기계 환산하지 않고 기기 실측과 사용자 확인을 거친다. 웹은 키보드 포커스/200% 글자 확대, 문서는 본문·표의 실제 인쇄 크기와 흑백 출력 의미를 별도 검증한다.

## K. 미확인 목록

N1~N3의 현재 픽셀 실측, 라이트/다크 실제 짝, 글꼴·타입 스케일, 컴포넌트별 해부·상태·R·모션, 폰/폴드 레이아웃, 원본 캡처 해시가 미확인. 세 사례의 출처 페이지가 변할 수 있으므로 새 프로젝트에서는 해당 날짜의 실제 렌더를 기준으로 다시 기록한다.

N6에서는 이미지 해시·팔레트 출력색·보이는 부품 종류가 확인됐다. 원본 폰트명, CSS 수치, 버튼 전후 상태, 실제 앱/웹/문서 구현, 다크 모드와 모션은 **원본 미확인**이다. 앱·웹·문서 샘플은 이 사실을 보완하는 설계안이며 원본의 숨은 규격이라고 주장하지 않는다.
