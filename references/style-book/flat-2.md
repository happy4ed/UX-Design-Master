## E.1. 글꼴·아이콘·슬라이더 결정

이 표는 컴포넌트별 구분이 누락되지 않도록 한 적용 계약이다. `제안`은 시연용 방향이며 원본 재현값이 아니다. 폰/폴드와 라이트/다크에서 각 부품의 기본·누름·포커스·끌기 상태를 따로 확인한다.

| 부품 | 형태·사용 규칙 | 근거 등급 | 상세 근거 |
|---|---|---|---|
| 글꼴 | 정보 위계가 분명한 현대 산세리프 | 제안 | flat-2.md C/E |
| 아이콘 | 그림자 없는 평면 채움 기호 | 제안 | flat-2.md C/E |
| 재생 위치 | 색으로 분리한 얇은 트랙과 단순 사각 썸 | 제안 | flat-2.md C/E |
| 음량 | 단순한 평면 막대와 수치 피드백 | 제안 | flat-2.md C/E |

시연 SVG·CSS의 실제 속성은 [기준 화면](../../samples/style-book-reference-screen.html)에서 확인한다. 근거 없는 시연값은 이 가이드의 원본값으로 승격하지 않는다.

### E.2. 컴포넌트별 형태·상태·모션 변환

색 토큰만 바꿔 스타일을 적용했다고 판정하지 않는다. 아래는 [시연용 변환표](component-expression.json)의 기능형 **설계 가설**이다. 원본 사례 B절에서 확인된 성격과 E절의 부품 제안을 분리한다. 실제 원본 부품의 형상·누름·선택·모션을 확인하기 전에는 원본 일치로 쓰지 않는다. 같은 콘텐츠로 [13개 역할 보드](../../samples/style-book-component-board.html)에서 확인한다.

## G. 인터랙션

누름·호버는 F3처럼 **표면 색 변화와 높이 변화 중 하나를 주 피드백으로 선택**한다. 같은 부품에 둘을 과하게 겹치지 않는다. 화면 전환은 선택된 목적지와 읽기 위치를 유지한다. 시트/대화상자는 overlay 층을 분명히 하며, 끌기 조작은 위치·값을 연속 표시한다. 진동은 대상 플랫폼에서 의미가 있을 때만. 시간/이징은 세 서비스 공통값이 없어 미확인.

## H. 문구 관례

짧은 기능 이름과 실제 상태·값을 사용한다. 단위는 데이터에서 가져오고, 긴 설명을 같은 버튼/칩 안에 반복하지 않는다. 텍스트가 화면을 구조화하므로 제목/본문/보조 라벨의 글꼴 역할을 명세한다(제안).

## I. 해도 되는 것 / 안 되는 것

1. 정보 그룹은 여백과 선으로 먼저 나눈다 / 카드·그림자로 모든 영역을 띄우지 않는다(F3).
2. 조작은 경계·포커스·선택 상태가 읽히게 한다 / 평면이라는 이유로 클릭 가능성을 숨기지 않는다(F1,F2).
3. 그림자는 raised/overlay 같은 기능 층에만 쓴다 / 같은 줄의 의미 없는 카드마다 높이를 주지 않는다(F3).
4. GOV.UK 색이나 GitHub 아이콘을 Flat 2.0의 범용 정본이라 선언하지 않는다(F1,F2).

## K. 미확인 목록

세 서비스의 같은 화면 크기·같은 상태 원본 캡처/해시가 없고 픽셀 치수·R·간격·모션은 미측정이다. 라이트 GOV.UK 토큰 이외의 다크 수치는 제품별로 다시 조사한다. Flat 2.0이라는 단일 공식 시스템은 존재하지 않으므로 어떤 제품의 수치도 다른 제품에 보편화하지 않는다.

### K.2. guess 교체 기록

[기본 레퍼런스](../../samples/style-guess-books.html?style=flat-2)의 C.1 토큰·E.4 부품·G.1 모션은 `깊이 효과 없이 색면과 기능적 대비`을 구현한 `guess`이다. A는 스타일 신원, B는 실제 출처만 기록하고 추론으로 출처를 꾸며내지 않는다. D/F/H/I/J는 이 기본 레퍼런스를 기기·과업·문구·접근성에 맞게 재배치·확장하는 계약이다. L의 내부 렌더 PASS는 원본 일치 판정이 아니다. 새 원본에서 같은 부품과 상태를 발견하면 원본 화면의 값·프레임을 실측 → 현재 guess와 차이 기록 → 코드와 책 수정 → 다시 렌더 검수 → 해당 항목의 `guess` 태그 제거 순으로 갱신한다.
