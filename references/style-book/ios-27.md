### 유리 소재의 층과 시연 계약

Apple의 Liquid Glass는 콘텐츠 위에 놓인 **조작·탐색 층**이다(H1,H7). iOS 시연에서는 앱바 행동, 검색, 세그먼트, 아래 내비게이션, 시트·대화상자에 반투명도·배경 흐림·채도 변화·얇은 가장자리 반사·그림자를 함께 준다. 일반 목록 행과 본문 카드는 읽기 쉬운 콘텐츠 층으로 남긴다. 유리 효과를 모든 면에 복제하지 않는다.

투명도와 `backdrop-filter: blur()`만으로는 **뒤쪽 선의 굴절**을 증명할 수 없다. 가이드와 시연에는 선·색 경계가 있는 배경 위에 유리 렌즈를 겹치고, 렌즈 안에서 배경 패턴이 실제로 휘어지는 장면을 넣는다. 현재 웹 시연은 자체 제작 CSS 배경을 SVG 변위 필터로 굴절시키는 **설계 가안**이다. Apple 시스템 렌더러·iOS 27 픽셀값을 복제한 결과로 취급하지 않는다. 원본 화면과 비교할 때는 배경 사진/패턴, 라이트·다크, 스크롤 위치를 각각 기록하고 렌즈 가장자리·글자 대비·터치 영역을 확인한다.

검증: [`test_ios_liquid_glass.py`](../../tests/test_ios_liquid_glass.py)는 필터를 켠/끈 렌더의 픽셀 차이, 두 색 모드의 소재 존재와 가로 넘침을 확인한다. 검사가 통과해도 원본과의 시각적 일치 판정은 별도다. 투명도 감소·고대비 설정에서는 불투명한 면과 읽기 쉬운 글자로 대체한다(H7).

**투명도 분기:** H1의 `clear`는 사진·영상처럼 풍부한 배경 위에서만 쓴다. 이 경우 시연 렌즈는 배경 색과 윤곽이 통과하고, 굴절·가장자리의 얇은 반사로 형상을 구분한다. 앱의 밝은 바탕은 iOS 콘텐츠 층의 옅은 중립색을 유지한다. 검색·탭·앱바처럼 글자가 있는 일반 조작은 `regular`에 해당하는 약한 광도 조정과 흐림을 쓴다. 모든 조작을 짙은 반투명 회색으로 채우거나 바깥 그림자를 두껍게 만들어 양각 버튼으로 보이게 하지 않는다. 배경이 밝아 글자를 읽기 어렵다면 **텍스트 주변의 국소 대비**를 보강하고 유리 전체를 불투명하게 채우지 않는다. 색·그림자·모션 수치는 공식 27 토큰이 아닌 현재 시연 가설이다.

**Liquid Glass 동작 명세(H8,H9를 26 시점 근거로 사용):** 누를 때 컨트롤이 손가락에 반응해 작게 수축하고 놓을 때 복귀·정착한다. 가까운 유리 조작이 펼쳐질 때 하나의 광학 형상에서 갈라져 나오고, 닫힐 때 다시 흡수된다. 선택 지시자는 두 위치에서 각각 새로 나타나는 대신 경로를 따라 이동한다. 반사 하이라이트는 변화 중에만 지나가며 상시 반복하지 않는다. 시트는 호출한 조작에서 시작하는 관계가 읽히도록 나타난다. 이 동작의 정확한 거리·시간·탄성은 27 원본 측정 전까지 확정하지 않는다. 현재 [컴포넌트 시연](../../samples/style-book-component-board.html?style=ios-27)은 수축·복귀, 펼침·흡수, 선택 지시자 이동, 시트 등장을 작동 가능한 웹 가안으로 보여 준다. 모션 감소 설정에서는 형상 전환 애니메이션을 없애고 상태만 즉시 바꾼다.

## H. 문구 관례

- 제목은 화면 목적을 짧게 표현하고 데이터 값과 구별한다. iOS 26 이후 섹션 헤더의 첫 글자만 대문자라는 **전달 관찰**은 한국어 대소문자 규칙이 아니며 대상 언어로 검증한다(K1).
- 버튼은 결과를 예측할 수 있는 행동 이름을 쓴다. 단위(%, 분:초, dB)는 실제 데이터와 컨트롤 값에 연결한다. 확인하지 못한 문구는 예시로라도 작동한다고 주장하지 않는다.
- iOS의 Dynamic Type 확대에서 줄바꿈·행 높이·요약 표시를 다시 확인한다(H5).

## K. 미확인 목록과 다음 조사

1. iOS 27 UI Kit Sketch 원본을 이 작업에서 직접 열지 못했으므로 K1의 수치·키트 버전·색 표본·원본 해상도를 1차 재검증해야 한다. 원본 캡처와 해시를 배포 스킬 밖에 둔다.
2. 라이트 모드 색 역할 대부분, 다크 상태색·scrim·상태 불투명도, 간격 단계, 앱바/탭바/시트/대화상자 수치, 아이콘 굵기 단계, 모션 시간·이징이 미확인이다.
3. 재생 위치 막대의 누름 변화, iOS 27 Music 세로 화면, 상단 인라인 검색 높이, bordered dark 채움은 전달 요약도 미확인으로 둔다.
4. K1에서 단지 iOS 26 Music 실측으로 기록한 재생·음량 막대와 미디어 버튼은 iOS 27 고유 값으로 확정하지 않는다.
5. 세그먼트·칩·라디오·진행·토스트·빈/오류 상태 등은 이 판에서 수치와 상태를 확인하지 못했다. 실제 제품의 대상 화면·공식 원본을 받아 개별 부품 명세를 채운다.

### K.2. guess 교체 기록

[기본 레퍼런스](../../samples/style-guess-books.html?style=ios-27)의 C.1 토큰·E.4 부품·G.1 모션은 `콘텐츠 위 투명 렌즈와 부드러운 깊이`을 구현한 `guess`이다. A는 스타일 신원, B는 실제 출처만 기록하고 추론으로 출처를 꾸며내지 않는다. D/F/H/I/J는 이 기본 레퍼런스를 기기·과업·문구·접근성에 맞게 재배치·확장하는 계약이다. L의 내부 렌더 PASS는 원본 일치 판정이 아니다. 새 원본에서 같은 부품과 상태를 발견하면 원본 화면의 값·프레임을 실측 → 현재 guess와 차이 기록 → 코드와 책 수정 → 다시 렌더 검수 → 해당 항목의 `guess` 태그 제거 순으로 갱신한다.

### Liquid Glass 시연 보정

- 문제: 이전 시연은 검정·회색 불투명 버튼과 카드 중심이라 배경 투과·굴절을 볼 수 없었다.
- 수정: [컴포넌트 시연](../../samples/style-book-component-board.html?style=ios-27)과 [기준 화면](../../samples/style-book-reference-screen.html?style=ios)에 자체 제작한 배경과 굴절 렌즈를 추가했다. 탐색·조작층에 유리 표면을 적용하고 콘텐츠 행·카드는 읽기 쉬운 표면으로 유지했다.
- 렌더 증거: [다크 컴포넌트](../../samples/style-book-renders/ios-component-phone-dark.png), [라이트 컴포넌트](../../samples/style-book-renders/ios-component-phone-light.png), [다크 기준 화면](../../samples/style-book-renders/ios-reference-phone-dark.png), [라이트 기준 화면](../../samples/style-book-renders/ios-reference-phone-light.png). 네 렌더에서 필터 켜짐/꺼짐의 가시 픽셀 차이를 확인했다.
- 한계: 웹 SVG/CSS 굴절은 iOS 시스템의 동적 Liquid Glass와 동일하지 않다. H7의 조작층 위치·광학 속성을 바탕으로 한 내부 가안이다.
- 2차 보정: 라이트의 두꺼운 바깥 그림자와 탁한 틴트를 줄이고 `clear`(미디어 위)와 `regular`(일반 조작)를 분리했다. 자체 제작 풍경 배경 위에서 투과·굴절을 확인하고, 눌림/복귀·컨트롤 펼침/흡수·탭 지시자 이동의 중간 프레임을 [시연 렌더](../../samples/style-book-renders/ios-motion-middle-light.png)로 기록했다. H8/H9의 iOS 26 동작 관계를 참조한 **27 시연 가안**이며 원본 영상의 프레임별 대조는 아직 하지 않았다.
- 원형 조작 검수: 펼쳐지는 이전/다음 버튼은 가로·세로 **48×48px**의 동일한 원형 조작 영역을 사용한다(스킬 앱 하한 P1). 고정 높이와 유동 너비를 섞어 세로 타원이 되던 구성을 제거했다. 320/390px 폰과 폴드에서 실제 bounding box의 너비·높이 일치, 렌즈와의 간격, 가로 넘침을 검사한다.
