# 맥시멀리즘 — Maximalism

## A. 신원

| 이름 | 분류 | 계열·기원 | 대상 버전 | 가이드 버전·확인일 |
|---|---|---|---|---|
| 맥시멀리즘 / `maximalism` | 자유 | 이미지·타이포·색·패턴을 겹쳐 시선을 끄는 표현 계열; 단일 표준 없음 | 웹/앱 브랜드 시안, 2026-11 관찰 | 0.1.0 · 2026-11-05 |

이 가이드는 여러 실사례에서 추출한 **설계 어휘**다. 어떤 한 브랜드의 토큰을 다른 제품에 그대로 옮기는 표준이 아니다. 브랜드 이미지와 표현 권한이 있을 때 탐색안으로 사용하고, 반복 작업 앱의 모든 화면에 같은 밀도를 강제하지 않는다.

## E.1. 글꼴·아이콘·슬라이더 결정

이 표는 컴포넌트별 구분이 누락되지 않도록 한 적용 계약이다. `제안`은 시연용 방향이며 원본 재현값이 아니다. 폰/폴드와 라이트/다크에서 각 부품의 기본·누름·포커스·끌기 상태를 따로 확인한다.

| 부품 | 형태·사용 규칙 | 근거 등급 | 상세 근거 |
|---|---|---|---|
| 글꼴 | 큰 압축 제목과 차분한 정보 본문 | 제안 | maximalism.md C/E |
| 아이콘 | 굵은 채움 기호 | 제안 | maximalism.md C/E |
| 재생 위치 | 굵은 트랙과 큰 사각 썸 | 제안 | maximalism.md C/E |
| 음량 | 색 대비가 큰 막대와 명확한 숫자 | 제안 | maximalism.md C/E |

시연 SVG·CSS의 실제 속성은 [기준 화면](../../samples/style-book-reference-screen.html)에서 확인한다. 근거 없는 시연값은 이 가이드의 원본값으로 승격하지 않는다.

### E.2. 컴포넌트별 형태·상태·모션 변환

## F. 패턴

하위 화면+스위치 행, 목록|상세, 설정 묶음, 필터 고르기, 확인, 빈/로딩/오류, 여러 개 고르기의 최대 상태를 각각 화면으로 렌더한다. 맥시멀 표현은 **주요 시각 구획**에 집중하고 입력·오류·확인에는 조작 위계를 우선한다. 칩이 하나의 명령인지 필터인지, 확인 대화상자가 몇 행동을 가졌는지는 실제 기능 계약으로 결정한다. 이 패턴들은 X1~X3의 직접 재현이 아니라 제품 적용 제안이다.

## G. 인터랙션

누름 피드백은 위치·색·테두리 중 한 축을 고른다. 화면 전환은 다음 정보의 위치를 예측 가능하게 유지한다. 시트·대화상자는 배경 장식을 가려 집중을 돕는다. 끌기는 값 변화가 즉시 읽혀야 하고, 진동은 실제 기기 지원을 확인한다. X1~X3의 모션은 재생 측정하지 않았으므로 C의 시간·이징은 제안으로 남는다.

## H. 문구 관례

화면 제목은 한두 단어의 목적어·역할명, 버튼은 결과가 예상되는 동사로 쓴다. 큰 글자를 장식으로 쓰더라도 별도의 기능 설명을 반복하지 않는다. 단위·숫자·대문자·한글 조사/줄바꿈은 제품 언어와 실제 데이터 기준으로 결정한다.

## I. 해도 되는 것 / 안 되는 것

1. 큰 타이포나 이미지 **하나를** 주인공으로 삼을 수 있다(X1/X3). 모든 부품을 크게 만들면 과업 위계가 사라진다.
2. 다른 규모의 글자와 비대칭을 활용할 수 있다(X1/X2). 명확한 정렬선 없이 무작위로 흩뿌리면 읽는 순서가 깨진다.
3. 강한 색 한 점만으로도 표현적 밀도가 가능하다(X1). 맥시멀리즘을 `무조건 원색 7개`로 정의하지 않는다.
4. 사진과 큰 브랜드 글자를 겹칠 수 있다(X2). 얼굴·상품·주행동을 글자로 가리지 않는다.

## J. 접근성 덮어쓰기

이 자유 스타일에 공식 최소 크기는 없다. 제품 적용 시 **조작 영역 48×48 이상, 인접 8 이상, 모바일 글자 14 이상, 의미 있는 색/텍스트 대비 4.5:1·비문자 3:1**을 기본 검사한다. C의 작은 내비 라벨이 14 미만으로 렌더되면 키우고, 추가한 폭·행 높이를 `원래 제안 → 변경값 → 이유 → 캡처`로 기록한다. 150/200% 글자 확대에서 헤더와 칩을 재배치한다. 배경 이미지 위 글자는 실제 이미지를 포함해 대비를 측정한다.

## K. 미확인 목록

- X1~X3의 실제 CSS 토큰·색·폰트·R·반응형 전환점·호버/누름·모션은 미측정. 브랜드 간 동일값으로 추정하지 않는다.
- X2의 쿠키 모달 뒤 전체 구도와 X3의 하단 정보는 관찰 불완전.
- 라이트/다크 전환은 세 서비스 공통으로 관찰되지 않음. C의 다크는 프로젝트 제안.

### K.2. guess 교체 기록

[기본 레퍼런스](../../samples/style-guess-books.html?style=maximalism)의 C.1 토큰·E.4 부품·G.1 모션은 `굵은 조판과 여러 정보층의 선명한 위계`을 구현한 `guess`이다. A는 스타일 신원, B는 실제 출처만 기록하고 추론으로 출처를 꾸며내지 않는다. D/F/H/I/J는 이 기본 레퍼런스를 기기·과업·문구·접근성에 맞게 재배치·확장하는 계약이다. L의 내부 렌더 PASS는 원본 일치 판정이 아니다. 새 원본에서 같은 부품과 상태를 발견하면 원본 화면의 값·프레임을 실측 → 현재 guess와 차이 기록 → 코드와 책 수정 → 다시 렌더 검수 → 해당 항목의 `guess` 태그 제거 순으로 갱신한다.
