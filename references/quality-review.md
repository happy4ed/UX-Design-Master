# 실제 화면·문서 검수

요청한 제품과 산출물에 관련 있는 항목을 검사한다. 항목을 모두 통과했다고 자동 보고하지 말고 실제 확인과 미확인을 구분한다.

## 흐름과 콘텐츠

- 가장 중요한 과업을 처음부터 완료까지 직접 실행한다. 탐색, 뒤로 가기, 선택·입력, 오류·복구, 완료 피드백이 연결되는지 확인한다.
- 제목과 버튼이 실제 행동을 설명하는지, 가짜 수치·후기·불필요한 문구가 없는지 확인한다.
- 빈 목록, 단일 항목, 많은 항목, 긴 제목, 한글·영문·숫자 혼합, 이미지 없음으로 내용을 바꿔 확인한다.

## 정렬과 순서

- 컨테이너 경계, 텍스트 기준선, 제목-본문 간격, 행·열 간격, 버튼과 아이콘 중심, 반복 패턴의 일관성을 실제 렌더링에서 확인한다.
- DOM/읽기/키보드 순서가 의미 있는 콘텐츠 순서와 맞는지 확인한다. CSS order로 모바일의 읽기 순서를 깨뜨리지 않는다.
- 이미지 초점, 크롭, 투명 여백, 아이콘 두께와 크기, 실제 폰트 로딩 후 줄바꿈을 확인한다.

## 레이아웃 내구성

- 제품에 맞는 작은 모바일·일반 모바일·태블릿·데스크톱과 전환점 직전/직후 폭을 확인한다. 지원 범위에 포함되는 경우 320px도 확인한다.
- 의도하지 않은 가로 스크롤, 겹침, 잘림, 화면 밖 버튼, 고정 높이로 인한 콘텐츠 손실을 찾는다. flex/grid 자식의 최소 너비, 줄바꿈, overflow 처리, 이미지 비율을 검토한다.
- 200% 확대와 큰 글꼴, 가로/세로 방향, 안전 영역, 모바일 키보드에서 주요 행동이 보이는지 확인한다.
- sticky/fixed 헤더·하단 바·모달·드롭다운의 레이어, 스크롤 잠금, 포커스 복귀를 확인한다.

## 접근성과 동작

모든 디자인에서 [다국어·RTL 필수 검수](multilingual-review.md)를 적용한다. 한국어·긴 영어·아랍어 RTL의 초기/포화 조건과 좁은/일반 폭을 실제 렌더로 확인하고, RTL에서 화살표·단계·축·키보드·읽기 순서가 의미를 유지하는지 확인한다.

키보드만으로 주요 기능을 실행하고 포커스가 보이는지 확인한다. 입력 레이블·도움말·오류 연결, 의미 있는 HTML, 터치 대상, 색 대비, 모션 감소를 확인한다. 터치 대상은 가능하면 44×44 CSS px 이상을 확보하고 작은 아이콘은 클릭 영역을 넓힌다. 실제 대상 플랫폼의 기준이 있으면 따른다. 자동 검사만으로 전체 접근성을 보장하지 않는다.

[컴포넌트별 입력 계약](multi-input-contract.md)에 따라 각 조작 요소의 클릭/탭·호버·롱프레스·드래그/드롭·스와이프·키보드 허용 여부와 이유를 대조한다. 실제 마우스와 터치에서 누름 취소, 스크롤과 드래그의 경합, 손가락 이탈, 잘못된 드롭, 연속 입력을 검사한다. 호버에만 숨은 명령이 없고 롱프레스/드래그/스와이프에는 발견 가능한 단순 조작과 키보드 경로가 있는지 확인한다. 입력 방식마다 같은 상태·결과가 나오는지도 본다.

## 구현과 전달

문서는 대표 페이지뿐 아니라 페이지 넘김, 제목 고아 행, 캡션과 그림의 분리, 표 헤더 반복, 쪽번호·교차 참조·출처를 최종 판형과 화면 크기에서 확인한다. 다이어그램·인포그래픽은 원본 수치·단위·분모·척도와 노드·화살표의 관계를 대조하고, 라벨·선·범례의 충돌과 축소 시 판독성을 확인한다. SVG/PNG/PDF로 납품하면 실제 내보낸 파일을 다시 열어 폰트·투명도·클리핑·편집성을 검수한다. [상세 계약](diagram-infographic.md)을 따른다.

PPT·발표 슬라이드는 [발표 자료 디자인](presentation-design.md)의 전체 장별 주장·증거·읽기 순서를 확인하고, 편집 원본과 최종 PPTX/PDF/이미지의 실제 렌더를 각각 다시 연다. 발표 화면·배포본·인쇄본에서 차트 수치와 출처, 글자·폰트 대체, 애니메이션의 정적 대안, 노트와 숨긴 장을 확인한다. 인포그래픽은 부분 그림만 통과시키지 말고 전체 주장·스캔 경로·부분별 원본값 계보·매체별 재배치까지 검수한다.

다이어그램은 생성 당시의 SVG 좌표만 보지 말고 **실제 삽입 폭**에서 본문·보조 글자 px, 글꼴 굵기, 화살촉 고정 크기, 몸통 길이, 노드·되돌림 선 간격을 측정한다. 좁은 화면에서 11px 미만으로 축소되면 가로 스크롤 또는 다른 읽기 경로를 제공한다. 생키의 실제 분할값이 없으면 연결선을 만들지 않고 원본 자료를 확인한다. [검사기](../assets/visualization/layout-audit.mjs)가 0건이어도 최종 표시 크기의 캡처를 보고 판독성을 판단한다.

구현물은 실제 브라우저·기기에서 대표 화면과 흐름을 확인하고 콘솔/네트워크 오류를 점검한다. 디자인 파일만 납품하면 반응형·인터랙션 제약을 명세하고 구현 검증과 구분한다. 자산 라이선스·폰트 폴백·이미지 로딩 공간·불필요한 대용량 자산을 확인한다. 성능 수치를 보고하려면 실제로 측정한다.

발견 문제 → 사용자에게 미치는 영향 → 수정 → 재확인을 기록한다. 승인된 기능과 방향을 바꾸지 않는 오류는 바로 수정한다. 큰 구조 변경이 필요하면 영향과 수정안을 구체적으로 보여주고 관련 단계만 다시 확인받는다.

디자인 비평은 자동 검출 결과를 먼저 읽고 결론을 맞추지 말고, 실제 화면의 목적·계층·인지 부담·과업 적합성을 독립적으로 살핀 뒤 수치 검출·접근성 결과와 합친다. 발견마다 `위치·상태·뷰포트 / 관찰 증거 / 사용자 영향 / 심각도(차단·중요·다듬기) / 구체적인 수정값 / 재확인 결과`를 남긴다. 맞게 작동하는 구성도 적어 무분별하게 교체하지 않는다. 체크리스트의 항목 수나 한 점수로 디자인의 완성도를 선언하지 않는다.

제작자가 의도를 아는 상태에서 하는 이 검수와 별도로 [독립 사용자 관점 검수](independent-review.md)를 실행한다. 평가자에게 화면별 정답을 주지 않고, 기능명·조작 결과의 첫 예상과 실제 관찰이 어긋나는 곳을 확인한다. 평가자가 보지 못한 상태는 제작자의 실측으로 보완하되 독립 평가 PASS로 합치지 않는다.

실제 웹 구현을 납품할 때는 대표 URL·상태·여정·기기/네트워크를 정해 LCP·INP·CLS의 시작값을 측정하고, 문제의 원인 증거와 수정 뒤 같은 조건의 결과를 기록한다. 실사용자 필드 값과 실험실 측정값은 구분한다. 브라우저 성능 지표가 없는 정적 목업·인쇄 문서에는 해당 항목을 NOT_APPLICABLE 또는 NOT_RUN으로 기록하며 임의 수치를 만들지 않는다. 접근성·시각 품질·과업 완수는 성능 점수와 별도로 검수한다.

[지식 적용 표](knowledge-application.md)에서 선택한 규칙이 실제 화면·문서의 어느 위치에 들어갔는지 대조한다. 같은 항목의 이름만 기록하고 동작·정렬·가독성을 확인하지 않은 경우에는 검증 완료로 처리하지 않는다. 검토 후 제외한 후보도 그 이유가 현재 사용자 과업과 맞는지 확인한다.
